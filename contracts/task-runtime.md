## 角色与主动调用

主执行 Agent（Root）是当前接受用户指令、负责整项交付的 OMP 会话，经 `orbit omp` 启动并加载 Orbit 扩展。它负责实现和必要分工；Orbit 程序负责观察和控制，独立检查者负责检查实际产物，裁定者按需处理真实争议。新项目无需预设团队、额外角色或 Orbit 需求表。

当前工作区入口已替换（尚未交付新安装构建）：`orbit omp` 提供接入资格，不因打开会话就建任务。未绑定任务的新用户消息在原生 `before_provider_request` 钩子里取得已经持久化的原生消息 ID，在首个模型请求前作一次有界入口判定。先排除代码块与成对引文中的命令，只在用户当前指令上判拒绝、讨论或明确受控请求；明确要求 Orbit 受控执行仍直接走现有 `start` 前置校验，孤立产品名不构成授权。有成果要求的只读审计可进入语义判断，不因只读一律排除。其余请求由 `orbit-entry-3` 分别判断执行授权、实质交接价值和独立监督价值，程序按「执行授权且（交接或监督）」组合；串行交接可适用，不问速度、耗时或必须并行。没有有效新题义放行记录时不调用模型作自动入口判断，保留 Root 自主决定；不会要求用户逐次批准，也不会因入口判定直接派发成员。会话和产物仍按原合同绑定，启动失败不能说成已受控。OMP 的 `devin-agent` 类模型不触发该 provider 钩子，不能声称它在首个模型工作前已经通过入口判定。

入口启动失败时，先区分用户**明确要求受控**与仅由入口模型提出的**自动候选**。前者仍失败关闭：在已验证可安全修改的 OMP 请求体中将失败原因、原生消息 ID、逐候选选模诊断及证据提交或显式选模动作送入当前 Root 回合，未成功建任务前不得以普通执行代替受控执行；无法安全修改的请求体提示并中止。后者不因选模失败禁止普通任务执行：向 Root 与用户明确标记「本次未受 Orbit 监督」、原因和自愿补证据／显式启动的操作，不假称 JEV 已评分或已创建任务；可安全修改请求体时继续普通回合，无法确认恢复已送达时中止。明确讨论与概念问答不建任务；有成果要求的只读审计按新入口评估。对同一原生消息去重，成功绑定后清除失败提示。

Root 可向用户级缓存提交一手来源核实的精确模型质量事实，不要求先建任务或补齐 Root／全部候选。检查者先取可运行池内型号；池空或池内都不可运行时仍可从当前 OMP 目录选，经隔离只读环境模型／凭据预检。精确身份事实与有效映射目录先验同时输入，实际验收来自当前 instruction 或有效工作单元；缺失不等于不胜任。新版质量正向判断必须匹配真实校准放行、实际 Jev provider／型号、输入及问题集；未放行只呈现事实和候选顺序，Root 可自主选择。时间、速度、粗费用、异家族偏好和旧 0.55 不进入当前检查者排序。经过质量门的候选只有在可信本路由资源与可归属用量构成可比时才比较预测费用；Root 自行声明而无可归属样本的 token 构成只展示条件性估计，不参与自动费用排序。不可比时过门候选保持调用方稳定候选池顺序，不构成质量或费用优势；未知不读为免费或预算承诺。可运行降级明确质量未证实，不冒称独立检查已通过；实际失败在未尝试可运行候选中有界重选，全部失败才阻塞，在途不换模。
每次建新任务，核对候选池与当前 OMP 会话目录的交集，并预检其中型号在隔离检查者中的可解析性；池内无可运行型号时退回 OMP 当前会话可用型号，由 Root 选择经过同样预检的检查者。任何路径在目录、凭据或探针不可用且无法取得可运行型号时才拒绝建任务，并在项目本地 `.orbit/checker-selection-failures.jsonl` 保存实际核对的候选、如有的 Jev 输入／问题版本／逐型号分数和隔离探针结果；无法写入也明确提示。成功选择保存当前任务输入、评分、未评分身份、选择原因与降级警告。对可运行但缺失、过期或无效的精确身份资料，`start` 返回 `evidence_needed` 与 Root 补证步骤；Root 从一手来源提交真实事实，无法取得则记 `status=unavailable`，不借近似型号编造。新有效资料在下次检查前重问 Jev、重新选模；补证不是启动硬门。`model-status`／`/orbit-models` 的只读诊断不把未探测型号宣称为可用。
OpenRouter 模型概述是独立、可选的外发来源：用户在新终端显式配置 `OPENROUTER_API_KEY` 后，仅在项目未设置 `.orbit/jev-disabled` 时，`start` 的检查者选模准备阶段才可带认证头请求官方 `GET https://openrouter.ai/api/v1/models` 元数据及 `GET https://openrouter.ai/api/v1/benchmarks?source=artificial-analysis` 基准；不发送任务要求、代码、会话或候选对话。不配置 key、项目禁用或移除 key 后，绝不请求，也不使用先前留下的概述缓存。成功目录以用户级私有快照保存 72 小时并跨进程协调；72 小时只是抓取有效期，不是基准测量日期。认证、限流、网络或结构失败有界退避且如实显示最近外发状态，不影响旧的精确证据、Jev 或可运行检查者降级。`orbit model-status` 的候选概述状态和最近外发结果只读，不探测型号、不刷新缓存。
OMP 的 `provider/model/reasoning/billing_route` 不是 OpenRouter `canonical_slug`。映射按四字段精确匹配；随版本发布或用户级提交的清单需有第一方模型版本依据。既有四条版本来源审计不证明真实 reasoning／billing route 已核实；新增 K3 subscription_quota 结构映射仍须当前宿主确认 transport，账户／额度未知，`unknown` 不能冒充已核实路由。只有命中完整匹配键的条目可用于当次快照，目标消失／canonical 漂移或变体矛盾立即失效；不能借相邻型号、API 名、价格或吞吐补齐。Artificial Analysis 指数经 OpenRouter 返回，只能作为有来源的**模型级弱质量先验**，`reasoning=unknown` 不推断档位、不证明本执行路由的质量、价格或额度。

本次目录事实变更（工作区已接线，未作为新安装构建交付）：缓存使用 `orbit-openrouter-model-overview-v3`，旧 v1／v2 不当作 v3 复用；分别抓取目录元数据和 Artificial Analysis 基准，按实际 id／canonical 与 permaslug 精确关联；保留多个变体，不取最大值或均值。保存真实目录 ID、上下文、模态、支持参数及可得 coding／agentic／intelligence。lookup 返回有界模型目录事实，调用方须明确选择任务相关指标才提供质量先验；agentic-only 不再被通用 coding 门挡住，缺 coding 仍不能用其他指数冒充编码证据。目录能力标为 `model_catalog`，不能覆盖实际路由限制。当前来源没有可核验的测量日期与方法版本，分别保持未知，基准 `as_of` 只是数据集时刻；72 小时抓取时效不补测量日期，任务要求已知测量日期时不给先验但保留事实。未分类任务仅收到事实、不猜编码。成员与新版检查者已接该投影；完整实际路由与覆盖审计、精确测量日期资格、代表性校准仍未闭合，不能宣称新策略已验收。
本次选型使用 `jev-checker-task-fit-5`／`jev-delegation-4`／`jev-candidates-4`、`jev-selection-input-2` 和 `orbit-quality-decision-3`，新放行记录 `orbit-selection-calibration-v2` 不接旧概率与旧阈值。题义是现有任务相关质量事实是否支持把候选列为有界、可核验的适配选项，不预测未来交付成功；相关已映射模型级先验可以支持初始判断，不要求每个路由先有本地成功样本。模型级先验不是本路由质量或可运行证书；精确证据与先验存在潜在冲突、明确路由限制未知或不满足时，该候选暂停自动正向推荐，交 Root 复核。程序结构验证不能证明真实样本发生，选型放行文件尚待代表性模型实跑和独立复核。质量门通过后，仅当可信本路由资源与可归属用量构成可比时按较低估计排序；成本未知或不可比时，过门候选保持调用方稳定候选池顺序，任务适配概率不作为过门后的排序依据——池序是用户偏好，不构成质量或费用优势，未知成本不读为免费。决策版本升 -3 期间，旧 -2 放行文件在新版本下自动失效；重签放行（记录排序语义变更理由并独立复核署名）前只呈现事实与池序降级，不得宣称已放行。


**模型使用边界（本次用户裁决）：**OMP 当前会话可用且独立检查者能解析的模型无需额外逐型号用户授权；候选池是优先选型范围，不是权限名单。Root 可指定可运行型号，程序记录来源、当前任务与实际使用型号；工具参数或旧的 `Orbit authorization` 文本不再构成特殊授权渠道。检查在途不换模，实际认证、额度或检查失败不冒充通过：保留失败证据，在已验证可运行、尚未尝试的候选中按 Jev 顺序有界重选并重新检查；全部失败才阻塞并告知具体故障。成员实际模型漂移仍拒绝登记为成功。检查者继续使用 OMP 的同一模型配置和凭据解析能力，同时保持独立只读 profile、固定快照与禁止写工具；不复制账号凭据到任务记录。

入口判断以原生消息 ID 在项目内留存原文摘录、规则／问题集及内容摘要、输入与决策版本、实际判断 provider／模型、分数、阈值、可得用量或失败原因；按 ID 去重并避免同一原文消息重复建任务。已按当前有效版本完成且 delegation_value 达到其已校准阈值的入口事实，在任务建立后首个可送达 Root 的请求里一次性提示（说明本任务具实质交接价值、可先 declare 工作单元供两阶段评估或说明自行实施依据，是否分工由 Root 自主决定）：该提示只投影已付费事实，不是成员已选、不强制分工、不触发用户确认、不做成本或时间比较，且在宿主进程内每任务只发一次；未知、旧版本、修订后或已有工作单元的任务不发正向提示。新放行记录只接受版本化实际模型，绑定 `orbit-entry-rules-3`、`orbit-entry-3`、问题内容摘要、`orbit-entry-input-2`、`orbit-entry-decision-2`。记录包含预先标注的真实正负、失败与缺证样本、原始有界输入和实际判断回执、放行范围／复核者／日期／理由；程序检查样本在该门下符合标注，但这不证明日志真实或模型普遍可靠，仍须独立核实实跑来源。响应实际模型漂移、缺答案或服务失败不自动启动，保留可得消耗。旧六条样本、0.80／0.80 及旧文件的样本计数不作为新门，历史按对应版本查阅。当前源码已内置八个干净生产输入真实样本的有限入口放行：固定 `jev-1.13.0`、执行授权 0.85、交接／监督各 0.65；阈值先冻结、含两个未参与调参的 holdout 和真实 HTTP401，并经独立 OMP 复核。可观察 profile 为 `git_untruncated_request_v1`：不属于 Git 工作区或截断的 uncertain 请求不支付判断，由 Root 自主决定；显式受控仍直接走正常前置校验。这个有限放行不证明其他领域或未来任务可靠性，安装构建的自动入口和完整交付仍待真实验收。无活动任务的裸「继续」交 Root 核对可追溯原要求，不能从 Git 变化猜目标；活动任务仍按有效绑定继续。所有启动继续经过候选检查模型、权限与绑定校验，独立检查、完成和停止门不变。

任务启动后，扩展在该 Root 会话的每个用户回合开始前（OMP `before_agent_start`）注入一条由任务持久记录派生的短状态摘要：当前阶段、开放问题与待核对线索、是否已有当前版本的有效终检、下一动作。摘要不建立第二份状态，也不冒充用户输入；任务事实仍以任务目录记录为准，用户无需每轮手动查询 `status`。未启动任务不注入每轮提示：接入条件由 Orbit 工具描述与 `context` 回执提供，扩展只刷新界面状态行，不逐轮塞入完整合同。
活动任务存在时，新原生用户消息**不自动成为修订**：只有 Root 经原生工具显式提交 `amend`，才修改任务输入版本并使旧通知失效；独立问题保持独立，不能无声改动既有终检。含糊的消息由 Root 向用户明确归属；活动任务的完成与暂停由原完成门处理，不能将独立追问吞进旧任务。OMP 状态行和 CLI `status` 从同一持久状态给用户看「当前状态｜原因｜需要用户做什么或无需操作」，区分检查在途、手动终检、自动/裁定结论、完成申请和停止确认；普通用户不必代替助手执行内部命令。供 Root 的每轮状态块继续给出 `check`、`stop(intent=complete)`、修复和补证据的具体操作，历史通知数量不算当前通过；界面刷新不重扫整个工作区。外部材料确实不足时停止为 `needs_user`，列出材料与停止状态；普通 `paused` 不暗示还能重检或在终态申请完成。
当已绑定任务的原生 `ask` 因宿主 `interrupt_skipped` 合成结果未完成时，扩展只按可观察的工具调用 ID 记录跳过事实与可得的问题摘要；运行程序在 Root 空闲、无在途工具且未被中断的安全回合按 ID 最多提醒一次，请 Root 视需要重新发起原生提问。Orbit 不代填答案、不重发问题，也不把跳过当作已向用户提问成功。后续同一 Agent 的成功 `ask` 或任务终止会清除待补问；OMP 18.3.2 没有单独的「Root 明确放弃提问」事件，部分问题重问后的逐项对应也不可证，不能猜测清除。

Root 使用 OMP 原生 `task` 派发本任务拥有的执行成员，成员经原生 `hub` 通信、等待、唤醒与回报。团队保持一层：扩展在派发的 `tool_call` 门校验调用者必须是本会话已验证的主代理，成员会话的 `task` 调用被阻断，成员也不能以 Root 身份绑定或使用 Orbit（按 OMP 注册表的主代理身份校验）。Orbit 不额外授予权限，不绕过 OMP 和目标项目规则；受控成员的工具与范围取 Root 声明的工作单元，并继续受原生权限限制。Root 负责派发时传递有效要求与规则、核验集成与成员收尾。

## 成员登记（先登记、再模型工作，失败关闭）

每个原生执行成员的真实身份在其首个模型工作前持久登记，不满足则不发生模型工作：

- 受控任务的 Root 派发在扩展的 `tool_call` 门被拦截，每个 spawn 项被赋予请求名 `orbit-<uuid>`；受控任务中调用者不是已验证主代理、或注册门不可用时，派发被阻断。没有活动 Orbit 任务时允许 OMP 原生 `task` 由主代理显式派发，但须明确标记该工作**不受 Orbit 登记、检查或停止监督**，仍受 OMP 自身权限及单层团队限制；不得产生伪造的 Orbit 成员记录。
- OMP 的 AgentRegistry `registered` 事件在 `createAgentSession` 内同步发出，早于成员的首次 provider 请求。扩展在该窗口内同步调用登记入口（`scripts/orbit-register-member`），由 TaskRecord 以临时文件 + fsync + rename + **目录 fsync** 写入任务目录的 `members.json`（任务内权威成员清单）。写入成功才放行；写入失败、成员清单损坏、或实际注册 ID 与请求名漂移（分配器返回加后缀的重复 ID）时，扩展将注册表状态翻转为 `aborted`（终态）使会话创建失败，并在 `members.json` 记录 `refused`（含原因与 `abort_confirmed`）。阻断以 `setStatus` 返回真且读回 `aborted` 为证；无法确认阻断时不记录为干净拒绝。
- 登记记录包含实际 `thread_id`、请求名、状态、实际模型（可得时）、工具调用 ID 与时间。TaskRuntime 的正常 tick 与异常退出后的显式 `stop` 重试都重读 `members.json` 重新发现全部实际成员 ID；不依赖插件内存或事件流。

## 输入与独立性

- 一个任务对应一个授权项目根、一个产物工作区、一个已接入的 Root 会话和一个 Orbit 运行进程。输入只需当前项目、原始执行要求及明确指定的依据。
- 输入是用户原始执行指令及明确指定的依据文件。Agent 发起时从所绑定会话的指定用户消息读取原文；用户直接发起时可明确提供文本。不将 Root 摘要标记为用户原文。
- 后续明确修改追加保存，检查使用最新有效输入。程序记录来源和版本；不要求模型手写摘要哈希、receipt 或 evidence 链。
- 依据文件的内容保存在任务目录；项目内规则包含于实际产物快照。外部引用只读取明确给出的文件，不递归读取用户目录。

### 工作区绑定

新任务同时保存 `project_root` 与 `workspace`。`project_root` 是授权、任务记录和 Root 会话所属目录。`workspace.artifact_root` 是产物目录，默认与 `project_root` 相同，并记录真实路径、Git common dir、worktree、HEAD 和绑定时间。固定快照、指纹、Jev 变更摘要以及新执行成员的工作目录都使用 `artifact_root`。检查者与裁定者仍只读该快照，不获得执行成员的权限。

产物目录只在创建时的默认绑定，或显式 `rebind-workspace` 时改变。该命令接受同一真实路径，或同一 Git 仓库（相同 common dir）中的另一个 worktree；非 Git 的不同路径拒绝。CLI 与原生工具只把该命令写入队列。任务进程记录来源、原因和 history，并按新的产物目录继续观察。终止任务拒绝。`amend` 与 `dispute` 只追加检查输入或争议理由；修订通知按实际 `source` 记录，`explicit_text` 不表述为用户本人消息。

在途检查记下当时的 `artifact_root`。完成时若与当前产物目录不同，即使内容摘要相同，也记为 `workspace` 过期。因工作区过期的 finding 不迁入待核对线索；程序为新的产物目录安排一次检查。其他原因的过期不因此立即重查。`status` 显示产物目录、绑定时间和最近一次重新绑定。没有 `workspace` 的旧记录，`status` 与 `stop` 把产物目录读作 `project_root`，并且不回写记录。程序不自动检测「声明的产物位置与绑定冲突」，也不因此暂停完整检查。

## 程序与模型

- 程序负责实际会话绑定、状态观察、计时、固定检查输入、投递纠正、执行停止和持久记录；不判断某个工程方案是否正确。
- Root 负责实现和必要分工。独立检查者根据原文、依据、项目规则和固定产物指出遗漏、错误、多做以及下一次观察时间。
- 问题先补事实或修正；仍有真实争议才由独立裁定者处理。偏好不阻断，裁定不改变目标或授权。同一 finding id 已是 open 时，若输入摘要、`artifact_root`、产物摘要、requirement、evidence、action 都没有变化，后续检查的重复报告记 `finding_repeat_ignored`，不再次纠正 Root。任一证据维度变化才重新投递。已 resolve 的同一 id 也按这六项绑定；六项都没有变化时不重开。换一个新 id 表达语义相同的问题，程序不猜测为同一问题；检查者只按 prompt 复用已有 id。
同一 finding 在连续两次基于当前输入及当前绑定证据的有效检查中仍开放时，程序保留重复纠正去重，但在状态中一次突出该 ID、最新证据及下一动作（修复并重检、附证据 dispute，或由用户裁定真正的产品口径）。六项绑定中任一实质变化时重新计算连续次数，允许新证据重新纠正；仅靠重复次数不关闭 finding，也不停止任务。
- 检查误报可被独立裁定推翻；撤销结论和原因保留，后续检查不得把已撤销结论自动视为未解决。某个有效手动检查的 `delivery.ready=false` 若被同输入、同产物版本的有效独立裁定或后续独立检查以可核验交付事实推翻，旧不可交付理由不再作为现行下一动作；记录转为「需当前版本的手动终检」，**不**由裁定或自动检查发完成通知。普通停止后即使留有旧原因，终态任务也不能再重检或申请完成；若仍需交付，应建新任务。
- 发现明确授权缺口、边界违反或已裁定纠正持续未落实时，暂停相关执行并报告具体原因。不自动替换 Root。观察程序报错时先尝试收尾绑定执行，记录失败与确认结果；无法观察后续用户修改时受控停止并报告 needs_user。不自动恢复运行。

### 可选 Jev 调度

Jev 的首个判断 provider 是 TypeSafe 的 `https://api.typesafe.ai/v1/systemone`；待替换的任务内既有问题集仍使用 `jev-latest`，新入口只使用对应真实放行记录固定的版本化模型，不能静默跟随别名漂移。TypeSafe 的 [模型文档](https://docs.typesafe.ai/models) 与 [API 文档](https://docs.typesafe.ai/api)允许通过 `model` 字段选择该服务提供的 System One 模型；这不等于任意 Coding Agent 模型或其他服务商可直接替换。

**统一判断数据模型与 provider 适配（源码已实现）：** Orbit 的外部判断调用通过自有 `JudgmentRequest`／`JudgmentResult` 携带有界 `state`、稳定问题 ID、真假标准、数据模型及问题集版本；按 ID 消费经校验的有限 `[0,1]` `probability_true`。未回答完整、服务失败或不可映射时返回带结构化原因的 `unavailable`，不使用部分答案触发自动动作。TypeSafe 适配器负责鉴权、HTTP 与原生响应映射；成员与检查者按上述新版本解释和校准，旧时间双门及整体比较不作为备用路径；失败仍不触发正向动作。新增 provider／模型必须显式选择、针对会触发自动动作的判断分别校准；不能将自由文本、自报置信度或未经验证的新服务分数套入 Jev 门槛，不能在失败时静默换服务。凭据不进入任务记录，判断 provider 不等同于 OMP 执行／检查模型候选池。
判断记录同时保留 `question_set_version`、实际 provider／模型及可得用量：入口写入消息级账本与任务 `entry`；任务内观察、成员建议和检查者质量判断分别写入其实际事件／状态或检查模型选择记录，避免问题集或模型变化后把历史概率当作同一种分数。判断失败不以旧分数触发新动作。

本次判断回执变更（工作区已接线，未作为新安装构建交付）：`unavailable` 的答案仍为空、不能触发自动动作；服务响应中实际返回且可校验的模型身份和用量独立保留，包括 HTTP 错误、缺答案或非法概率响应。没有返回的身份或用量保持未知，不以请求型号、零消耗或部分答案补齐。公共 Jev 错误附带该回执，入口 trace、runtime 第一／二阶段状态与事件、检查者选择记录保留其身份与用量；失败用量参与累计，缺失标 incomplete，池内 pending 判断也累计且推荐分支不重复计。完整调用归属和整次结算仍须按 ADR-009 §6 接通并验收。

判断调用归属接线中：每次 provider 调用由适配器生成独立本地 `call_id`，不发送到模型输入、不冒充供应商返回 ID；相同请求重试仍是另一次可能消耗。成功与失败回执都传递该 ID、请求型号和实际型号；入口 trace、任务内状态／事件及检查者选模记录保留它们。任务私有 `resource-calls.json` 按调用 ID 去重，启动前入口／选模回执在任务创建后接入，不从时间窗口猜归属；旧记录缺 ID 只标未归属，不生成历史 ID。原始 input/output/cache/reasoning 等字段分别保留单位和缺失情况，不无条件相加或折算金额。当前接入范围与完整性见当前计划，尚不能以判断账本宣称 Root／成员／独立检查和实际路由结算已闭合。

当前 TypeSafe 实现只从启动 Coding Agent 时的 `TYPESAFE_API_KEY` 环境变量读取 key，对新 Orbit 任务全局启用；`orbit jev setup` 可一次性输入 key，写入当前用户的 TypeSafe 环境文件并配置 zsh／bash 启动文件，使新终端自动提供该环境变量。key 不写入 Orbit 配置或任务记录；已有环境变量优先。当前终端和已运行任务不会被子命令改动。每个 Orbit 任务可以把有界的原始要求、指定依据摘录、有效修改、近期宿主观察和产物差异摘要交给 Jev。项目可以单独关闭该外发。监督 Jev 返回"可能卡住""可能偏题""当前产物值得完整检查"；成员质量判断独立消费具体工作单元的交接／适配问题。程序依据对应输入和当前任务状态安排检查者或提示 Root，不将概率当作问题证据、完成结论或停止授权。指定依据超出预算时明确标注截断与省略；有效修改超出预算时保留最新部分并明确标注被省略的范围，不把缺少的依据或更早修改当作需求不存在的证据。
`orbit openrouter setup` 单独交互输入 OpenRouter key，私有环境文件只供新 zsh／bash 终端加载，已有 `OPENROUTER_API_KEY` 环境变量优先；不借用 TypeSafe 或 OMP 的 key，也不修改当前终端与运行中的会话。setup 仅保存凭据，不代表接口鉴权或模型覆盖已经核实。

新版成员提示已接运行时（工作区，未作为新安装构建交付）：Root 用 `orbit work-unit` 声明目标、要求引用、上下文／决定、范围、验收、依赖和升级条件。成员范围按声明强制：`allowed_paths` 是成员全部可访问路径且读写共用，规格／测试／依赖需要访问时也必须列出，或把必要事实放入 `context`；它不提供自动只读保护。`allowed_commands` 必须是完整命令、逐字精确匹配，不是前缀。单元 v2 从真实 TaskRecord 捕获输入版本和产物根，不接受提交者伪造；旧版输入或重新绑定后的单元不得派发或 accepted，失败／拒绝产物仍留证。只有当前版本且依赖已 accepted 的单元进入建议。

每次 finish 将状态、结果、核验和结束时间保存到对应 `dispatches` 记录，与实际成员／调用／型号一起交给后续成员及选择判断。重派只清空当前尝试的结果，不删除历史结果，不改写资源账本；旧 v2 单元重派前保存仍可核实的最近一次结果，更早已缺失的结果不补造。一次失败不自动成为型号禁用，Root 须结合失败原因和新证据决定补输入、重试、升级或结束该路径。

推荐 hint 与派发的绑定按**同代**校验：只有持久 hint 的版本与该工作单元**实际 persisted selection 记录**的版本一致（两者都是非空版本），且签名、消息 id、单元、输入版本、产物根、尝试序号、用户边界与实际成员／调用全部匹配时，程序才把 `hint_signature`／`hint_message_id` 记入该次派发；不得以缺省值相等（undefined == undefined）或旧代 hint 配新代 selection 通过，也不为旧 `v1` 另建无调用方的兼容层。Jev 的问题、阈值与 decision-3 放行不因该修正改变。

成员在**真实原生错误**后停止、且无在途工作时，程序按**精确派发身份**记录一条执行失败事实：错误须为该成员当前回合的结构化 `stop_reason=error` 且带可解析时间、不早于本次 `bound_at`；无在途须同时满足非 streaming、`active_tools=0`、registry 为**已知 `idle`**（SDK AgentStatus 可观测空闲；`null`／parked／未知一律保留 Root 手动 finish），并且**实际 owner-scoped async 快照的 `running` 为空**——缺 getter、`null` 或未知形状一律不推定“无在途”，保留 Root 手动 finish 路径。满足时，仅当该单元**当前为 `bound`** 且其 latest dispatch 的成员与调用与本条完全对应，程序在单元 store 内原子地把该单元记为 `failed`，把真实原生错误、来源与结束时间写入本次 attempt，历史结果与资源账本全部保留；已由 Root 裁决、已换绑或已 `accepted` 的单元不被覆盖，旧输入版本或新工作区的单元仍只能保留旧失败、不能据此在新版本派发（正常派发门不变）。该记录只是**程序观察到的执行失败**，不伪造 Root 的业务 `accepted`／`rejected`／`acceptedAt`，也不代替 Root 对结果验收与是否重试／换模的决定。

成员成本预测引用已接受单元时，还须匹配该接受结果的实际成员和型号；后续换人完成不追认前次已拒绝结果的成功样本资格。此前实际消耗继续计入资源账本，预测不可核实则成本保持未知。原生回执不声明 reasoning 时账本保持缺失；`similar_unit` 引用核验只在该比较处把缺失按类型化 `unknown` 与预测路由对齐，已报告的具体档位仍须精确匹配、不归一为 unknown，账本记录本身不改写。

候选取池∩当前目录∩原生 Agent 映射；实际空池用一次原生 task 解析，池读取失败不静默回退。逐候选保留真实四键身份、目录先验、精确质量事实、实际路由能力限制与潜在冲突。不要求 Root 或全池事实，不拿相邻型号、价格、速度或目录上下文冒充任务质量。未放行只呈现事实；有效放行先问 handoff_fit／member_task_fit，通过后问逐候选任务适配，两次实际回执均按独立 call_id 入账。程序缓存实际输入、完整工作单元／失败历史、候选事实、放行绑定及可得路由资源；未变复用不付费，变更重新评估。

派发仍由 Root 经原生 task 发起。只有成功送达且持久记录的 delegation_hint 是程序建议；观察在判断期间变化则延后提示，不把准备动作当已发送。同一签名只送一次，修改要求／工作区或事实使旧建议失效。采纳归因必须同时匹配真实 unit／member／tool call／model 与目标派发尝试；旧失败调用、同型号或时间相邻不能冒称采纳新的推荐。串行交接合法，不要求 Root 并行另做一份工作。

本次工作区宿主接线要求每个受控 task 文本以独立行 `orbit-unit: wu-...` 引用耐久单元；核对当前原始输入、实际产物根、状态及 accepted 依赖。批量调用全体预检通过后才改写请求名和补齐原始单元上下文；同一单元不能同时派给多个成员。登记窗口或首次可观测实际模型时执行同步 bind，失败成员不得使用工具。采纳提示的签名及 message ID 只从 task 调用当时已送达的当前提示捕获，普通 Root 自选不补记推荐。成员逐工具调用继续核对绑定和真实路径；声明的命令还须通过已验证系统沙盒，未知平台和入口不静默放行。macOS 越界写入和网络拒绝已有本机核验，原生 isolated worktree 不能替代权限沙盒或静默改变产物绑定。当前不宣称工作区重绑定接缝或新安装构建自主派发闭环已经通过。

工作区原生用量接线观察 SDK assistant 调用边界，保留实际角色、执行身份、单元和原始字段；没有报告的推理档与上游身份保持缺失。pending 留在可更新 sidecar 并显式计作覆盖缺口，不在停止时提前写入不可变未知行；最终回执由宿主直接写入任务账本，因此运行时退出后的晚到用量仍可记录，不修改终态或重新启动执行。持久化失败有独立私有缺口通道，未知不等于零。账本只承诺已记录调用的范围，完整真实模型覆盖及成本选择仍待验收。

**受控成员模型边界（2026-09-29 修订）：**Root 决定是否分工，Jev 只给建议、不自动派发。每次受控原生 `task` 调用前按本会话最新候选池与 OMP 可选目录生成原生 Agent；池内 Agent 可在补证待答时由 Root 自行显式选择，不假称 Jev 推荐。通用 `agent="task"` 或省略 agent 则先解析当前 `@task` 的精确 `provider/id`：存在可用池内 Agent 且默认型号不在其中时**拒绝**受控派发，明确列出可用 Agent 和待补证动作；池空或无可用池内 Agent 才可保留已解析的 OMP 默认角色，不能静默把有池任务交给池外默认。普通非受控 OMP 会话不受此门约束；Root 如确要使用默认型号，可通过 `/orbit-models` 把其纳入可用候选后再派发，不能靠虚构 Jev 建议绕过。模型无法解析、Agent 已不在本会话池中或注册／首次模型请求时实际型号漂移，仍拒绝并说明下一动作；登记派发不等于模型身份、成员交付或停止已获证实。

精确质量补证是可选事实补充，四键身份必须逐候选来自真实路由；unknown 与 provider default、不同 billing route 不互换，不为命中 lookup 改路由。新补证字段退出时间／速度／local_samples／cost_tier，测量日期与检索日期分开；历史记录保留但旧指标不进入当前选型。目录报价不进入 OMP 结算，资源事实来自独立可信路由数据流。资源事实的发布生效日未知时，只允许以显式 unknown 标记存档：该事实可列出但覆盖不了任何调用、永不参与定价或成本推荐，绝不用页面更新时间、最后更新日期或检索时间顶替发布生效日；没有该显式标记而缺生效日的导入仍被拒绝。检查者 reasoning 或实际 route 不可证明时保持 unknown，主会话的 SDK 解析不证明独立进程的服务端配置或账户。补证触发下一次新判断，不中断在途检查、不给已执行工作追荐。

明显的卡住／偏题信号可触发过程检查；产物就绪信号可触发完整产物检查。过程检查只判断是否有需要 Root 纠正的具体问题，不能完成任务。周期 Jev 仅在可辨认的任务状态、输入、成员或产物变化时调用模型，不因时间流逝且没有新事实反复判断；Root 工作中不因纯定时重复完整检查。自动检查按 observation key 去重；旧进程遗留的同 key `in_flight` 记 `check_abandoned_recovered` 并以新检查号重试一次。用户手动请求可绕过去重但不能与在途检查并发。**无 finding 不等于交付就绪**：独立检查须结构化标记当前交付是否就绪及未就绪理由，只有有效的手动终检明确就绪、无当前 finding／待核对线索、成员已结束且 Root 已完成一轮时，按输入与产物版本发送一次 `finalization_notice`。纯文字交付要先形成可供检查的实际答复；不能用尚待未来交付的承诺领取终检通过。Root 未完成一轮时偏好等其 turn 结束再通知，但**按版本绑定的 pending 通知即使 Root 仍在 active/等待，也必须在有界 60 秒内送达**。送达 pending 通知**不自动完成任务**；Root 的显式完成意图仍须等待其 turn 收尾，并在停止时核对当前产物、输入与成员状态。等待期间不采用检查者给出的短间隔持续复检。`check` 的机器响应要求：没有用户预先明确、且不依赖检查结果的后续状态变更时，Root 结束当前 turn 并等待 Orbit 唤醒，不应仅为等待检查结论而 sleep、轮询或查询状态。检查者只能核验终检当下可见的答复／产物；完成申请后的最终措辞仍受版本门与 Root 的交付责任约束。
当前版本的自动产物检查若确认已实际交付、无 finding／待核对线索且成员结束，只能按版本**至多提醒 Root 一次**主动请求手动终检；不发 `finalization_notice`，不把自动检查提升为手动检查，也不代 Root 申请停止。真实用户消息、输入或产物改变后沿原版本门重新核验。

检查模型在隔离目录不可用、认证、额度或结果校验失败时先保存失败证据；检查结束后在当前 OMP 会话可选且隔离环境已核对的剩余型号中按池优先、Jev 适配顺序有界重试，同一输入和产物版本不重复尝试失败型号，不在途切换。没有剩余可运行型号才阻塞；**失败阻塞的同一模型不允许用重复手动 `check` 绕过阻塞**，CLI 和运行时均拒绝。候选池、目录、凭据或有效证据等选择输入改变时可重新评估；Root 也可通过 `review-model` 选择 OMP 可用型号并触发新检查，无须新用户型号授权。手动检查绕过去重不绕过失败门；没有有效独立终检时不得假称任务已完成，可按用户明确要求普通暂停并核对停止确认。

交给检查者与裁定者的程序上下文有 64KiB 上限。原文、修改和指定依据不压缩；其余长文本保留有界前缀并附原文长度与 sha256；历史列表按限额保留较新的一段，省略范围显式标出。程序另按现有 `state.checks` 计算一个有界 `check_history`：**当前 input 与真实产物根**对应的**最早有效 artifact reviewer 检查**为锚点（role=reviewer／kind=artifact、非 failed 非 stale、其自身 `artifact_digest` 作为历史保留；修复或任何编辑都会改变产物摘要，故锚点不按当前摘要匹配，也不授予当前完成资格），其后是限额内的较新窗口，每条只含检查身份（number／role／kind／产物根／输入与产物摘要／开始与结束时间／终态／stale 原因／failure_kind），省略项以计数与编号显式列出，重要锚点不被单纯尾部窗口淘汰后谎称不存在；它只是历史事实，不授予当前完成资格，也不把旧版本 finding 导入待核对线索。

## 原生协作观察（hub 与成员状态）

扩展把本任务的原生协作记入进程内、按任务隔离的有界缓冲，供 TaskRuntime 轮询：

- `hub_events` 返回 `{ events, dropped_oldest, next_seq, buffer_cap }`；每条事件带按任务单调无隙的 `seq` 与稳定 `id`，以及 `task_dir` 归属。事件含原生 `hub` 或 OMP `write agent://<peer>` 的真实消息意图（op/to/from/message；Root 来自 awaited `tool_call` 门、成员来自所属会话的工具开始事件）、实际工具结果和原生 `task` 结果。缓冲内消息有界截断，同任务 `collaboration.jsonl` 按观察顺序保存未截断的原文和实际回执；调用意图不等于成功送达。seq 跳变或 `dropped_oldest` 增长是该任务真实的 observation_gap 信号。
- 有界缓冲在 OMP 进程退出时丢失；任务目录的独立协作记录保留已归属事件。无绑定事件不追认给后来的任务，持久写入失败标明 gap，消费者仍须及时轮询。
- 按实际成员 ID 可查 `member_state`（registry 状态、实际模型、会话是否存活、registry 生命周期 `acceptedAt/terminalAt`、`async_jobs` 快照、当前分支末条 assistant 为错误回合时的结构化原生错误事实 `last_turn_error`）、`member_result`（持久产物路径与有界内容）、`send_member`（向成员投递用户修改，steer；仅任务 starting/running 时允许，失败如实上报）与 `stop_member`。SDK 注册表 ref 被移除后，`member_state`／`member_result` 以注册窗口保留的身份、`history`（持久输出路径、解析型号）、`lifecycle` 快照与保留会话继续只读服务，不因 ref 消失丢失已观测终态；任务所有权校验与停止屏障不因此放宽，无存活会话的成员不可 `send_member`。
- **成员结算（2026-09-30 修订）：**成员终态集合为 `completed`／`failed`／`refused`／`rejected`，来源分级、互不冒充。原生接受：SDK 注册表 `lifecycle.acceptedAt`（仅成员经 yield 交卷路径产生；毫秒 epoch 数值或 ISO 字符串按原生单位解析）保持原生事实记入 `accepted_at`，不得伪造；已被失效结算的同一 acceptedAt 值不得再次结算。本派发核验完成：成员当前绑定的最新 dispatch（实际成员 ID 与 tool_call 精确匹配当前尝试，且该单元输入摘要与产物根仍为当前版本；成员记录未带单元关联时按同一精确身份从耐久单元记录唯一恢复，歧义或型号不符不恢复，不得按相似型号、时间或相邻事件归因）经 Root `accepted`，且该派发有真实原生交付——本派发绑定后写入的持久输出文件、大小或内容非空、结果文本经该文件读取——且当前无 running/streaming、在途工具为零、后台状态按完成门处理，记 `completed`、`result_delivery=work_unit_acceptance`。时间证据（回合时间、绑定时间、文件 mtime）缺失或不可解析时不视为当前，不据此结算。原生失败：桥暴露本回合真实 provider／原生错误（当前分支末条 assistant 的 `stopReason=error` 结构化字段；显式 null 表示已观察的最近回合非错误，清除旧事实；字段缺失才是未知），且该回合身份不早于本派发绑定，且回合与工具已结束，直接记 `failed` 并保存原生字段；不以 Root 文字、返回文本或 idle 推断失败。业务拒收：Root `rejected`／`failed` 且有真实原生输出、执行已结束、无当前原生错误，记 `rejected`；这不是原生失败，不记 provider error；成员无任何可归因原生事实时保持未结算。模型漂移仍是硬否决，优先于一切结算。执行终结与现行任务证据资格分离：物理派发身份取实际 thread_id、tool_call_id 与该单元最新尝试的唯一匹配（含实际 model 核验），输入或产物根版本变化本身不撤销已发生的执行终结，也不伪造新执行；但旧版本上的结算只是该次执行事实，业务 accepted/rejected 的新结算仍须当前输入／根、真实交付和当前检查链；原生 acceptedAt 是当前执行的接受事实、按自身路径结算，单凭它不授现行 ready／coverage。二者都不能替代当前版本终检。成员再现真实新轮（running/streaming/在途工具）、实际重派导致的派发身份变化、model drift 或更新原生回合错误时，旧结算失效回到未结算（历史保留在事件与 `settlement_history`）；重派／新回合不得借用旧验收，SDK 按轮次清除的 lifecycle 不跨轮恢复。
- 已确认停止的成员不能再经原生 `hub` 或 `write agent://<member>` 被唤醒；任务非活动状态时对本任务成员的两种发送在工具门被拒绝。非 Orbit 成员与其他任务的流量不受影响。
- 终检就绪的 `pending_finalization` 等待成员结算有界：超过等待上限、版本仍有效（产物与输入摘要未变）而成员结算仍不可证实时，程序对该版本只发一次明确的 Root 收尾通知，列出未结算成员与各自缺失的事实，请 Root 显式结束成员／单元后再申请完成；不自动置 `needs_user`／`stop_unconfirmed`，不按时间推断失败，不停止任何进程，成员结算门、独立终检与真实停止门均不绕过。

## 观察与完成

- 新建任务，以及实际开始新版检查的活动旧任务，要求逐项覆盖证据：独立检查输出 `coverage={complete,items}`，每项保存 `requirement`、`scope=delivery|lifecycle`、`status=verified|unverified` 与具体 `evidence`。`complete` 只表示检查者已枚举原始要求、有效修订及指定依据中的全部要求；它不是程序证明。未读材料、未核验项或压缩缺口必须显式 `unverified`，不能从无 finding、Root 自述或 Jev 分数推导已覆盖。逐要求与 evidence 文本按 1000 字符上限记录：截断只表示记录限制，不改变覆盖完整性、verified/evidence 要求或验收门。
- 覆盖 v2 的 `delivery` 包含产物、集成、要求执行的测试及回答内容；`lifecycle` 仅包含当前终检及其后的完成／确认停止／结束报告。后者仍留存，不声称未来事件已发生，其资格由程序的手动终检、当前回复结束及实际停止门核实；不能要求停止前先证明停止，也不能把测试执行改归生命周期绕过证据。旧项缺 scope 仍按 delivery 解释，不自动移除旧缺口。宿主验证回执保存实际工具执行、当时输入／产物／根及来源；检查者不得把 Root 自写日志或声明冒充程序观测的执行。Root 的文件工具（edit／write）也进入同一回执类：只记真实开始／结束时间、身份与绑定摘要及有界目标路径元数据，**不保存写入内容、patch／diff、脚本正文或工具结果正文（回执 `output` 保持 null）**；未观测到开始保持 unknown，未证明可解析的目标方言（如 hashline）保持 unknown 而不手写猜测解析；控制地址（`agent://`、`xd://` 等）记为路由目标，不冒充文件变更；“观测到一次文件工具调用”不等于字节已改变，`isError=false` 也不能当作已写入证据。
- 程序把覆盖绑定实际检查号、角色／kind、输入摘要、固定产物摘要及真实产物根，持久写入私有 `requirement-coverage.json`；过期记录只作历史，过程检查／裁定不产生交付覆盖资格。同版本最新产物 reviewer 的不完整或未核验结果不能被旧通过覆盖。局部程序回执或工作单元通过可作为有范围的证据，最终仍需整体枚举与集成核查；检查者只读工具不能执行测试，须区分自己读到的事实与 Root 实际回执。
- 新任务只有当前产物 reviewer 明确完整枚举、交付项至少一条且全部 verified，才可产生手动终检就绪通知并通过完成复核；生命周期仍由程序的独立门核实。缺覆盖、损坏或写入失败保持 `requirement_coverage_unverified`，不编造通过；普通停止仍可收尾。新任务保存 `coverage_required=true`，旧记录缺字段的历史完成不追认成新覆盖，导出保留缺口。覆盖不改变执行权限或用户要求。
- 观察由程序在约定时间和可识别的执行结果节点触发，不依赖 Root 主动申请。等待只等待事件或时间，不调用模型。
- 检查读取固定副本，允许 Root 同时工作；必要验证在隔离环境进行。文件内容、文件类型、可执行权限以及符号链接目标参与产物版本识别。
- 固定快照里的 `review_focus.added` 取 Git 工作区相对索引／HEAD 的状态，包括**在本任务开始前就已存在的未跟踪文件**；它是检查优先级线索，不是“Root 在当前任务中新增”的时间证据。检查者须结合本任务动作、可得的开始时证据和实际要求归因，不能仅凭此列表要求删除其他任务的既有产物。
- 检查者另获得任务绑定时 HEAD 到本次固定快照 HEAD 的有界已提交路径线索；只有 Git 能证明起点为快照 HEAD 的祖先时才提供，不能据此认定提交属于本任务。`review_focus` 仅含当前工作区相对 HEAD 的改动，可能漏掉本任务期间已提交的交付；两者都须结合原始要求和快照文件核验，不能凭否定性文件名猜测断言产物不存在。Root 的任务相关已交付答复按输入／产物版本留存为检查线索；后来独立问答不能覆盖它或充当本任务唯一交付。
- 同一输入与产物版本下，运行程序给独立检查者保留最近至多四个**归属本任务且已完成**的 Root 回复（最近一条及前三条）；手动终检排队的回执本身不能抹掉此前真实交付。检查者同时看实际交付与后续回执，若后续实质修订否定旧答复则据此判断；输入或产物版本一变，旧回复不带入新版本。不相关用户问答仍不归入此历史，也不能以历史答复代替检查固定快照。
- 旧版本上的纠正或完成结论应用前必须核对当前产物与输入。发生变化时重新检查相关变化，不能把旧问题直接当成新版本仍存在。
- 检查完成时记录本次过期由产物、输入、宿主状态、工作区还是争议变化引起。产物检查判断固定 snapshot：纯 Root turn、只读 `status` 或观察记录变化不产生 `host` stale；workspace、artifact、input 与 dispute 仍按版本判断。过程检查以 Root 行为为检查对象，保留 `host` stale。工作区过期的 finding 不迁入待核对线索。其他过期检查中仍可能有待纠正的问题：记为待核对线索，在 Root 交付、下一次约定检查或用户请求时对新版本重新核对；核对确认仍成立的问题按普通纠正自动送达 Root，不要求 Root 轮询状态。
- Root 正在执行时，检查者建议的下次观察时间不会让完整检查比约定间隔更频繁；Root 空闲时仍按检查者建议执行。自动的明确修改与 Root **归属本任务的交付**触发检查不受纯定时节流限制；只有与本任务无关的用户问答和 Root 完成回合、且输入／产物未变时，不产生新的交付检查。同一任务有真实新变更、有效纠正或手动检查时仍按原门处理；消息归属无法可靠判定时不把该消息当作已交付，也不静默归入任务。自动检查按 observation key 去重；旧进程遗留的同 key `in_flight` 记 `check_abandoned_recovered` 并以新检查号重试一次。用户手动请求可绕过去重但不能与在途检查并发。**无 finding 不等于交付就绪**：独立检查须结构化标记当前交付是否就绪及未就绪理由，只有有效的手动终检明确就绪、无当前 finding／待核对线索、成员已结束且 Root 已完成一轮时，按输入与产物版本发送一次 `finalization_notice`。纯文字交付要先形成可供检查的实际答复；不能用尚待未来交付的承诺领取终检通过。Root 未完成一轮时偏好等其 turn 结束再通知，但**按版本绑定的 pending 通知即使 Root 仍在 active/等待，也必须在有界 60 秒内送达**。送达 pending 通知**不自动完成任务**；Root 的显式完成意图仍须等待其 turn 收尾，并在停止时核对当前产物、输入与成员状态。等待期间不采用检查者给出的短间隔持续复检。`check` 的机器响应要求：没有用户预先明确、且不依赖检查结果的后续状态变更时，Root 结束当前 turn 并等待 Orbit 唤醒，不应仅为等待检查结论而 sleep、轮询或查询状态。检查者只能核验终检当下可见的答复／产物；完成申请后的最终措辞仍受版本门与 Root 的交付责任约束。
- 完成必须对应 Root 已结束当前执行、实际交付版本通过独立检查、相关执行资源完成收尾。失败、未知、未检验和未停止分别如实记录。
检查通过、当前版本可申请完成、完成申请已入队、以及实际停止确认是不同状态；通知失效或完成申请被拒必须显示原因码与下一动作，不能以隐藏的自动完成代替 Root 的完成意图和停止硬门。对「提交并推送」之类要求，检查者另获得有界只读 Git 事实（本地 HEAD、目标分支、可取得的远端引用及核对结果）；网络不可达或引用不可取得标为未验证，不将 Root 自报当作远端证明，不给予检查者写 Git 的能力。用量分别记 Root 任务级可得值（无可靠归属则未知）、原生成员、Jev 入口／选模／任务内调用与检查者 tokens；不从耗时或订阅额度臆造金额。
- 完成意图必须建立在当前有效终检上：Root 工具显式发起的完成意图（内部 complete 标记）在执行前同步核对「当前版本的 manual reviewer 结论无遗留问题」——存在按当前产物与输入版本绑定的 `finalization_notice`、无 open finding 与待核对线索、成员已结束、检查可用。缺 `finalization_notice` 或仍有未闭合问题时，工具同步返回结构化拒绝与**按原因区分的下一动作**（缺 notice 指向在最终版本上请求手动 `check` 并结束当前 turn 等待；open finding／待核对线索先修正或完成核对；成员未结算先结束成员；检查清理未核实先重试并核实清理），CLI 回执与运行时唤醒共用同一原因→下一动作映射；回执明确区分「命令已入队」与「完成前置条件未满足」；不入队、不自动降级为暂停、不改变任务状态，任务保持运行，用户之后仍可再次请求终检。存在未核实的检查清理记录（`cleanup_error`）时，按检查不可用同样同步拒绝。记录的运行进程已退出或已失败时，完成意图同样被同步拒绝（原因码 `runtime_unavailable`），并明确指引用一次**显式普通 stop** 完成已确认的清理与成员收尾——该清理重试属于普通停止路径，完成意图不得借用它。
- 前置核对通过后，完成意图把停止入队：程序等待 Root 当前 turn 正常结束（`completed`，用户最终交付完整送出）后执行实际停止，并在**拆资源前**再次核对当前产物、输入、成员与停止确认；全部合格记 `complete`。**拆资源本身可能持续（成员停止需等在途工作），因此在资源停止后还要做一次复核**：这次复核只依据持久状态（notice 是否仍对应当前产物与输入、open finding 与待核对线索、成员结算、检查清理是否已核实；指纹或 roster 不可读同样不合格），**不再查询已停止 Root 的桥接**——停止证据以本次停止确认（`stop_confirmation`）为准，桥接瞬时不可达不得把合格完成降级为暂停。复核不合格时一律不得记 `complete`：已停止的运行按普通停止记 `paused`；停止确认失败，或复核发现本次停止未覆盖的成员（停止期间新登记进权威 `members.json`、或名单不可读）时记 `stop_unconfirmed`——不得把未被实际停止的成员谎称已确认暂停。复核还必须重新读取权威 `members.json` 并与本次停止覆盖的名单对照（拒绝登记、从未做过模型工作的条目不参与）；并在记录中保留 `completion_invalidation`（原因码、说明与时间）与 `completion_invalidated_after_stop` 事件；该情形不得表述为任务仍在运行。同一交付轮次被中断或等待超时，按普通停止记 `paused`／`stop_unconfirmed`，绝不记完成。
- 用户明确中断走显式暂停：Root 工具的暂停意图与普通 CLI `stop` 都按普通停止处理（`paused`／`stop_unconfirmed`，保留会话与上下文），不受完成前置条件约束，也不因此记录完成；Esc/内部停止请求、硬截止与崩溃后的停止重试同样不走完成路径，CLI 原有普通 stop 语义不变。

## 停止与资源

- 最小暂停单位是承载相关工作的 Agent 当前执行；保留会话和上下文，确认关联后台动作实际停止。不得把仅发送中断请求、注册表标签或 `hub cancel` 回执当成停止证据。
- Orbit 控制明确绑定的 Root、本任务登记的全部成员与自有检查进程。原生界面中断 Root 时，程序负责停止其登记成员；中断请求持续有效，不被紧接着开始的活跃轮次掩盖，明确启动新任务时才重置；即使一个成员停止失败，仍尝试停止其余成员。
- 成员停止确认按实际观测分级：会话存活时经 abort、按 owner 取消并等待异步任务底层工作结算，且以观测到的在途工具数归零为证；成员的注册表会话已释放（完成后的 idle/park 处置）时，OMP 18.2.8 对处置完成没有公开信号，后台与进程退出不可证实——桥返回结构化证据且 `confirmed:false`，任务保持 `stop_unconfirmed`，不得把"已完成"或注册表 idle 充当退出证据。OMP 进程整体退出时，以进程与实际子进程退出为证据。
- 已退出的 failed／stop_unconfirmed 任务接受用户显式 stop 重试，从任务记录（含 `members.json` 重新发现的成员 ID）重连收尾，不重启执行；证据不足继续保持 stop_unconfirmed。
- `stop_unconfirmed` 保存结构化 `stop_diagnostics`（Root、成员、检查清理及未覆盖名单／失败阶段的可得结果）；显式普通 `stop` 重试前重新读取任务与原生会话状态，已停的 Root 不重复打断，未停则按既有授权请求并等待真实确认。桥接不可用或证据不足时继续保留未确认状态，运行进程退出不等于宿主已停止。
- 时间和消耗预估是参考，不产生默认硬门。实际消耗不可得时记未知。用户明确的硬上限单独记录；停止后对比预估与实际并解释可得偏差。
- 不兼容旧 v2 命令、数据或门控。旧用户资料保留；旧运行代码、合同、解析器和模板已整体退役，不保留双轨。

1. 程序自主检查真实中间产物，独立模型从原始要求发现遗漏，现有 Root 修正，最终实际产物经独立复核通过。
2. 明确边界触发后，实际相关执行和后台动作停止，会话上下文保留；以真实会话和进程结果证明。

## 当前接入与记录接口

- 受控入口为 `orbit omp [OMP 原生参数]`：启动原版 OMP 并为该 Root 会话加载 Orbit 扩展，原生参数（`--resume`、`--model`、profile、权限等）与退出码透传。普通 `omp` 不接入 Orbit（安装切换见安装文档，切换完成前本机行为以实际安装为准）。命令面以安装版本的 `orbit --help` 为准。
- 扩展经 OMP 原生工具面（`xd://orbit`）提供 Orbit 操作；程序投递经原生 custom message（steer），标记不冒充用户输入。用户明确切换／分支／回退会话前收尾原任务，未确认停止则取消这次切换并保留原通道供重试；不自动创建、迁移或恢复 Root。
- `.orbit/tasks/<id>/` 保存原文、依据版本、明确修改、固定副本、检查结果、状态与权威成员清单 `members.json`。`complete` 表示独立检查及实际收尾均通过；`paused` / `needs_user` 表示已经确认停止；`stop_unconfirmed` 表示停止尚未得到确认；`failed` 仅表示运行错误，停止是否确认以 `stop_confirmation.confirmed` 为准。
- 独立检查者是另一只读 OMP 会话（独立进程，非成员），读取固定快照并复用 OMP 模型目录与凭据解析。候选池有可运行型号时优先在池内筛选：精确证据与启用的模型级先验同时进入新版任务适配判断，匹配真实校准放行才正向推荐；未放行或无可行动信号时按可运行候选顺序降级。池空或池内不可运行时由 Root 从当前 OMP 会话可用型号中选择，仍须隔离预检并保留 Jev 判断、缺精确证据／降级提示与实际型号记录；全无可运行型号才失败关闭。运行期间认证、额度或检查失败不当通过，检查结束后对尚未尝试型号作有界重选；已在途检查不切换。固定独立 checker／adjudicator 的隔离会话关闭该层的 SDK 默认 provider-error 自动重试（不涉底层传输自身能力、不表示任何错误都只调用一次）：此层的模型失败恢复由本条有界重选处理，避免同一型号在同一检查内嵌套重复同错误（历史真实样本以后按 reference 入档）；瞬态 provider 错误也会一次结束本次固定型号检查并交给既有重选，可能更早换型号——该 tradeoff 如实接受。仅作用于隔离 reviewer 会话，不改 Root／成员／全局设置，不放宽有效结果、身份核对、只读／完成／停止门。此前显式重选和检查失败阻塞的真实样本属于旧授权语义，缺证据池内降级有独立夹具真实终检与停止确认；本次 OpenRouter 接入不冒称安装版 `orbit omp` 已完成新的真实验收。裁定者模型仍由 OMP 配置决定并记录实际 provider/model。
- `start` 收到 Root 指定的检查型号时，在建任务目录前预检该型号属于当前 OMP 可用目录且隔离检查者可解析；不通过则拒绝并让 Root 从可用型号重新选择。预检只证明本地可尝试，不保证后续模型请求、额度或结构化输出成功。
- 受控任务在**实现之前**由程序给出一次工作单元引导：任务已受控且尚无工作单元时，程序在首个可扩展的 provider 请求载荷中注入一条 bootstrap 指引；同一请求内入口 advisory 若也合格，两条指引合并进同一次载荷注入；在该 provider 载荷路径上，各自只在合并注入成功后按任务去重，失败不标记成功并在下个可达窗口重试。bootstrap 只经该载荷送达；已 bound 的 `before_agent_start` 仍保留常规状态指引与既有入口 advisory 承载（advisory 保持其原有按任务去重行为），不再承载 bootstrap，同一请求的 system 与 payload 不重复送达同一句；不可扩展的载荷保持待发，不得记为已送达。同时记录一条事实：Root 首次明确 `write`／`edit`／`ast_edit` 之前的工作单元状态（`declared`／`none`／`unknown`）与真实 `tool_call_id`，只陈述观察、**不据此推断是否拒派**，也不以 shell 写命令替代该判定。该引导不依赖入口判断概率，因此显式请求与自动入口都一致；未受控任务与成员会话不注入。
- 受控 Main Root 的合作政策送达：程序对**本进程实际接管（owned）且仍活动**的受控 Main 会话，在**每个可达的 provider 请求**上，于与 OMP 原生 system／developer 指令**同层**处注入一条合作政策指引（可承载位置为 OpenAI Responses／Codex 的 `instructions`、Anthropic 顶层 `system`、messages 载荷中既有的 `system`／`developer` 原生消息文本末尾，以及 Responses `input` 中既有 developer 块的原生文本之后），同一请求内幂等、不落在用户消息尾，也不改写用户需求、原始要求或宿主基准规则。政策为**条件表达**：若原生默认以「仅 2+ 独立片段才委派／不委派单一片段」限制交接，则本受控任务适用有界交接规则——**有界单成员串行交接是正当交付形态**，Root 可先声明工作单元交 Jev two-stage 适配评估，再依据真实 hint 或带局限的 Root 选择用原生 `task` 派发；成员可承担实质实现，Root 保留规划、集成与核验。缺少可并行片段、共享接口或需等待依赖都不单独构成拒派理由；短小低收益任务可有据自行实现，质量与成本未知仍为未知；入口高 delegation 概率不是实际候选推荐。程序不代替 Root 派发、不增加用户批准、不扩大原生权限或目标规则、不强迫每个任务派成员。识别不到的载荷形状保持**未送达**：本次实现只静默跳过（既不注入、不落用户消息尾，也不新增通知或事实），因此不得描述成已主动告知 Root，也不以用户消息尾句冒充同层已解决；渠道事实按**本进程内「任务＋政策版本＋渠道」各记首次一次**（渠道、政策版本、真实任务／会话／型号与注入文本指纹），后续请求按请求幂等、不重复记录、不因此新增持久系统，也不保存原始请求体或凭据，也不据此声称服务端已收到或模型已遵循。该政策与上文单次 bootstrap 引导相互独立：bootstrap 仍只一次，政策按请求可达而复发，二者不互相冒充重复。

- **Root 阶段型号选择（已接线／确定性验证通过，真实模型路径未实测）——语义**：同一受控 Root 会话可在任务内自主选择阶段型号。既有 `orbit` 工具增加 Root 专用 `action=root-model`：`task`＝当前**本进程 owned 且活动**的任务目录、`root_model`＝**用户现有池且当前 OMP 可选**的精确 provider/id、`phase`＝`execution｜integration｜diagnosis`、`text`＝非空选择理由。工具可列出本次现有池∩可选精确 IDs 供 Root 选择；Root 的选择不是 Jev 新推荐。允许场景：有界实施交付后，对难靠程序验证的验收整合、已暴露漏检或困难诊断，按任务事实选择必要强模型承担；无此需要保留当前模型——只作必要阶段选择，不硬编码任何旗舰、不强制每次集成都升级，不改 Jev 题义／阈值／release。
- **Root 阶段型号选择——执行边界**：切换只经公开 ExtensionAPI `pi.setModel`（frozen OMP 18.3.4 源码证实：不写全局默认 model/thinking 配置；会写 native `model_change` 会话条目与使用统计、刷新模型相关工具提示／方言、重置 provider 会话与缓存键）。**保留本会话状态与相同权限边界**；conversation、async jobs、成员绑定与已记录结果不变。凭据可解析不等于调用、额度或质量成功，**实际身份以下一次 assistant 原生回执独立记录为准**；`phase` 是意图声明，不是模型能力测量，不追认既有调用。切换不清除失败、不追认旧调用、不等于完成或实际升级工作已发生；已实际派出的成员不随 Root 切换换型。
- **Root 阶段型号选择——记录与拒绝**：请求与拒绝只写到程序已核对 owned 的**当前任务** `collaboration.jsonl`（tool call、session、from/to、phase、reason、actual、error 等小记录，不含秘密值／原始 provider 载荷）；**不得把调用方传入的 foreign task 当日志目的地**——无可信任务绑定时拒绝由原生工具回执留证，不伪造 task 关联。SDK 报错记录分类／有界安全说明；SDK 在切换后抛错时记录**实际可观察到的当前型号**，不假装回滚或成功。之后调用按真实 boundary 身份＋Root 所声明 phase 记入现有 ledger，成员仍 `member_execution`，不跨模型合计。拒绝条件：原生错误／无 API key／未绑定／非本进程 owned／terminal／runtime 已停／目标不在现有可用池／同目标同阶段重复切换／同会话并发选择（简单拒绝）／在途独立检查或手动终检排队时（保留现有等待纪律，不新增等待或轮询）。切换失败不自动重试或回滚猜结果。
- **程序发起的 Root integration 阶段选择（源码已按更正接线／确定性验证通过，真实路径未测）——语义与边界**：真实缺陷经独立检查确认修复后，程序在**发送现有手动终检提醒之前**为该任务选择一次 integration 阶段型号（0.7.29 曾按「提醒唤醒后的下一回合」接线，installed OMP 18.3.4 源码证明该接缝不可达——direct 路径 `isStreaming` 在 hook 准备期恒 true、idle custom 唤醒不经过 `before_agent_start`；runtime 写序亦证明 send 时磁盘尚无所需 provenance；旧接线已由本次源码替换，本段为更正后的现行语义）；这是 §5.1/5.3/11.3 负收益路径调整的**待实测**决定（动机：0.7.26/0.7.28 两代 K3-Root 交付均出现质量负例，且 028 中 #6/#12/#13 旗舰 GPT checker 实际漏检 C1——问题不能归因低型号 checker，改由有执行能力的同 Root 阶段承担 full-spec 主动核验）。**触发时序（全部复用既有读侧与等待门，不新增轮询／定时／RPC／检查／停止状态）**：runtime 在 `remind_manual_final_check` 既有全部 会话身份／当前版本三元组（artifact_root, input_digest, artifact_digest）／非 stale 的 reviewer/artifact 自动检查 complete/continue＋delivery.ready=true／实际 `task_delivery` 三元组一致后，才在同一 custom message 发送前做选型；**每一份有效 按（task,input,root,artifact）一次，失败留证不自动重试，SDK 部分改变只记 actual-after 不假回滚；程序来源 trace 与 Root 工具 action 分开（tool_call_id=null，不伪造 Root 调用）；记录只称**配置已选择**，后续 native `actual_identity`＋`root_integration` `root-model` 仍优先，不自动回滚；并发 UI/异步选型的最后写者竞态如实存在、不作绝对互斥保证。**接线位点（SDK 已核，替换旧 before_agent_start 方案）**：宿主在既有 `send` RPC 分支识别 `integration_check` tag——tag 单独不授权，仍须全部核对（Main owned context、任务所有权、durable 当前 await 之后重新核对 binding／活动状态／用户选型／在途工作。普通 correction、finalization notice、member 消息不带 tag，行为零变化。**近期宿主观察（已实现，0.7.31 源码＋本修复）**：程序对过程检查（stuck/off_track）提供**有界近期真实事件序列**——最近 user 边界到最新 assistant 之间的真实 assistant/toolResult 事件按原生先后保留（窗口以真实观察计数，密集 custom/model-change 等非观察条目不占窗口槽），每条带 native 消息 id 与 status；超出窗口留真实 omission 计数标记。**边界**：最近 user 消息之前的事件不进入当前任务历史；无可信边界时不猜旧分支归属（空历史而非全部）；最新 assistant 仅含 toolCall 时当前 agent_message.text 为空，不以更早答复冒充交付。**不凭时间或无 diff 判卡**：单次错误/正常恢复/串行等待不构成卡点证据；unchanged observation 不重复付费（现有 dedup）。
**提醒内指引**：程序来源的全规格整合指引**追加在既有真实 custom 终检提醒消息内**（标明程序来源，非用户新要求）：说明实际 finding 与选择局限，要求 Root 在手动终检前主动按当前原始要求与规格核对整个交付、按风险做必要可执行验证并修复（不限先前 finding），保持 task_delivery／Root-verifications 完整归属；不预置样例、不强令额外验收项／固定型号、不宣称升级保证质量；既有 manual check／独立只读／完成／停止门全部保持。actual reminder／message_id 仅在既有真实 ACK 之后记录，不预写伪 accepted。**失败语义**：选型失败仍发送普通终检提醒（不因选型失败吞掉提醒）并留有界分类 trace、不重试；选型成功而 send 失败只证明**配置已选择**，不证明唤醒／真实调用／完成或收益，不回滚。
- `start` 亦可对已执行的原始要求中途接管：`--takeover-file` 传 `reason`（必填）与可选的 `prior_scope` 声明，并必须复用该要求的原生消息（`--message-id` 或最近的原生用户消息），`--prompt-file` 不能接管。接管块只保存 Root 的声明与程序真实采集的边界：原生消息 id、原文 sha256 与字节数、接管时存入该任务私有目录的 `WorkspaceSnapshot` 真实快照（摘要＋相对路径，首轮独立检查前原件再被编辑也不改变已存快照）、监督开始时刻；**不接受**调用方自报的摘要、快照路径或日期，快照捕获失败即不建任务。旧执行不被追认为受控，其用量／成员／检查不迁入本任务；接管失败不创建任务、也不声称已受控；未受控的在途资源与成员由 Root 自行收尾，Orbit 不追溯登记。自动入口在建立任务前若观察到该 Root 会话在当前原生消息之前已有程序可见的 assistant 工具调用（仅执行事实，引用或回复文字不算），按同一接管边界建立**当前新任务**：`prior_scope` 保持 unknown，理由说明关联范围未知、不追认此前执行为受控；没有此类工具调用的新任务仍按普通 `start`。同一会话中此前受控任务的记录不因此被改写或覆盖。接管建立后，Root 可经 `orbit takeover-scope` 只入队补交后来声明的 `prior_scope`：runtime 作为唯一状态写入者 append-only 记入 `prior_scope_declarations`（声明文本、理由、实际声明时间、来源为提交者声明，不冒充 native 用户消息或程序观察；检查者投影并列最近五项与省略计数），创建时的 `prior_scope` 不覆写，真实快照／摘要／原生消息／监督起点及输入版本、要求、成员、资源与终态不变；同内容重试不重复追加；非接管任务、已终态或坏载荷明确拒绝；该声明不追认旧执行，也不授予完成或覆盖资格。
- `status [TASK]` 默认显示可读摘要，`--json` 返回机器记录；摘要分开显示任务状态、执行协作、JEV、检查状态和下一动作。仅活动任务显示所安排下次检查的时间与依据；终态即使持久记录保留旧 `next_check_basis`，可读摘要也不得把该依据显示为仍待 Root 收尾／再检查。记录中存在 `completion_invalidation` 时，摘要必须显式给出「完成复核未通过」的原因码与说明，并说明该次停止只是普通停止、`stop_reason` 不代表交付已通过独立终检，避免把被否的完成读成已验收。`doctor` 不调用模型；`update`/`uninstall` 只维护所属运行安装，维护应在相关任务结束后执行。

## 本地任务证据与主动导出

已启动任务在 `.orbit/tasks/<id>/` 持续保留运行程序的 `events.jsonl`、权威成员记录及检查证据；原生 OMP 协作由扩展按任务持久记录在 `collaboration.jsonl`，不只依赖有界进程缓冲。记录实际可观测的派发输入、时间、模型身份及来源、成员通信、检查触发及结果、finding、纠偏投递与停止。Root 自主派发不以补写理由为门槛；明确理由若不可得则记未记录，Jev 的建议及实际派发分别记录，不能从相邻时间推断建议即动机。证据丢失、截断或无法归属必须显式标注，旧任务和异常退出不能伪装完整。
`orbit session-summary --thread ID [--project DIR]` 从本机当前项目中具有相同原生 OMP 会话 ID 的任务文件生成只读汇总，不跨项目或写入任务。区分检查总数、过期／失败／手动检查、Jev 调用、成员、纠偏和 finding；旧任务缺失 `collaboration.jsonl`／`events.jsonl` 显式列为缺失，不补造事件。仅对可归属的检查者 token 汇总已知值，存在未知时总用量与金额仍为未知；不把订阅额度折算成价格。

`orbit export TASK --output FILE` 由用户主动生成本地单任务证据包：原始任务记录、事实时间线、相关检查快照与可安全归属的原生会话材料；不可取得的部分进入缺失清单。运行中的导出标明截取时间和在途状态，不影响任务或完成门。导出不上传、不调用模型、不判定任务或 Orbit 的产品缺陷；开发者收到用户自愿交付的材料后才另行分析。现行独立检查者仍只检查固定产物快照，不读取 `.orbit` 来替代交付终检。
