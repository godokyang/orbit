# Orbit 开发协作流程

> 目标：高质量完成当前授权任务，减少用户被迫纠偏、完整交付耗时和供应商额度浪费。
> 适用对象：开发、评估和维护 Orbit 的 Agent。本文不描述 Orbit 产品运行时已经具备的能力，也不要求开发者先通过 Orbit 自举执行任务。

本文的主执行 Agent（Root）指当前负责用户整项任务的 Coding Agent，通常就是正在阅读本文的你；这个名称不要求另建会话或预先配置团队。

## 1. 明确当前交付与授权

开始前核对用户目标、阶段、范围、完成条件和已有决定。研究、设计、最小验证、实现、发布是不同授权；得到一个技术答案不自动进入下一阶段。状态追问不改变主线，明确暂停、取消或修改要求则及时落实。

先读根 [AGENTS.md](../../AGENTS.md)、[文档索引](../README.md)与[当前交接](../plan/handoff.md)。涉及产品语义时回到 `contracts/task-runtime.md` 和 ADR-007；涉及现有实现时先查代码与[欠账](../plan/debt-ledger.md)。不只凭需求标题或 Root 的摘要确定业务含义。

实现前冻结用户可观察的完成条件，区分代码实现、真实可用性、提交与发布。环境受阻不能自行降低约定验收，也不不断增加新证明要求。普通工程选择在已有授权内处理，只向用户提出真正影响目标、产品语义、权限或风险的未决问题。

方案评估和短任务由 Root 直接完成，不默认派发，不为仪式创建 TODO、Goal 或人工确认门。预计超过三十分钟的实现任务，由 Root 在 `docs/plan/` 维护一份总 TODO，记录目标、非目标、验收、依赖、状态和本次可用供应商；取得执行授权后，如用户已要求 Goal 则激活可用 Goal 能力。没有该能力如实说明，不伪称已启动；不得因补工具状态停止已授权的可执行工作。

是否采用长期 Goal 可在任务开始时一次确定，既有授权不反复确认。用户尚在讨论时不启动实现 Goal。TODO 不堆积日志，复杂接缝确需说明时再建实施文档；不要为每个小任务造整套材料。

## 2. 按收益使用协作

Root 负责整体方向、依赖、资源、验收与用户沟通，也可以亲自实现。方案评估默认使用当前 Root 的判断能力；只有用户要求协作评估时才派发。实现阶段仅在工作可独立交付、能缩短关键路径或需要实质独立核查时使用成员，不以空闲席位数量决定分工。

每条完整行为有一个主要执行者。不要按按钮、路由、后端方法和测试文件机械拆票；研究型任务可以交付足以改变决策的事实，不要求靠代码差异证明进展。

使用用户声明并已授权的工具和供应商池；能力、近期实际表现、上下文负担、核验与返工成本共同决定分配，不固定供应商等级。未知额度标为未知；token、费用与套餐用量按实际单位记录，不从时间推算虚假费用。不可用时不反复尝试，不自动购买额度、启用新模型或换成其他协作通道。

在用户指定的 Herdr 环境内，通过当前安装的 Herdr skill 与 CLI 发现、复用或创建执行成员。先验证 `HERDR_ENV=1` 并读取 live 状态；不凭 pane 名、历史 roster 或窗口存在判断可用。只给确认空闲的成员新任务；working、blocked、unknown 先核查。不得默认改用 Codex 内部子 Agent。

不在 Herdr 中则继续可独立完成的工作；缺少已约定的必要协作能力时报告具体缺口，不擅自控制另一会话或假装独立评审完成。不另写各家终端的回车、ACK、屏幕解析协议。

## 3. 派发必须传递有效规则

派发时给出八项：目标、模式、依赖、允许修改范围、占用资源、完成条件、明确不做、失败停止条件。模式可用实现、沿指定路径验证并修复、只读验证或环境准备；只读任务不得顺手修代码。

明确要求成员读取本仓根 `AGENTS.md` 与本文；涉及合同、UI 或其他专项材料时，只带本票相关来源。用项目绝对路径避免跨 workspace 误读。另直接携带当前关键限制与已确认事实，不能假设各供应商自动加载所有仓库规则。

参考派发正文如下，按任务缩短，不让成员复述阅读 ACK：

```text
项目：<绝对路径>。先读 AGENTS.md、docs/agents/development-workflow.md 及 <本票必要来源>。
目标：...；模式：...；依赖：...；允许修改：...；占用资源：...。
完成条件：...；不做：...；停止条件：...。
当前有效决定：<本票相关授权、纠正、版本与已完成人工前置>。
只做本票，不改总 TODO，不提交推送，不扩大验收或权限。问题先报 Root。
结束必须回报结果、产物、实际验证和剩余项；详细日志留本会话。
```

Root 检查回执与实际产物，不把“任务已发送”“仍在运行”“成员说完成”当成交付事实。状态不明或回报缺失时先补取已有结果，核查阻断或退出原因，不盲目重发同一任务。成员不能自行继续派发下一轮。

## 4. 实现、并发与接管

新增实现前查已有代码和成熟能力；选择满足本次需求且可维护的简单路径。未知未来需求不作为抽象依据，不重写成熟组件以替代必要接线。无关缺陷只记录影响与建议，等待扩大范围的授权。

并发要求依赖就绪、产物独立、文件和运行资源不冲突。并行写任务按需要使用从明确基线创建的独立 worktree；串行和只读任务不为形式新建工作区。热点与生成入口一次只归一个执行者，worktree 不能消除语义依赖。

Root 在解释、交接与返工成本已高于亲自处理时，可有界接管。先确认原写者停止并释放资源，保留已有成果，再接管具体难点；整体监督仍由 Root 负责。被 Root 实现的高风险或跨模块行为同样需要适当的独立核查，不能自己给自己作唯一通过依据。

共享环境有明确 owner，成员消费同一有效版本，不各自 rebuild/reset/清理。进程在同一 Herdr workspace 的新 tab 运行，不在 Coding Agent tab 增加 pane。启动者记录目录、入口、PID/进程组、端口及停止方法，不记录凭据。

## 5. 途中判断与纠正

在首个代表性产物、依赖改变、重复失败、成员问题和完成请求等节点核对目标。重要实现任务的路线或完成判断需要独立检查时，评审者直接读原始要求、当前约束和实际产物，不能只沿 Root 的票面寻找一致证据。不用固定多席，也不靠票数决定事实。

普通耗时提醒不自动判失败、换人或增加模型调用。本开发流程依赖 Root 使用现有工具作判断；Orbit 产品中的按任务观察与控制按现行合同单独验证，不把开发协作纪律当成运行事实。

发现明确违反已确认边界的行为，暂停受影响动作；不相关工作继续。低效疑点先说明新证据和下一步要关闭的缺口，Root 决定继续、补输入或接管。满足约束的偏好分歧由 Root 取舍，不扩大成验收阻断。

一般难点不按统一次数换人：有新事实且有明确验证路径时继续；缺上下文或环境先补前置；同一错误反复出现且无有效进展时停止加码，回到需求与设计方向。用户授权预算、明确停止条件及具体环境的一次标准恢复边界仍须遵守；相同阻断不得靠改名、换人或恢复会话重置累计投入。

用户纠正后更新当前任务事实，通知受影响成员，并核查下一次动作和产物是否符合修正。口头同意和消息已发都不算落实。恢复或交接时读当前 TODO、diff、关键验证和未解除阻断；复用仍有效的人工前置，过期时给出具体依据，不重复盲问。

## 6. 验证与评审

测试取舍遵守根 AGENTS.md。先运行与改动有关的已有测试，再为核心用户行为和真实回归风险补必要覆盖；不为可逆的文档与小修复机械新增测试。动态数据属于一次性审计或集成验证，不固化为稳定单测。不能为了通过而改业务规则、伪造运行证据或弱化验收。

评审核对两个方面：符合本仓当前规范，以及完成用户要求（包含是否做多了）。先独立看原文和产物，再读作者解释。结论指出位置、证据和影响；可验证事实由证据裁定，普通技术偏好由 Root 决定，真正产品或授权冲突交用户。

先冻结评审对象与完成条件。修复后只复核原问题、直接影响和新增变化，已有有效结论复用，不因“最终评审”重开全量检查。反复不闭合时重新判断方向，不能靠叠加测试或 reviewer 制造收敛。

验证结果分别说明静态检查、模拟/脚本化测试和真实 Agent／用户路径实际证明了什么。确定性 fixture 通过不等于模型能自我纠偏。使用外部模型前核对现有授权、材料与资源边界，未知权限不推断，已获授权不重复询问。

## 7. 完成与收尾

按冻结条件核对实现、组合后的行为及约定的真实验收；子任务完成不等于总任务完成。提交、推送和部署分别报告，不用它们替代质量验收。

Root 维护任务进度，成员不提交或推送。用户未禁止时，已核验完整片段可以建立本地 checkpoint；推送、发布、部署只在明确授权内执行。本地 checkpoint 不能夹带他人改动。

所有任务都检查本次资源：确认成果已保存或集成，停止不再使用的自有进程并核对派生进程与监听端口，随后清理无用的临时目录、worktree、分支、日志和缓存。共享、仍有证据价值或归属不明的内容保留并说明；不按通用进程名杀进程，不批量清空临时目录，不清库。

恢复仍有价值的材料不因任务结束机械删除。任务完成后，长期决定进入 ADR／合同，实际验证与有用经验进入 `docs/reference/`，当前状态进入 `docs/plan/`。已被这些正文吸收的工单、重复快照和过期指南从当前目录删除，通过 Git 查阅历史；删除时同步修正引用，不建立另一套归档副本。实际完成且必要收尾结束后才更新 Goal 完成状态。

最终回复说明结果、实际验证、未完成项及有意保留的资源。不要向用户倾倒日志。必要时用已有记录简短复盘人工纠偏、返工、等待和可得供应商消耗，不另建常驻统计项目。

## 8. 规则来源与产品边界

本流程已吸收外部项目中适用的工程方法，规则只在本文件及 Orbit 根 AGENTS.md 维护。外部参考资料不是阅读本流程的前置条件，不自动同步或取得裁定权。发现矛盾时按用户明确决定和本仓适用规则处理，不要求开发者同时满足两套项目流程。

本文不改变 Orbit 产品的现行任务运行合同。修改产品语义必须明确更新相应 ADR／合同并验证，也不自动要求把“开发 Orbit”作为一个 Orbit 产品任务运行。
