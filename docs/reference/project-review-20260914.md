2026-09-14，用户要求补齐 Root 创建执行 Agent 的规则，并检查项目中其他不妥之处。由当前 Root 直接检查。范围包括 skill 与全部角色规则、公开文档和合同、CLI、任务记录、运行循环、原生连接、检查进程、快照、安装与版本脚本，以及现有验证入口。没有调用付费模型，没有操作真实执行成员。

## 已修正的说明与规则

- Root 创建和复用执行成员的权限来自已有工具与授权；派发、资源协调、实际结果核验和收尾有明确归属。执行成员不得自行扩张职责；只读检查角色不创建执行团队或递归启动 Orbit。
- skill 按需引导到协作说明。用户指定 Herdr 时加载当前 Herdr skill；目录未提供时按本机 CLI 获取说明，不要求目标项目具备本仓开发流程。Herdr 仍是可选工具。
- Herdr 创建命令需要已有可用 shell pane；说明覆盖先发现成员、按需准备 pane、启动、派发和核验。本机帮助及 live 状态已核对，没有为验证文档新开 Agent。
- 专项规则中八处失效的共用职责路径改为真实相对链接；可选项目模板同步使用 tasks/shared 目录布局。
- 测试规则明确禁止伪造通过，不禁止正常修复生产代码；定向修复不强制每次新增永久测试。开发流程不再无条件要求在 Herdr 新建 tab。
- `start` 返回 `starting` 与运行程序实际接入区分说明；模型建议移除依赖旧会话背景的评审成员描述。

## 已复现的运行问题

后续状态：用户授权跑通完整流程后，以下两项已修复并通过相关确定性测试；保留原始复现用于说明风险。日常接入和全任务停止仍单独验收。

### 1. 停止后，同一批队列仍会投递修改指令

位置：`lib/orbit/task_runtime.rb` 的 `consume_commands`，以及 `lib/orbit/task_record.rb` 的 `commands`。

触发：运行程序读取队列前，先后入队 `stop` 和 `amend`。停止分支将状态写成 `paused`，但队列遍历继续执行 `amend` 的 `send_message`。原生连接对空闲会话使用 `turn/start`，因此可能重新唤起已经停止的 Root，而任务记录仍为暂停。

本地复现复用 `tests/task_runtime_test.rb` 的 `fixture`：依次执行 `record.submit('stop', ...)`、`record.submit('amend', ...)`，再调用一次 `runtime.tick`。观察结果为 `task_status=paused, stop_calls=1, messages_after_stop=1, host_status=active`。这是确定性模拟验证，不是对真实会话的停止实验。

建议优先修复：任务进入终态后，不再处理该批队列的后续执行指令；对未处理命令明确记录处理结果。用这条已复现路径验证停止后不会再次投递或启动执行。

### 2. 无 Git 项目会把依赖目录纳入快照

位置：`lib/orbit/workspace_snapshot.rb` 的 `walk_directory`。无 Git 路径只排除 `.git` 与 `.orbit`，不会排除生成依赖；Git 路径则依赖项目忽略规则。

本地临时目录无 `.git`，仅放入 `node_modules/example/index.js`，调用 `WorkspaceSnapshot.capture` 后，该文件实际出现在快照 manifest 中。临时目录随后已清理。

影响：无 Git 项目安装依赖后，采集和检查可能包含大量无关文件，不符合 ADR 所述排除无关生成依赖的范围，也增加耗时与输入负担。

建议明确并实现最小的生成依赖排除规则，并保留用户明确指定依据文件的现有独立读取方式；不扩展为全语言目录分类平台。
