# Orbit 工程经验

本页提取自旧 Alpha 问题、测试失控事故及重构挑战记录，保留值得防止再次发生的错误。它不新增产品门控、测试配额或验收任务；当前规则以 [开发规范](../../AGENTS.md)、[开发流程](../agents/development-workflow.md) 和 [ADR-007](../adr/007-task-runtime-refactor.md) 为准。

| 已遇到的问题 | 应保留的教训 |
| --- | --- |
| 修复链、测试数量或审核轮次不断增长，原始需求被挤掉 | 冻结当前交付，先验证高价值行为；复审只处理原问题和实际新增变化，不为覆盖率与理论风险扩大任务 |
| 动态数据或一次性核验结果被固化成永久单测 | 分清稳定行为测试与当次数据审计；不能为让测试通过改变业务规则 |
| 多个检查者都沿用 Root 的残缺摘要，或者只检查旧提交 | 独立性首先来自完整原文和实际版本；未提交修改、新文件和删除必须进入检查对象 |
| 用方法名、pane 标识、自填凭证或模拟服务证明“已经接入” | 在真实工具上验证原文读取、事件和控制；消息提交、执行结束、后台进程退出分别核实 |
| 旧版本的问题在 Root 修正后仍被用来阻断 | 应用结论前核对实际产物与输入；检查使用固定副本，验证命令也要考虑共享资源和外部副作用 |
| 工程偏好被提升为必须修复，复审无法结束 | 问题应指向具体需求、证据与影响；真实争议可以独立裁定并撤销误报，偏好不阻断交付 |
| 测试绿色被当成真实效果，或者只统计执行者而忽略检查成本 | 分开说明程序行为和真实模型实验；以交付、返工、检查和人工介入的整体投入评价结果 |
| 为保留旧设计继续增加合同、迁移层和操作表单 | 删除已淘汰的路径，保留现在需要的职责；历史在 Git 中查阅，不让已完成工单重新进入执行队列 |

## 本次重构补充的事实

真实试跑发现一次多余检查：已有交付检查后，“首次变化”触发仍生效，导致修正期间再次检查。已修正触发条件，并用已有确定性测试验证，未为此重复消耗模型额度。详见 [验收记录](orbit-runtime-acceptance-20260914.md)。

专用环境中的纠偏和停止通过，仍不能证明普通终端 Agent 已可接管，也不能证明复杂任务普遍节省额度。整次任务用量不可得时保留未知，Root 历史累计量不能冒充本任务总量，缓存 tokens 不重复相加。
