## 切片 A：过期原因、调度收敛与自动投递

### 既有任务复盘（`.orbit/tasks/faf2e5d2…`）

- 7 次已完成检查全部过期、纠正投递 0；检查用量 4,246,313 tokens。检查者自设 `next_check_seconds` 为 30–60 秒；7 次检查开始时间相对前一次结束只隔 31–78 秒，单次检查耗时 47 秒–3 分 35 秒，Root 全程持续编辑。
- 只读复盘可确定：检查 1 的产物 digest 到检查 2 开始时未变，输入与争议也未变，但 `host_digest` 每次开始都不同，因此检查 1 的过期来自宿主执行状态变化；检查 2 期间有一次输入修改（03:01:59 明确修改），c2→c3 起产物开始变化。旧记录不区分过期原因，其余检查无法逐项归因。

### 实现要点

- `finish_check` 按产物、输入、宿主、争议分别记录 `stale_reasons`；Root 正在执行时，检查者建议的下次观察时间不会让完整检查早于 `review.interval_seconds`（约定间隔下限）；Root 空闲、用户请求、明确修改和 Root 交付仍按原语义触发。
- 过期检查中 `correct`/`continue` 的 findings 作为待核对线索保存在 `state.recheck`，内容含完整 finding；下一次**审查者**完整检查在 prompt 的 “Pending clues” 段收到线索，被要求明确确认（进入 findings，复用 id）或撤销（进入 `resolved_ids`）。未提及的线索保留；确认后按普通纠正自动送达 Root。过程检查不接收、不核对产物线索。
- `orbit status` 显示最近检查的过期原因、开放问题与待核对线索数量、下次检查时间及依据（`next_check_basis`）。

### 确定性验证

`tests/task_runtime_test.rb` 新增：过期纠正不送达旧版本、线索随下一次检查送达且被撤销/确认分别处理、Root 执行时的约定间隔下限、Root 空闲时仍按检查者建议、过程检查不接收也不清除产物线索；另有 Jev 输入预算与省略范围断言。完整 `npm test`（17 项）通过。

## 切片 B：Jev 输入与真实判断

- 输入边界：修改按字符预算保留最新部分，超出时写入 `amendments_omitted`（省略数量与保留范围），并明确“缺少更早依据不构成偏题证据”。确定性用例覆盖 30 条长修改下的保留范围。
- 真实 Jev：三个任务均使用已配置 key，`jev_assessed` 事件与 `state.jev` 可核对，包含 model、三项 scores 与用量。观察到的 scores 均为低值（例如本仓任务 0.15/0.33/0.29），三个任务共 47 次调用，未触发任何过程检查；没有观察到 Jev 减少无效完整检查（完整检查实际由约定间隔、交付和用户请求驱动）。
- 额外消耗：每次调用约 2.4–2.7k 输入 tokens + 55 输出 tokens；持续编辑时因观察变化，调用间隔可缩短到约 20 秒。服务失败回退只由确定性用例覆盖，本次未制造真实 TypeSafe 故障。
- 结论（事实陈述）：已配置 key 的新任务可用 Jev 并留下可核对判断；本次样本中没有观察到过程检查增益或完整检查减少，额外消耗可量化。默认启用仍按用户决定保留，未据审查建议改关闭。

## 切片 C：Herdr 非 Codex 成员路径核对（达到停止条件）

- 在 Herdr 工作区新建 pane，`herdr agent start controlled --kind opencode` 成功；成员完成真实工作（运行项目测试并把确切输出与后台服务 PID 写入 `member-report.txt`），结果经文件读取，未依赖屏幕解析。
- 中断与停止：`agent send-keys esc` 后 4 秒成员仍为 working，前台循环进程仍在推进；`send-keys ctrl+c` 使成员进程退出（Herdr 报 `agent_not_found`）且前台 shell 树消失，但成员先前启动的 `python3 -m http.server 8765`（PID 57243）继续存活；执行 `pane close` 后该后台进程仍然存活。
