# 任务运行重构验收（2026-09-14）

依据：ADR-007、`contracts/task-runtime.md` 与当前执行 TODO。这里记录实验事实，不签发产品语义。

## 冻结范围

- 仅使用本次已授权的 Codex / `gpt-6-astra`，不换供应商，不访问 Zeen。
- 使用临时项目和专用 `codex app-server` Unix socket；当前开发 Root 与三位 Herdr 成员保持原会话。测试先建立独立的夹具会话，再由 Orbit 接入该已有会话，不将新建 Root 写入产品入口。
- 预估两条真实路径共 5–15 分钟；token/费用预估未知。时间是参考，只有路径 B 明确设置的截止时间是停止边界。
- A：预置 greeter 仅支持普通姓名，原始指令同时要求空白姓名输出 `Hello, stranger!`。测试用开发指令只控制初始时序：Root 首轮保留中间产物并等后续消息，不主动申请检查；不把遗漏答案提示给检查者。独立检查必须自行读取原文和实际文件发现遗漏，Orbit 投递后 Root 修正，最终独立检查对应真实产物。
- B：在另一夹具会话启动可观测心跳执行。确认执行正在发生后给 Orbit 明确截止时间；核对实际中断、后台登记清空、心跳停止和同一会话上下文保留。
- 确定性测试与真实模型结果分开记录；不增加第三条必需真实实验，不把通过两条路径说成普遍节省额度。

## 接入事实

- 本机 Codex `0.154.0`。普通 embedded TUI 没有外部即时控制端点；SQLite 持久队列不能替代中途停止。
- 真实 socket 探测否定了初稿“Unix 上直接 NDJSON”的假设：原生端点实际通过 WebSocket 握手。官方源码见 [`unix_socket.rs`](https://github.com/openai/codex/blob/rust-v0.154.0/codex-rs/app-server-transport/src/transport/unix_socket.rs)。传输改为复用 [`ws` 的 IPC 能力](https://github.com/websockets/ws/blob/master/doc/ws.md#ipc-connections)，Ruby 端只处理 JSON-RPC；不手写 WebSocket 帧协议。
- 真实握手已通过。原生分页历史拒绝 ephemeral 会话，也拒绝尚无首条用户消息、未物化的线程；夹具使用已收到原始用户指令的普通持久会话。产品应如实报告这些能力限制。

## 结果

两条路径均通过。下列时间为 UTC；原生结果、最终任务状态、检查结果及用量保存在 [选取的原始记录](orbit-runtime-acceptance-20260914.evidence.json)。实验使用本次临时夹具，不涉及用户业务代码。

### A：遗漏被发现、修正并复核

- 绑定已有会话 `01a09bb8-0c7a-7863-984c-8b5cc8fb0f27`，原始消息标识 `acceptance-original`；任务 `422bbccc-9ee0-4817-9890-2328bf03b09d`。
- Orbit 从 17:13:19 运行至 17:14:55，耗时 96.36 秒。程序自主触发第一次检查，独立模型实际运行 Ruby，发现空白姓名返回 `Hello, !`，提出 `blank-name-fallback`；检查者没有收到预置遗漏答案。
- Orbit 向同一 Root 投递纠正；Root 对空白姓名使用 `stranger`，未新增依赖或功能。第二次检查期间 Root 状态变化，程序将结论记为过期，没有据此完成任务。第三次独立检查在 Root 已结束执行后通过，问题关闭、后台登记为空。
- 最终实际产物版本为 `sha256:09064c62d50432d851cf939512abe1b6cbbfec036f260dba0ddbb6df66883995`，任务为 `complete`。开发 Root 另外直接执行普通、空字符串、纯空白三种输入，得到 `REAL_GREETER_VERIFICATION_PASS`。

### 验证与范围

- `npm test` 通过：快照 5 个行为测试、运行循环 2 个行为测试、原生连接 3 个行为测试；安装脚本语法检查一并通过。快照含未提交修改、新增、删除、权限和链接；循环含过期结论失效、独立撤销误报、无事件等待与停止未确认。
- 新测试及协议夹具共约 818 行，超过仓库 300 行建议：实际 WebSocket 服务夹具与三个原生交互行为占主要篇幅，另外覆盖冻结验收所需的版本和停止语义。未为覆盖率追加极端输入或旧协议矩阵；这些确定性检查不能替代上述真实模型实验。
- 安装／卸载在临时目录验证，包括带空格的相对路径、从项目外调用、保留用户额外文件和拒绝未知目录；另由协作 Agent 独立复核。Skill 官方校验通过。
- 只证明已绑定 Root 的原生当前执行、登记后台进程和 Orbit 自有检查进程。没有证明能接管任意已打开 TUI，或停止其他供应商 Agent、脱管 daemon。

### 时间、额度与一次纠偏

两条运行本身合计约 111 秒；从 A 开始到 B 结束约 5 分钟，位于实验预估 5–15 分钟下沿。这不包含此前接口探测、夹具准备及开发收尾，不把它当作整次研发耗时。

A 的三次独立检查共报告 input 263,565、其中 cached input 194,816、output 1,089 tokens。缓存量包含在 input 中，不能重复相加，也不等同于套餐扣费。A 夹具 Root 会话累计 totalTokens 129,179；一般任务沿用已有会话时会混入之前工作，所以产品不把会话累计量当作本任务总量。其他供应商完整计费未知。

真实轨迹暴露了一次可避免检查：首轮已由交付事件触发，但“首次产物变化”标记尚未关闭，修正时又触发检查。已改成任一首次检查都会关闭此触发，并在已有确定性行为测试中验证修正进行时不再重复触发。没有为此重新消耗真实模型额度；两条真实路径证明的是核心纠偏和停止，触发修正由确定性测试补证。尚不能声称已经证明普遍节约额度。
