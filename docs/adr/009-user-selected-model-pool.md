# ADR-009：由用户确认候选模型，Orbit 按当前 OMP 会话推荐分工

- 状态：**设计已确认，实现完成并已通过真实验收**（2026-09-25；完整证据见[证据记录](../reference/model-pool-acceptance-20260925.md)）。候选池、会话交集、质量／端到端时间／粗档费用选模、显式优先与失败阻塞规则已随源码落地并有确定性测试。真实验收样本：显式不可用检查者结构化失败→同任务显式重选→任务 `complete`+停止确认（`193ad1dd`）；原生 GLM 成员→真实检查者 finding F1→根因修复→`resolved_ids` 闭合→停止确认（`3dc116a4`）；生成 GLM 成员被覆盖为 Grok 时成员模型漂移被检测、记录并中止、拒绝交付，且成员与任务双层停止确认（`bfcc270a`，release `6f808e8d…`）。**Live 边界：**无显式检查者模型且池非空时，本轮真实尝试在任务开始前被正确 fail-closed 拒绝、未建任务（live start 只记录质量线拒绝，未落分数）；另作诊断 JEV 调用得 GLM 0.27、Grok 0.04（均 < 0.55），改动证据后的本地 GLM 检查指标为 0.42。池内自动**正**选择仅由确定性选模测试覆盖，未取得 live 正样本。历史漂移失败尝试保留为回归历史。本文只声明本 ADR 范围内的选模实现与验收；现行运行事实以[任务运行合同](../../contracts/task-runtime.md)和[ADR-008](008-omp-native-collaboration-base.md)为准，进度见[模型候选池交付 TODO](../plan/model-pool-delivery.md)。
- 范围：OMP 单宿主内的模型发现、候选池、执行成员推荐与独立检查者选模。Root 仍显式调用原生 `task` 派发成员；Orbit 不改 OMP、不自动派发、不增加第二层成员。
- 依据：用户逐项确认的 Q1–Q22 决定；OMP 18.2.8 的[扩展接口](https://github.com/can1357/oh-my-pi/blob/v18.2.8/docs/extensions.md)、[Agent 发现与模型优先级](https://github.com/can1357/oh-my-pi/blob/v18.2.8/docs/task-agent-discovery.md)及[原生 task 行为](https://github.com/can1357/oh-my-pi/blob/v18.2.8/docs/tools/task.md)。

## 问题与目标

当前 Orbit 只比较 Root 模型和 OMP `@task` 的默认模型，没有枚举当前会话可选模型。登录账号、自定义 provider、环境凭据和 OMP 配置都可能改变实际可选范围；直接读登录记录既不完整，也不能证明模型可调用。单一默认候选还可能与 Root 使用同一模型，无法给出有价值的多模型分工建议。

目标是让用户先从**当前 `orbit omp` 会话可选列表**中确认少量候选；Orbit 此后只在这些候选内，为写代码成员和独立检查者选择具体模型。建议要体现任务质量、端到端完成时间和粗档费用，且不把可选列表误称为额度、网络或模型请求已经验证通过。


## 2026-09-27 最终裁决：OMP 可用模型不再逐型号授权

用户明确撤销原先的逐型号原生消息授权门：Orbit 是 OMP 扩展，使用 OMP 当前会话可用的模型与同一套配置／凭据解析；候选池只是优先筛选范围，不是权限名单。池内有隔离检查者可运行型号时先由 Jev 判断当前任务适配性，正向信号优先、低分与未知证据按现行降级规则排序；池空或无可运行池内型号时由 Root 从 OMP 可用型号选择，并经过相同的隔离可用性核对与 Jev 评估。成员由 Root 显式派发，Jev 的成员分工收益判断继续仅给建议；通用 `@task` 的精确有效 OMP 模型不因池外而被拒，实际模型漂移仍中止。

此前 §1／§4／§2026-09-27 补充裁决中的 `Orbit authorization: member_model=…`、`review_model=…` 与 `review_model_session=…`、会话选模记忆及池外阻断规则不再生效，不保留兼容授权渠道。Root 选模是工具操作而非模拟用户消息；模型和理由仍留任务证据。独立检查者复用 OMP 模型目录与认证解析，但仍在独立只读进程／profile 核对实际型号；登录可选不等于请求成功。检查失败留证后在尚未尝试的可运行型号中按 Jev 次序有界重试，不在途换模，不把失败当终检；全部失败才阻断并告知实际原因。精确事实缺失不阻断可运行型号，也不编造评分。下列旧条款仅保留历史决策背景，现行语义以本节和任务运行合同为准。
## 决定

### 1. `/orbit-models` 与长期候选池

- 在 `orbit omp` 的交互 TUI 中，裸 `/orbit-models` 打开可搜索的多选界面：按 `provider/id` 过滤、↑/↓ 移动、Space 勾选、Enter 一次保存净增删、Esc 取消不写。可选列表来自当时的 `ctx.models.list()`；单列显示池内但本会话不可选的旧标识，允许移出、不可新增。列表不声明模型已验证可调用或有额度。无交互 UI 时裸命令仍显示文字列表，原有逐项 `add/remove` 命令保留。
- 批量保存按打开时池快照计算净差量，提交前重读本会话可选列表；待新增不可选则拒绝，要求刷新。在同一跨进程锁下，对本次要改的 ID 比较当前池与快照：同 ID 已改变则拒绝并提示刷新，其他 ID 的并发变化保留。无净变化不写入；失败留在界面供重试，不切换 Root 或在途成员模型。
- 候选池长期保存，所有 Orbit 会话共用；仅保存模型标识和必要的格式版本，不保存凭据、账号资料或模型连接配置。持久写入原子化，多个会话修改不能静默覆盖彼此。
- 每个会话在需要推荐或准备新派发、新检查时，以**长期候选池 ∩ 该会话当时的 `ctx.models.list()`** 为候选；池内旧标识不会自动替换为新版本。池变化只影响后续动作，在途成员或检查不切换模型。
- 候选池为空时，不给执行成员模型建议；受控任务中的通用原生 `task` 默认仍受下述池内模型门约束，只有用户在原生消息中精确授权池外型号才例外。独立检查继续沿用当前会话默认模型。候选池非空时，检查者必须在池与本会话目录交集内选**隔离环境可运行**的型号；任务适配分或证据缺失不再阻止启动，只会影响排序并形成降级提示。若无任何可运行池内型号，才拒绝选模，不擅自用池外默认、不跳过独立检查。
- 用户在原生消息中精确指定模型时，以核实过的该选择优先。池外选择附提示、不自动扩充候选池；Root 工具参数不构成用户授权。Root 当前模型是比较基准，不要求入池。

`ctx.models.list()` 表示 OMP 在当前会话认为已配置凭据、可选择的模型；它不是逐模型的付费连通性测试。Orbit 不遍历登录数据库，不为列表中的每个模型发送探测请求。列表或凭据改变时重新计算交集。

### 2. 原生执行成员的模型映射

OMP 原生 `task` 指定的是 Agent 名称，没有按次直接传入模型 ID 的字段。因此 Orbit 为本会话的合格候选生成**会话隔离的 OMP Agent 定义**：每个可派发名称映射一个明确的 `provider/id`，用原生 `task/hub` 运行，成员不能继续派发。生成物不写入项目 `.omp/agents` 或用户全局 Agent 目录，不修改原版 OMP。

Orbit 向 Root 推荐“有界子任务 + 成员角色名 + 具体模型”，并给首选和少量备选、质量/时间/费用理由。Root 仍决定是否派发以及交接内容；受控任务的通用原生派发不得绕过池内模型门。若候选模型与 Root 的实际模型相同，不把它当作自动多 Agent 执行建议；池内自主派发仍可登记，池外须真实用户精确授权。

OMP 会在执行原生 `task` 时重新发现 Agent 定义，但任务描述可能较早缓存；其模型优先级还允许 `task.agentModelOverrides` 高于 Agent 文件。实现必须在本仓实际 `orbit omp --extension` 启动路径中验证动态定义可被发现，且在成员首次模型工作前核对最终模型与用户选择一致。配置覆盖、认证回退或不可用选择导致模型漂移时，不得把另一个模型当成已获授权的候选悄悄运行；要记录失败并交 Root 重新选择。若原版 OMP 当前接缝无法保证这一点，先明确具体缺口，再依据 ADR-008 的上游策略裁决，不能把未经验证的动态映射写成已支持。

### 3. 推荐依据与 JEV 边界

JEV 仍先判断当前是否有边界清晰、值得并行的子任务；低收益任务不因候选池存在而强行派发。需要推荐时，Orbit 对池内当前可选、可派发的模型按下面顺序处理：

1. **质量先过线。** 根据本地同类任务记录、可比较的编程/Agent 能力资料及任务要求判断是否足以完成该子任务。资料不足的模型可列为“待评估”，不成为最终自动推荐；不能仅凭模型名称声称质量达标。
2. **比较端到端时间。** 考虑成员工作、交接、预期返工、Root 集成与验证、并行资源争用。模型输出速度只是参考；不得把任务总耗时等同于 tokens/s。
3. **比较粗档费用。** 用低/中/高等档位及置信度表达价格或套餐额度负担。优先用实际任务样本、可核查资料与已知计费方式；资料不足时允许根据供应商/模型定位作明确标注的低置信度粗估。按量 API 与订阅额度不换算成虚假的统一每 token 价格；无法判断时如实显示未知，但费用档位未知本身只影响排序、不压掉建议。本轮不增加费用硬预算机制；除用户显式设置的 deadline 外没有新的费用停止线。

这项决定**改变了旧费用硬门**，并已随源码落地并通过真实验收：池内候选路径改用带来源的粗档 `cost_tier`（低／中／高与置信度）作次序，`cost_tier` 未知只影响排序、不构成自动拒绝；旧接口（会话未暴露模型目录时的默认成员比较）保留 `cost.*` / `quota.*` 数值事实用于比较口径。运行合同与 JEV 专项已同步该粗档语义。新规则不维护固定品牌排行榜，示例“Codex/Claude 一档、GLM/Kimi 一档”不作为事实或永久分组。模型证据缓存与来源仍可复用，但不强迫 Root 为每个可选模型查精确报价。本轮不增加费用硬预算机制；除用户显式设置的 deadline 外没有新的费用停止线。

实际调用出现认证或额度失败时，记录具体模型和原因，本会话暂停推荐它；凭据或可选模型列表变化后重新评估。Orbit 不未经 Root 确认自动切到备选。推荐、Root 的派发决定、实际使用模型和失败状态分别记录；候选池变化必须使旧建议失效。

新候选没有可用的同标识证据时，质量判断尚未发生，不能把「缺证据」称为 Jev 低分。Root 仍可在建任务前从一手来源查证并提交到同一用户级缓存以改进排序，但这是**可选动作**，不是池内可运行模型启动前提；相近型号的事实仍不得复用。以前「证据不足或低于质量线即拒绝自动选模」的要求由下方补充裁决废止，不影响本节执行成员派发提示的质量门。

### 4. 独立检查者

检查者继续运行在独立、只读的 OMP 会话中，读取固定快照。它与执行成员共用用户确认的候选池，但必须再通过检查者隔离环境的模型目录与凭据解析；主会话可选而隔离会话无法解析的模型只可考虑执行成员，不自动推荐给检查者。本阶段不复制主会话的自定义模型配置或凭据到检查者目录。

池内有多个具有正向任务适配信号、且隔离环境可运行的检查模型时，Orbit 按端到端时间、粗档费用、不同模型家族、池顺序选择；没有正向信号则用可运行型号中的最高适配分，未取得任何有效评分则按池顺序。降级选择明示质量未经证实；同家族视角多样性低不冒充异家族。`ctx.models.family()` 只供当次家族比较，不持久化。

检查模型由 Orbit 为下一次检查自动选取并记录实际 `provider/id`；用户显式指定优先。当前检查已开始后不切换。模型目录与凭据解析只说明具备尝试条件，不保证额度或网络正常；实际失败时记录并要求 Root 显式重新选择，不把失败结果当作通过，也不自动转用池外模型。

显式指定检查模型的首次 `start` 在建任务前也要用检查者隔离环境作只读目录与凭据解析探测；探测不通过则不创建任务，Root 改选模型。显式优先与池外提示不变；探测成功只证明可尝试，不保证实际请求、额度或结构化检查结果成功。

### 2026-09-27 补充决定：会话显式选择与候选诊断

用户可将一次显式选择的检查模型授权给**同一个 OMP 会话的后续任务**；该选择仅存会话内存，可随时清除，不自动扩充长期候选池，也不跨会话保存。每次启动前仍重新校验该模型在检查者隔离环境可解析且具备凭据；失败明确告知改选操作，不自动换模。没有该授权时仍按长期池与当前会话交集自动选择，不使用之前任务的单次显式模型。精确同标识证据与任务适配分只用于池内排序；缺证据、过期、隔离环境不可解析分别报告已核对的状态，未探测的项目标记未探测。启动和 `/orbit-models` 提供证据提交与显式选择途径，但池内模型无证据或低分不再导致选模失败。

### 2026-09-27 补充裁决：模型授权来源与池外默认成员（无授权拒绝实机已验，正例待验）

裁决时，本会话两批原生 `agent="task"` 均未指定模型，四名成员却实际运行在 OMP `modelRoles.task` 的 `zhipu-coding-plan/glm-5.2`；第二批派发前的五个池内成员候选明确不含此型号。当时的「原生派发不受推荐池影响」加上只核对池生成 Agent 的门，使默认角色无告警落到池外；`root_without_hint` 只说明不是 Jev 最终建议，**不证明 Root 或用户明确选了成员模型**。隔离验收由控制者编写的显式 `review_model` 消息只授权那份夹具，不能作为真实用户自动选模或池外授权的正例。

- **成员：**受控任务的通用 `task` 或省略 Agent 派发前解析本会话 `@task` 的精确 `provider/id`，核对当前池；池外只接受本任务原始或后续原生用户消息中独立一行 `Orbit authorization: member_model=provider/id`，保存型号、消息 ID、任务范围和提示。池空、目录不能解析或来源无法证明则拒绝，不默认换模／扩池；注册与首次模型请求仍按可观测身份核对，OMP 暴露的证据不足以证明 park 后进程退出。Root 决定是否派发池内成员，Jev 提示不升级为派发硬门。
- **检查者：**仅真实原生用户消息的独立一行 `Orbit authorization: review_model=provider/id` 授权本任务池外精确检查模型；`Orbit authorization: review_model_session=provider/id` 才可在同一 OMP 会话后续任务沿用。指令须精确、不在引文或代码块中，并绑定消息 ID；Root 参数、环境变量或 `source=explicit` 都不能提供授权。每次仍预检隔离目录和凭据；池内自动降级不需要额外型号授权，低分或证据缺失不等于可自行选池外模型。

源码门与确定性回归已实现；新隔离 OMP 18.3.2 安装已实测通用 `task` 的池外无授权拒绝（任务 `529b9d5b…`），不是成员注册或用户授权例外的正例。真实用户精确例外、池内派发和未经授权 `review_model` 的原生 UI 路径仍待复验；另一夹具中控制者编写的消息不能当本次用户授权。独立检查者默认模型在当前隔离目录不可用，新任务因检查失败暂停，不能把本次路径误记完整交付。证据见[本轮审计](../plan/orbit-session-audit-draft-20260927.md)。

### 2026-09-27 用户补充裁决：检查者适配问题与池内必选

当前 `jev-checker-quality-1` 问“证据是否足以**证明**模型胜任”，其否定项包含缺失／过期证据；旧 selector 又将低于 0.55 作为启动硬门，故 `kimi-code/k3-256k` 本次得到 **0.03** 时原生自动入口直接失败。该值是特定输入下“证据充分”的回答，不足以证明该模型不能检查任务；旧失败仅留总错误，没有持久逐候选判断。用户确认：有可运行池内模型就要选一个，不能要求另购池外型号来克服池内资料不足。

- Jev 新问题版本 `jev-checker-task-fit-1` 只问有可核查事实的候选能否对**当前任务**做有用的只读独立检查、发现实质错误；未知事实单独留作未评分，不编造能力。`quality_#` 的 noul 值是任务适配信号、**不是能力证书**；0.55 只将有正向信号的可运行候选放在优先组。优先组按旧端到端时间／粗档费用／异家族／池顺序排序；组空时有分数选可运行候选中的最高分，全部无分数则按池顺序。评分服务失败仍可按池顺序降级；每次选模都记录真实问题版本、输入、逐模型结果和未评分身份。以前的阈值不可套用到新的问题作为能力达标证明。
- 自动检查者只能从 `候选池 ∩ 当前会话目录 ∩ 隔离检查者可解析目录` 选，针对交集**全部**预检。优先型号不可用则选下一个可运行池内型号；目录、探针异常或没有可运行池内型号时失败，保留具体探测原因与如有的 Jev 请求／返回到项目本地 `.orbit/checker-selection-failures.jsonl`。池空保持原会话默认检查模型，池外仍需真实原生用户精确授权。
- 降级选择通知 Root 并写入任务记录 `review.selection.selection_tier=fallback`、`notice`、`task_fit_scores`、`unscored_candidates`；`orbit status` 显示“检查质量未经证实”。**模型选中不是终检通过**：只读检查、finding／当前版本终检、交付与停止确认门维持原要求。已在途检查和运行中实际认证／额度失败不擅自换模；那是另一个失败边界。

与旧 §1／§3／§4 的质量硬门相比，本补充仅改变**独立检查者自动池内选模**，不更改执行成员提示质量门、用户授权来源或检查结果裁决；此前历史验收的拒绝样本不得充当本规则的正样本。

**本轮验收（2026-09-27）：**独立安装本轮源码（`content_digest=f0802cd6f36bd140952733b0de4eba7b5cbf946569bf6fdae9af05b9b2979f35`）在新 OMP 18.3.2 夹具里，无精确身份缓存、无显式 `review_model`，候选池仅 `zhipu-coding-plan/glm-5.2`。`start` 实际返回池内型号、`selection_tier=fallback` 与可见质量未经证实提示，任务记录 `quality_score=null`、`unscored_candidates`；独立只读终检 #1 `verdict=complete`、无 findings，Root 收到完成通知并提交完成停止，`stop_confirmation.confirmed=true`（任务 `3980289d-4241-428c-9388-4bf7b93b02e0`）。这不是旧 `kimi-code/k3-256k` 低分事实的改写，也不证明低分真实 Jev 排序或多候选兜底；这些分支由确定性回归验证，原用户失败启动未重试。详细证据见[本轮审计](../plan/orbit-session-audit-draft-20260927.md#本轮新增独立夹具检查者池内降级真实闭环)。

### 2026-09-27 后续裁决：检查者缺证据时由 Root 补

上一节的池内降级保证可运行模型不会被缺证据挡在启动前，但不应让 Root 对缺口毫无行动。用户明确要求：缺证据就让 Root 补。只读核对本机用户级候选缓存时，池中 `kimi-code/k3-256k` 为 **valid**，其他五个精确候选标识为 **absent**，无过期项；旧 0.03 **不是** Kimi 缺证据的证明。同供应商近似型号缓存不能替代精确型号。本次补全的是实际缺口提醒，不回溯捏造旧分数。

- 成功启动时仅列出当前会话与隔离检查环境均可解析、却缺失／过期／无效的精确候选身份，写入 `review.selection.evidence_needed`，返回 `start.evidence_needed` 和面向 Root 的真实来源补证命令；证据有效但 Jev 低分或不可用时不要求重复查证。自动原生入口把这条程序提示放入**当前**模型请求（无法安全注入则一次 aside），不会假充用户的新要求，也不会重复生成选模失败。
- Root 在独立检查前优先查一手资料，通常使用不带任务目录的 `orbit model-evidence --file -` 写用户级缓存；若附上当前任务目录且提交身份精确对应 `evidence_needed`，任务承认它是检查者补证，不误报未请求的成员证据。无法核实则如实提交 `status=unavailable` 与原因，不能从近似型号借事实或编造指标。新有效资料改变选择签名，在下一次检查**开始前**重新询问 Jev 并按当前池重选；`unavailable` 回答也会清除这一缺证据请求，但不变造质量分。
- 缺口提醒**不**将“全池可运行必选”重新改为证据硬门。Root 仍可使用已经可运行的池内检查者，真正的只读终检及停止确认不变；已在途检查、池外真实用户授权边界不变。
