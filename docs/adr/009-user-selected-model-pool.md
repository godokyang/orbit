# ADR-009：OMP 会话内的候选模型池与选型

- 状态：已采纳，混合目标实施中，2026-09-29 核对。package 仍为 0.7.10，未冻结新安装构建；本文区分有效决定、实际接线与尚未验收范围。
- 范围：单 OMP 宿主内的型号发现、候选池、执行成员建议和独立检查者选择。具体运行行为以[合同](../../contracts/task-runtime.md)为准，宿主与责任边界见 [ADR-008](008-omp-native-collaboration-base.md)。
- 实施中决定：用户已授权完整实现[混合模型交付方案](../plan/mixed-model-delivery-proposal.md)。下方 §1—§5 汇总本次决定与已接线边界，§6 规定完整替换的语义和接缝；尚未闭合的接线、校准和验收不写成已上线。实现差距见[代码审计](../plan/mixed-model-delivery-code-audit.md)，进度见[当前计划](../plan/vision-completion-plan.md)。

## 背景与理由

账号、provider 和 OMP 配置会改变模型可选范围。Orbit 不能用登录记录、品牌印象或一个默认成员代表所有可用选择，也不能把目录可选解释为实际调用、额度或质量已经验证。候选池用于限定优先考虑的执行资源，真实结果仍通过任务核验。

早期设计增加逐型号原生消息授权门，并把检查者证据不足当启动硬门；日常任务暴露出死锁、池外默认派发和补证误归因。用户后续撤销型号授权门，允许可运行检查者明确降级，并收紧有池任务的通用成员默认路由。以下为合并后的现行规则；旧决定及各构建失败从 Git 和带日期报告查阅。

## 1. 候选池与目录

- 长期候选池跨 Orbit 会话保存，仅存型号标识和格式版本，不存凭据。以 `池 ∩ 当前会话 ctx.models.list()` 形成候选，旧标识不自动迁成相邻版本；目录可选只说明配置与凭据具备尝试条件。
- `/orbit-models` 的交互界面支持搜索和多选，Enter 保存净增删，Esc 取消；无交互 UI 保留文字与逐项命令。池内但本会话不可选的旧型号可移出，不能作为新增选择。
- 保存前重读目录，在跨进程锁内按打开时快照核对本次改变的 ID；同 ID 并发变化拒绝并提示刷新，其他 ID 的变化保留。无净变化不写入，原子持久化；修改池不改变 Root 或在途成员/检查者模型。

## 2. Root 与原生成员

OMP `task` 接受 Agent 名称，Orbit 为当前可用候选生成会话隔离的 Agent 定义，映射明确的 `provider/id`；不写项目或全局 Agent 目录，不修改原版 OMP。Root 通过原生 `task/hub` 决定派发、交接和集成；Orbit 与 Jev 只提供建议，不自动派发。生成 Agent 的启动须有有效 Orbit 任务绑定，团队保持一层。

受控任务每次派发前重新读取可用池内 Agent。有可用池内 Agent 时，Root 可自主指定其名称，即使 Jev 仍在补证；通用 `@task` 若解析为池外默认型号则拒绝并展示池内选择。池空或无可用池内 Agent 才保留可解析的 OMP 默认角色。欲使用另一型号可将它加入候选池，无额外逐型号消息授权。非受控原生会话不受此门影响，不能冒称已经受 Orbit 监督。

注册及首次可观测模型工作仍核对最终型号；配置 override、回退或发现漂移不能悄悄当成功。推荐、Root 自主派发、实际身份及失败分别记录；没有持久 `delegation_hint` 就不能称 Jev 推荐。与 Root 同型号不当作自动多模型优势，实际自主派发仍如实登记。上游不可观测路径及停止边界见限制清单。

## 3. 成员推荐与证据

新版成员 selector 已接 runtime（工作区，尚未作为新安装构建交付）：按当前输入／产物根和依赖取已声明的工作单元，候选为可用池内 Agent；真正空池只用一次实际原生 task 解析，不把池读取失败当空池，不要求 Root 或全池补证。保留工作单元上下文、决定、验收和实际失败／派发历史。

逐候选精确证据与目录先验同时呈现，按四键身份匹配；上下文／模态／工具要求由实际 SDK limits 单独核对。无有效放行时只显示事实并不付费作成员正向判断。匹配 release 时先问 handoff_fit／member_task_fit，通过后问逐候选 task fit；两次实际回执及失败消耗均保存。来源数字不与 Jev 概率相加；相关事实和冲突、任务／问题／实际判断型号约束适用资格。

旧 0.60／0.55／0.50、端到端时间、粗费用档与无池整体比较已从当前成员运行时删除，旧记录按版本解释。可信本路由费用仅在完整可比条件下参与政策，价格或用量未知不当零，不承诺预算内。Root 始终保留自主选择与原生 dispatch；只有成功送达的持久提示和实际 unit／member／call／model／attempt 一致才记为按建议执行，不能给旧失败调用追认下一次建议。

## 4. 独立检查者

检查者运行在另一只读 OMP 会话，读取固定快照；模型配置与凭据按 OMP 能力解析，不写入任务记录。主会话可选不等于隔离环境可运行；所有路径先做只读目录/凭据预检，不为全目录发送付费连通性探测。

先考虑可运行池内型号；池空或池内都不可运行时可以从当前 OMP 目录选择。Root 可显式指定可运行型号，逐型号消息授权与旧会话授权记忆已撤销。没有可运行型号才阻止建任务，失败记录实际核对结果，未探测项保持未知。

精确有效事实与目录先验同时供新版 task-fit 输入，实际验收可来自任务 instruction 或当前有效工作单元；检查不隐性要求先声明单元。实际 provider／模型／输入／qset 和真实校准放行匹配后才可正向推荐；未知或未放行时按候选顺序保留可运行选择。当前检查者选型已移除时间、粗费用和家族偏好；可信路由资源只在完整可比条件下影响已过质量门候选。缺失/过期事实及低分降级须显式标质量未经证实，不能把缺证据当已经问得低分。实际失败留证，在尚未尝试的可运行型号中有界重选，全部失败才阻塞；在途检查不换模，失败不能当通过。

Root 可在无任务目录时提交用户级精确事实，也可提交匹配当前任务请求的资料；新有效事实在下一次检查前重评。`evidence_needed` 是助手补证入口，不是要求用户逐候选证明可靠性的硬门。补证、显式选择和降级都不越过独立只读、版本有效、手动终检与停止门。

## 5. 可选 OpenRouter 概述的现有边界

用户可用 `orbit openrouter setup` 配置独立 key，凭据文件权限 0600。仅有 key 且项目未禁用外发时，start 选模准备阶段可请求官方模型目录；只发送认证头，不发送任务文本、代码或对话。无 key、移除 key 或项目禁用时不请求也不消费旧概述缓存。用户级私有快照抓取有效期 72 小时，失败有界退避；`model-status` 只读展示来源、状态与最近外发结果，不触发刷新。

映射 lookup 按 OMP 的 provider/model/reasoning/billing_route 精确匹配 OpenRouter canonical slug，目标消失、canonical 漂移或矛盾即时失效。[来源审计](../reference/openrouter-model-mapping-audit.md)核实了四条模型版本对应，不证明其完整 reasoning 或实际计费路由已核实；当前 K3 的 `billing_route=unknown` 若与真实 OMP 路由不同就不能冒改路由命中。

本次目录事实层已升 overview-v2，保存可得 coding／agentic／intelligence、ID、上下文、模态和参数；按明确任务选择指标，不再以非空 coding 阻断 agentic-only。成员和检查者都已接事实投影，精确记录与目录先验同时呈现。缓存 72 小时仅表示抓取有效，测量日期／方法未知如实记录；明确要求测量日期时不给未知先验，精确证据的测量资格正在补齐。实际覆盖、完整路由身份、代表性校准与真实效果仍待验证。0.7.10 旧 coding 门、仅检查者弱先验及旧阈值是历史基线，不迁为当前题义结论。

## 6. 已采纳的替换决定与实现接缝（实施中）

本节是本次实现依据，不是 0.7.10 能力声明。选择保留 OMP 原生 `task/hub`、先登记后执行、独立只读检查与当前版本停止门，在实际接缝上接通新选型与交接；没有证据表明必须先替换宿主。用户可见的自主派发继续由 Root 发出原生调用，不新增逐次用户批准或硬预算门。

### 6.1 判断与事实资格

入口分开判断执行授权、实质交接价值、独立监督价值，按「执行授权且（交接或监督）」组合；普通直接执行命令与有成果要求的审计可以提供授权。串行工作可以交接，不要求 Root 同时另做独立工作。显式受控请求、拒绝、原生消息去重与有效任务绑定仍先由程序处理。

成员及检查者按实际任务读取相关 coding／agentic／intelligence，保留目录 ID、模型版本、上下文和模态；缺 coding 不阻断相关 agentic，intelligence 不补充成 coding。抓取日期、指标测量日期及方法版本分别保存；测量日期未知可以作为标注局限的模型级先验，不能宣称最新测量或精确路由事实。任务对测量日期有明确要求时，未知不能通过该资格。

事实生产接口已在工作区升为 overview-v2：不复用 v1，返回完整有界目录事实，只向明确指定指标的调用方投影相关先验；未分类消费者不默认编码。目录能力与实际路由限制分别标明，当前测量日期／方法版本未知，要求日期已知时撤掉先验但保留事实。成员与新版检查者已接线，冲突／实际限制缺口留给 Root；实际覆盖、完整路由审计、精确测量日期资格及校准仍待闭合。这一工作区状态不是最终交付或安装版能力声明。

精确证据与目录先验同时提供，标明分别回答的问题、配置与日期。存在同任务／同配置的实质矛盾时标记冲突，暂停该候选的自动正向推荐并交 Root 复核；其余有据候选继续，不要求用户补完整池。Root 可有理由地自选，理由和未消除局限与实际调用分别留存。跨配置或模型级指数与一次任务失败的差别不自动当作矛盾，也不按来源名机械决定胜负。

新入口、任务结构、成员适配及检查者题义全部升版本。校准放行绑定实际判断模型、问题内容／版本、输入投影版本、决策规则与适用任务范围，包含预先标注的真实正例、负例、失败和缺证样本及放行理由。旧阈值、旧概率和未注明实际模型的样本不迁移。未放行时只显示事实与缺口，Root 仍可自主选择；不能为方便工作伪造样本或禁用完成门。

### 6.2 选型输入和排序

新问题、输入投影、缓存补证字段及决策比较均移除速度、延迟、端到端耗时、关键路径缩短与粗价格档。旧无目录路径不作为隐藏的备用时间门。运行超时、观察时间、TTL、额度重置与停止控制保留，但不进入适配或型号排序。旧记录按其版本解释，不作为新策略的有效判断。

能力事实是 Jev 的组合输入，不与其输出做数值相加。可运行性、权限、上下文／模态需求、完整身份匹配和事实有效性由程序核对；质量适配由具体工作单元及来源交 Jev 判断。质量正向门的数值只来自对应放行记录，不能照搬 0.55／0.50 或入口旧 0.80。

排序先保留当前任务的质量依据，再应用可比较的真实路由资源规则。价格未知不作免费，交叉输入／输出价格无可信构成时不推出总成本高低。不可比较时显示原因，由 Root 作带局限的选择；稳定兜底顺序不被描述成质量或成本优势。检查者仍有可运行候选降级与有界失败重选，降级不得标作独立检查通过。

### 6.3 工作交接与调用归属

工作单元保留目标、有效要求引用、必要上下文与已确认决定、允许路径／工具／外部动作、验收方式、依赖以及停止／升级条件，并绑定任务输入版本、实际产物根与实际原生派发调用 ID；建议记录目标派发尝试，旧失败调用不能领取新尝试归因。程序持久保存实际注册成员 ID、provider/model/reasoning/billing_route，结果由实际成员与相应工作单元回收核验，不按相邻时间猜归属。

Root 负责交接内容，程序在实际工具入口执行可计算范围限制；提示中的「只读」或成员自报遵守不能代替执行约束。目录上限不能覆盖更小的实际路由上限。实际范围或身份与声明不符时保留失败与已发生消耗，不静默换型号继续记作成功。既有要求修订、工作区、成员登记和停止证据的版本门保持有效。

调用账本至少关联调用 ID、任务／工作单元、角色、实际成员和执行身份、结果状态、usage 来源及分类定义。已有任务级会话累计值没有可靠调用归属时只能显示未归属，不能重复并入成员或当前任务。入口／判断、Root、成员、检查、裁定、重试及升级分别记录；失败响应有真实 usage 时保留，未知时显式标缺失，不归零。

### 6.4 路由资源事实

本路由资源记录包含完整执行／计费身份、第一方或可核实来源、核实时间及有效条件、币种、每项原单位和计价规则。输入、输出、缓存、推理分类按供应商定义记录，含重叠或包含关系，不能将其无条件相加。OpenRouter 报价仅属于该目录，不进入其他 OMP 路由结算。

订阅保留计划与账号范围、额度原单位、加权／请求规则及重置条件；只能在已核实的共同规则下比较，不硬换成 API 美元单价。金额计算使用真实可归属用量与对应有效价格；缺任一项就保持估计或未知，不能冒充实际账单。相近工作单元预测保留样本范围与不确定性，不让 Jev 编 token，也不新增预算配置、预算准入或费用停止线。
