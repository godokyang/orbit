# ADR-009：OMP 会话内的候选模型池与选型

2026-10-16：[ADR-012](012-jev-purpose-specific-input-and-compaction.md) 部分替代本文件中的 JEV 观察去重、检查模型随普通输入重选及通用输入组织安排。压缩模型新增速度优先仅适用于压缩；成员与检查者质量排序原边界保持。实现和新输入校准状态见交接。

- 状态：已采纳，2026-10-16 更新角色候选池与 Root 模型边界。实现与验证范围见[当前交接](../plan/handoff.md)。
- 范围：单 OMP 宿主内的型号发现、候选池、执行成员建议和独立检查者选择。具体运行行为以[合同](../../contracts/task-runtime.md)为准，宿主与责任边界见 [ADR-008](008-omp-native-collaboration-base.md)。

## 背景与理由

[ADR-011](011-agent-autonomy-and-runtime-responsibility.md)规定 Agent 与程序的职责：成员自主选择文件，Root 事后核对。用户明确授权、实际身份、模型池与调用账本约束继续适用。整项任务的效果评价见本文末节。

账号、provider 和 OMP 配置会改变模型可选范围。Orbit 不能用登录记录、品牌印象或一个默认成员代表所有可用选择，也不能把目录可选解释为实际调用、额度或质量已经验证。候选池用于限定优先考虑的执行资源，真实结果仍通过任务核验。

型号可运行与质量适用是不同事实。未获质量正向支持的可运行检查者可以明确降级；配置角色池后，自动选型不得借另一角色池或池外默认型号。

## 1. 候选池与目录

- 长期候选池跨 Orbit 会话保存，仅存型号标识和格式版本，不存凭据。以 `池 ∩ 当前会话 ctx.models.list()` 形成候选，旧标识不自动迁成相邻版本；目录可选只说明配置与凭据具备尝试条件。
- `/orbit-models` 的交互界面支持搜索和多选，Enter 保存净增删，Esc 取消；无交互 UI 保留文字与逐项命令。池内但本会话不可选的旧型号可移出，不能作为新增选择。
- 保存前重读目录，在跨进程锁内按打开时快照核对本次改变的 ID；同 ID 并发变化拒绝并提示刷新，其他 ID 的变化保留。无净变化不写入，原子持久化；修改池不改变 Root 或在途成员/检查者模型。

### 1.1 执行者与检查者候选池分离（2026-10-16）

用户确认将原共享偏好池拆成 `executor` 和 `checker` 两个角色池。JEV 为执行成员选型只使用执行者候选池，为检查者选型只使用检查者候选池，并自行判断候选对当前任务的适用性；同一型号可以分别加入两个池。Root 继续使用启动 OMP 会话的当前模型，不进入任一池。该决定不引入品牌、强度、价格等级或自动升级规则；保留既有显式检查模型选择能力。

存储从 v1 共享列表迁至 v2 角色结构时保留原列表为 legacy 来源。角色尚未单独配置时继承该来源；若没有旧列表，则保持此前各调用路径的空池处理（成员用当前 `@task` 解析，检查者从当前 OMP 可用目录选型）。角色被显式配置后（包括空列表），该角色只在自己的配置与当前 OMP 目录交集中选择；不可用项只影响该角色，且不会触发另一池或全目录回退。此规则区分未配置和已配置为空，避免把兼容回退误报为配置失败。

OMP 18.9.0 扩展 API 核查（`omp://extensions.md` 的 Extension context、Model selection 与 UI integration points）：`ctx.models` 只提供目录查询，`ctx.ui.select` 是单项选择，没有面向扩展的多选模型池组件。内置模型选择器属于 OMP TUI 的 `/model`、`/switch` 命令实现，没有暴露给扩展的调用入口。因此无法复用该原生组件满足双角色多选编辑；继续用 Orbit 的 `ctx.ui.custom()`，参照 OMP 的搜索、列表、光标与键盘呈现，保留角色池编辑语义。

角色化 `/orbit-models` 仍保留搜索、多选、键盘操作和一次确认保存。每次打开先选角色，只能提交该角色的一份净增删；编辑另一个角色时重新进入命令。

严格任务的模型授权仍是调用上限；已配置的执行者候选池与授权名单取交集，授权名单不能补充池外候选。未配置执行者池时保留既有严格任务行为。

CLI 的 `model-candidates` 命令省略 `--role` 时保留旧共享池读写接口，操作 v2 文档中的 `legacy_models`；这些变更不会改写已配置角色池的实际候选。需要查看或修改执行者、检查者实际候选时必须指定 `--role executor` 或 `--role checker`。这是 legacy-only 兼容行为，不表示角色配置会跟随旧接口更新。

## 2. Root 与原生成员

OMP `task` 接受 Agent 名称，Orbit 为当前可用候选生成会话隔离的 Agent 定义，映射明确的 `provider/id`；不写项目或全局 Agent 目录，不修改原版 OMP。Root 通过原生 `task/hub` 决定派发、交接和集成；Orbit 与 Jev 只提供建议，不自动派发。生成 Agent 的启动须有有效 Orbit 任务绑定，团队保持一层。

受控任务每次派发前重新读取可用执行者池 Agent。有可用池内 Agent 时，Root 可自主指定其名称，即使 Jev 仍在补证；通用 `@task` 若解析为池外默认型号则拒绝并展示池内选择。执行者池未配置且无继承旧候选时才保留可解析的 OMP 默认角色；显式配置空池或无可用池内 Agent 不回退。欲使用另一型号可加入执行者候选池，无额外逐型号消息授权。非受控原生会话不受此门影响，不能冒称已经受 Orbit 监督。

注册及首次可观测模型工作仍核对最终型号；配置 override、回退或发现漂移不能悄悄当成功。推荐、Root 自主派发、实际身份及失败分别记录；没有持久 `delegation_hint` 就不能称 Jev 推荐。与 Root 同型号不当作自动多模型优势，实际自主派发仍如实登记。上游不可观测路径及停止边界见限制清单。

## 3. 成员推荐与证据

成员 selector（已交付）：按当前输入／产物根和依赖取已声明的工作单元，候选为可用执行者池 Agent；只有执行者池未配置且没有继承旧候选时，才用一次实际原生 task 解析维持原空池行为。显式配置空池或无可用候选不回退；池读取失败也不当空池，不要求 Root 或全池补证。保留工作单元上下文、决定、验收和实际失败／派发历史。`execution=root` 不占推荐队列，可派单公平轮转；declare 回执和 task 前刷新让 Root 在派发前取得真实评估，程序不改其型号选择。缓存只随该单元相关依据变化失效，无关项目文件变化不重付费。

派发历史逐尝试保留实际成员／调用／型号及 finish 的状态、结果、核验、结束时间。重派不擦除历史结果或累计用量；这些结果沿现有单元投影进入选择判断和原生成员交接。保留失败事实是为了区分服务、输入和能力问题，不从一次失败制造永久型号黑名单。

逐候选精确证据与目录先验同时呈现，按四键身份匹配；上下文／模态／工具要求由实际 SDK limits 单独核对。无有效放行时只显示事实并不付费作成员正向判断。decision-4 匹配 release 时仍问 handoff_fit／member_task_fit，仅 handoff_fit 判结构可交接，member_task_fit 保留为诊断限制；具体候选由逐候选 task fit 原质量门决定；两次实际回执及失败消耗均保存。来源数字不与 Jev 概率相加；相关事实和冲突、任务／问题／实际判断型号约束适用资格。

旧 0.60／0.55／0.50、端到端时间、粗费用档与无池整体比较已从当前成员运行时删除，旧记录按版本解释。可信本路由费用仅在完整可比条件下参与政策，价格或用量未知不当零，不承诺预算内。Root 始终保留自主选择与原生 dispatch；只有成功送达的持久提示和实际 unit／member／call／model／attempt 一致才记为按建议执行，不能给旧失败调用追认下一次建议。

## 4. 独立检查者

检查者运行在另一只读 OMP 会话，读取固定快照；模型配置与凭据按 OMP 能力解析，不写入任务记录。主会话可选不等于隔离环境可运行；所有路径先做只读目录/凭据预检，不为全目录发送付费连通性探测。

检查者池已配置时只考虑池内且当前 OMP 可选的型号；空池或池内无可运行型号时失败关闭，不借执行者池或整份目录。检查者池未配置时优先使用迁移前共享候选；没有可选或可运行的继承候选时，沿用原逻辑回退到当前 OMP 可用目录。Root 可用显式 `review-model` 指定任一可解析且可运行型号，逐型号消息授权与旧会话授权记忆已撤销。失败记录实际核对结果，未探测项保持未知。

精确有效事实与目录先验同时供新版 task-fit 输入，实际验收可来自任务 instruction 或当前有效工作单元；检查不隐性要求先声明单元。实际 provider／模型／输入／qset 和真实校准放行匹配后才可正向推荐；未知或未放行时按候选顺序保留可运行选择。当前检查者选型已移除时间、粗费用和家族偏好；可信路由资源只在完整可比条件下影响已过质量门候选。缺失/过期事实及低分降级须显式标质量未经证实，不能把缺证据当已经问得低分。实际失败留证，在尚未尝试的可运行型号中有界重选，全部失败才阻塞；在途检查不换模，失败不能当通过。结构化判定的认证／额度失败（auth_or_quota/structured）按任务保存排除并跨产物／输入版本生效，Root 经 review-model 点名并携带 recovery_evidence 才是显式重试授权（Root 声明的恢复依据，非程序已验证恢复）且仅移除该目标；不可用与结果校验失败维持产物作用域重试。固定 checker／adjudicator 的隔离会话禁用该层 SDK 默认 provider-error 自动重试（`retry.enabled: false`，仅隔离层；不涉底层传输能力）：此层模型失败恢复归 Orbit 有界重选处理，以免一次检查内反复消耗同一失败型号；禁用后固定型号单次失败即交重选，瞬态错误同样一次结束本次检查（tradeoff 如实记录）。不改 Root／成员／全局设置，不新增重试框架或开关。

Root 可在无任务目录时提交用户级精确事实，也可提交匹配当前任务请求的资料；新有效事实在下一次检查前重评。`evidence_needed` 是助手补证入口，不是要求用户逐候选证明可靠性的硬门。补证、显式选择和降级都不越过独立只读、版本有效、手动终检与停止门。

## 5. 可选 OpenRouter 概述的现有边界

用户可用 `orbit openrouter setup` 配置独立 key，凭据文件权限 0600。仅有 key 且项目未禁用外发时，选模准备阶段可请求官方 `/models` 元数据及 `/benchmarks?source=artificial-analysis`；不发送任务文本、代码或对话。无 key、移除 key 或项目禁用时不请求也不消费旧概述缓存。两个来源均成功才发布新私有快照，抓取有效期 72 小时，失败有界退避；`model-status` 只读，不触发刷新。

映射 lookup 按 OMP 的 provider/model/reasoning/billing_route 精确匹配 OpenRouter canonical slug，目标消失、canonical 漂移或矛盾即时失效。[来源审计](../reference/openrouter-model-mapping-audit.md)现含六个精确身份变体（四个模型 identity）；`unknown` 不匹配真实 subscription 变体，路由命中不证明实际计费路由已核实。

目录事实层使用 overview-v3，保存可得 coding／agentic／intelligence、ID、上下文、模态和参数；按明确任务选择指标，不再以非空 coding 阻断 agentic-only。成员和检查者都已接事实投影，精确记录与目录先验同时呈现。缓存 72 小时仅表示抓取有效，测量日期／方法未知如实记录；明确要求测量日期时不给未知先验，精确证据按测量资格核对，未知保持未知。代表性校准与真实效果按完成记录（Git 历史：`aa089bb:docs/reference/mixed-model-delivery-completion-20261001.md`）的有限范围成立；域外泛化未证（见[当前限制](../plan/debt-ledger.md)）。0.7.10 旧 coding 门、仅检查者弱先验及旧阈值是历史基线，不迁为当前题义结论。

## 6. 已采纳的替换决定与实现接缝（已交付）

选择保留 OMP 原生 `task/hub`、先登记后执行、独立只读检查与当前版本停止门，在实际接缝上接通新选型与交接；没有证据表明必须先替换宿主。用户可见的自主派发继续由 Root 发出原生调用，不新增逐次用户批准或硬预算门。

### 6.1 判断与事实资格

入口分开判断执行授权、实质交接价值、独立监督价值，按「执行授权且（交接或监督）」组合；普通直接执行命令与有成果要求的审计可以提供授权。串行工作可以交接，不要求 Root 同时另做独立工作。显式受控请求、拒绝、原生消息去重与有效任务绑定仍先由程序处理。

成员及检查者按实际任务读取相关 coding／agentic／intelligence，保留目录 ID、模型版本、上下文和模态；缺 coding 不阻断相关 agentic，intelligence 不补充成 coding。抓取日期、指标测量日期及方法版本分别保存；测量日期未知可以作为标注局限的模型级先验，不能宣称最新测量或精确路由事实。任务对测量日期有明确要求时，未知不能通过该资格。

事实生产接口使用 overview-v3，返回有界目录事实，只向明确指定指标的调用方投影相关先验；未分类消费者不默认编码。目录能力与实际路由限制分别标明，测量日期／方法版本未知时如实记录。明确要求日期已知时撤掉未知先验但保留事实。模型级先验不能代替完整路由审计或证明域外适用性。

`/models` 不提供所需指数，基准按 permaslug 精确关联目录的实际 id／canonical；关联矛盾不猜目标。多 reasoning 变体并列保留，不提升最大值或均值；数据集 `as_of` 不充当测量日期。新 delegation-4／candidates-4／checker-fit-5 判断当前质量事实是否支持把候选列为有界可验证选项，避免要求事前预测交付成功。相关模型级先验可以支持初始判断，逐路由成功证书不是前置。选择成本输入绑定本任务／单元及当前要求，保留可信路由事实快照和预测依据；不同账户已分别核实且币种一致的现金估计可比较，订阅仍按原单位和明确条件展示。

精确证据与目录先验同时提供，标明分别回答的问题、配置与日期。存在同任务／同配置的实质矛盾时标记冲突，暂停该候选的自动正向推荐并交 Root 复核；其余有据候选继续，不要求用户补完整池。Root 可有理由地自选，理由和未消除局限与实际调用分别留存。跨配置或模型级指数与一次任务失败的差别不自动当作矛盾，也不按来源名机械决定胜负。

新入口、任务结构、成员适配及检查者题义全部升版本。校准放行绑定实际判断模型、问题内容／版本、输入投影版本、决策规则与适用任务范围，包含预先标注的真实正例、负例、失败和缺证样本及放行理由。旧阈值、旧概率和未注明实际模型的样本不迁移。未放行时只显示事实与缺口，Root 仍可自主选择；不能为方便工作伪造样本或禁用完成门。

### 6.2 选型输入和排序

新问题、输入投影、缓存补证字段及决策比较均移除速度、延迟、端到端耗时、关键路径缩短与粗价格档。旧无目录路径不作为隐藏的备用时间门。运行超时、观察时间、TTL、额度重置与停止控制保留，但不进入适配或型号排序。旧记录按其版本解释，不作为新策略的有效判断。

能力事实是 Jev 的组合输入，不与其输出做数值相加。可运行性、权限、上下文／模态需求、完整身份匹配和事实有效性由程序核对；质量适配由具体工作单元及来源交 Jev 判断。质量正向门的数值只来自对应放行记录，不能照搬 0.55／0.50 或入口旧 0.80。

排序先保留当前任务的质量依据，再应用可比较的真实路由资源规则。价格未知不作免费，交叉输入／输出价格无可信构成时不推出总成本高低。不可比较时显示原因，由 Root 作带局限的选择；稳定兜底顺序不被描述成质量或成本优势。检查者仍有可运行候选降级与有界失败重选，降级不得标作独立检查通过。

### 6.3 工作交接与调用归属

Root 交接目标、有效要求、必要上下文与已确认决定、用户明确限制、验收方式、依赖和停止／升级条件。成员自主调查并选择文件与方法，Root 核对实际改动；不以 Root 预列文件名单作为执行前置。用户授权、宿主真实权限与任务记录保护仍适用。

工作单元绑定任务输入版本、实际产物根与实际原生派发调用 ID；旧失败调用不能领取新尝试归因。程序保存实际成员 ID、provider/model/reasoning/billing_route，按实际成员与对应工作单元回收结果，不按相邻时间猜归属。实际身份或用户授权范围不符时保留失败和已发生消耗，不静默换型号记作成功；要求修订、工作区、成员登记和停止证据的版本门继续有效。

调用账本至少关联调用 ID、任务／工作单元、角色、实际成员和执行身份、结果状态、usage 来源及分类定义。已有任务级会话累计值没有可靠调用归属时只能显示未归属，不能重复并入成员或当前任务。入口／判断、Root、成员、检查、裁定、重试及升级分别记录；失败响应有真实 usage 时保留，未知时显式标缺失，不归零。

推荐 hint 与 native 派发的绑定按**同代**校验：持久 hint 的版本必须与同一工作单元实际 persisted selection 记录的版本一致（均为非空版本），否则不把 `hint_signature`／`hint_message_id` 记入该次派发；不接受缺省值相等，也不为旧 `v1` 建无人调用的兼容层。成员因**真实原生错误**结束且无在途工时，程序可按精确派发身份（单元当前 `bound` 且 latest dispatch 的成员／调用完全对应）原子记录一条执行失败事实：错误须为当前回合结构化 `stop_reason=error` 且时间可解析、不早于 `bound_at`；无在途须由非 streaming、`active_tools=0`、registry 为已知 `idle`（`null`／parked／未知保留手动 finish）与**实际 owner-scoped async 快照 `running` 为空**共同证明（缺 getter／`null`／未知形状不推定）。该事实只表示执行失败，不改写 Root 的业务裁决、不写 `acceptedAt`、不放宽正常派发门。

可交接的工作不要求可并行。Root 可以确定接口、约束与验收，成员随后实现，Root 再集成。受控 Main 会话在可达的 provider 请求中，以原生 system／developer 同层合作政策说明有界串行交接；该政策用于消除原生 restrained 指引对单成员交接的限制，不替代实际派发、不扩大权限，也不强迫短小任务委派。未知载荷形状保持未送达，不把用户消息尾当作同层注入。只记录渠道、版本、任务、会话、型号和文本指纹，不保存原始请求体；单次 bootstrap 引导独立保留。

Root 沿用 OMP 当前模型，角色候选池不参与 Root 选型。Orbit 不提供阶段换模或按检查发现自动换模的策略；用户仍可通过 OMP 原生 `/model` 主动切换。Root 的集成责任不依赖换模：按原始要求核对交付和验证，必要时修复，再请求独立终检。实现与验证边界见[交接](../plan/handoff.md)。

### 6.4 路由资源事实

本路由资源记录包含完整执行／计费身份、第一方或可核实来源、核实时间及有效条件、币种、每项原单位和计价规则。输入、输出、缓存、推理分类按供应商定义记录，含重叠或包含关系，不能将其无条件相加。OpenRouter 报价仅属于该目录，不进入其他 OMP 路由结算。

订阅保留计划与账号范围、额度原单位、加权／请求规则及重置条件；只能在已核实的共同规则下比较，不硬换成 API 美元单价。金额计算使用真实可归属用量与对应有效价格；缺任一项就保持估计或未知，不能冒充实际账单。相近工作单元预测保留样本范围与不确定性；引用的历史调用须完整归属；成员样本还须匹配已接受单元的实际成员和型号，后续换人成功不追认此前拒绝结果。预测分类构成须等于这些回执的逐类均值，防止引用真实调用却填入任意数字。原生回执未报告的 reasoning 在账本中保持缺失，引用核验只在该比较处按类型化 unknown 对齐，已报告的具体档位不归一为 unknown。Root 声明的无样本 token 构成只展示条件性估计，不用于自动费用排序。不让 Jev 编 token，也不新增预算配置、预算准入或费用停止线。

## 2026-10-09 长任务能力来源补充（已实施，有限验收）

用户确认同型号跨渠道合理复用模型级评测：精确有据映射优先，其次当前目录具体型号，再允许可解释的日期/fast等档位后缀回退基础型号；命中及降级来源可追溯，歧义不猜，不能混用不同代际或把目录价格/额度/上下文移植成实际路由事实。原因是现场已有目录型号因机械身份阻断未获先验；另有 fresh 但缺任务相关指标的事实-only 路径，必须保留真实缺口并在声明工作单元时明确相关指标。Root 为成员自主选型须给出任务相关理由，不使用型号或品牌偏好。Jev 题义、阈值、校准和实际完成门保持，真实推荐与自选分开验收。

实现、推荐影响原生派发及实际调用的有界证据见长任务验收（Git 历史：`aa089bb:docs/reference/long-task-optimization-acceptance-20261009.md`）。已观测的账户余额／额度失败跨产物更新保持排除；对该目标显式 review-model 还须提供 recovery_evidence，引用实际账户恢复或同路由成功调用。记录注明这是 Root 声明，程序没有独立证明账户已恢复；不因此解禁其他失败目标。

## 2026-10-12 可选严格模型授权

用户授权修复 Loom 实际检查调用逃出 MiniMax 名单的问题。新增独立于普通偏好池的精确任务名单（集成合同 1.4 `model_authorization`）：CLI `--allowed-model`、可选 `ORBIT_ALLOWED_MODELS` 会话启动上限，冻结后重选/回退仅可取名单内型号，耗尽阻断，paused 接续继承或缩小。普通任务的既有偏好语义保留；不改全局配置。原因是显式 review-model 只绑定当前选型输入，输入变化后重选本来合法，但不能代表外部授权边界。

采用公开 Agent.streamFn 与 ModelRegistry.resolver/getApiKey 的调用前守卫，包括缓存解析器；扩展 hook 错误被 OMP 捕获，不能独自承担阻断。严格任务关闭独立供应商的可选 JEV 辅助判断，保持原生协作与检查/停止硬门。未绑定前要受限必须设置会话环境上限，缺宿主接缝拒绝而不降级。具体公开字段与边界以 contracts/integration.md 为准；源码实现与验证事实见当前交接，不据实现声明真实全路径通过。

## 2026-10-16 补充：以整项任务评估成本与自动完成效果

状态：已确认的评价原则；JEV 调用记录已补充，整体效果仍需实际观察。理由见 [ADR-011](011-agent-autonomy-and-runtime-responsibility.md)：低价调用、少传 token 或减少顶级模型使用，可能被重复检查、返工和用户介入抵消。

首先核对是否按原要求及有效修订完整交付，再看完成这项任务的总投入。模型调用包括 Root、成员、JEV、独立检查、裁定、失败、重试与升级，沿用已有账本和真实归属，不重复累计。费用按可核实的路由价格与用量计算；缺项记未知，估计与实际分开，不将订阅额度硬换成金额。

等待、重复裁定、返工及用户催促／纠正另以实际记录评价。用户正常补充需求、主动提问不自动计为不满意或失败；结合前后文判断是否在替 Agent 推进任务。时间、调用量、费用与用户介入分别呈现，不制造无依据的综合分，也不将用户时间随意折成金额。

比较方案时同时看交付质量和这些投入，保留任务类型、模型与证据范围；更多只读调查可能提高单次成本，也可能减少后续返工，须实际观察。既有单任务正例和负例均保留，不能外推为普遍节省。

本节用于评估产品是否更完整、更省、更自动，不新增调用次数、耗时或预算硬门，不要求用户为每次调查批准。它也不直接改变 §6.2 的自动选型输入、排序或 JEV 阈值。
