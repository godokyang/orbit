# ADR-013：终检按交付验收，未检查项继续核查

状态：2026-10-16 用户确认，本次实现与验证已完成，真实分支边界见交接。当前进度见[总待办](../plan/agent-autonomy-implementation.md)；落地规则由[任务运行合同](../../contracts/task-runtime.md)维护。

本决定细化 [ADR-011](011-agent-autonomy-and-runtime-responsibility.md) 的 Root、检查者与程序职责，替代此前同版本最新整轮核查结果一律覆盖已有有效结论的规则。独立只读检查、模型授权、当前版本终检与实际停止门保持。

## 决定

- 默认终检核对用户要求的功能、关键安全边界与必要验证。开发过程要求仍由 Root 执行；未明确要求过程审计时，不以穷尽阅读履历或无功能影响的过程文档完整性阻断交付。用户明确要求的文档成果、测试、权限和资源边界仍属于验收，不能借此省略。
- 检查者区分尚未检查、缺少必要证据、已发现缺陷。尚未检查表示检查工作未完成，由检查流程继续；缺证与缺陷明确交给 Root 处理。未知分类保持未知，不从自然语言猜测处理方向。
- 同一要求在相关前提未变时，已有有效核查结论可以沿用；本轮未重读不构成撤销理由。有新反证或证据失效时撤销旧结论。输入、产物或工作区变化后，历史结论仅供检查者判断适用性，不由程序直接授予当前版本完成资格。
- 续查仍须完成整体交付核对。没有新发现不等于通过，没有进展也不能无限自动重试；明确记录未完成核查及下一责任方，由 Root 处理检查阻塞，不把检查工作缺口伪装成交付缺陷。
- 状态展示基于实际排队、运行和结束记录，说明剩余事项与下一责任方。请求已接受不能显示为检查正在执行，检查结束不能显示为任务已经完成。

## 理由与备选

Loom 接入任务的独立检查发现了真实的回答回执误判缺陷，说明独立核查需要保留。同一任务也发生未变材料从已核实退回未核实、未读完被要求 Root 重新交卷的循环。只改善汇报不能解决进度丢失；取消独立检查或无发现自动通过会漏掉真实业务缺陷。

因此采用收紧默认验收范围和续查有效进度的组合。代价是必须区分检查工作与交付缺口，并保持结论来源及适用版本。该机制不承诺模型判断必然正确，不放宽必要证据和真实停止要求，也不新增全量过程审计平台。
