# ADR-015：本次 DSH 迁移统一重写为 TypeScript

状态：2026-10-20 用户确认技术路线，随后明确“先继续完善文档”。**重写与 P3 均未开始**。当前已确认目标与进度见[总待办](../plan/agent-autonomy-implementation.md#typescript-重写目标与边界)，实施准备及验收映射见[能力整合专题](../plan/dsh-capability-consolidation.md#typescript-重写与切换条件)。本决定不宣称现行程序已更换语言或宿主。

## 决定与适用范围

本次迁移的目标是 **TypeScript/Node.js Orbit Core + DSH 进程内插件 + DSH 应用受控入口**，不再把 Ruby Core 作为长期保留的运行核心。核心重写与宿主替换属于同一次迁移交付，可按完整行为分段实现和验证，不要求一次性改完，也不先交付一个长期维护的 Ruby + DSH 版本。

重写的是实现，不是重新定义产品：

- Orbit 继续提供不依赖 Loom 的独立 Coding Agent 使用方式，拥有任务监督、独立检查及证据反馈能力；DSH 提供模型、工具、会话、成员和后台执行原语。
- TypeScript Core 与 DSH 执行宿主保持进程隔离；这是监督边界，不是单一常驻 daemon 或特定 IPC 的实现承诺。DSH 进程内插件承担宿主接入与调用前控制；独立检查者保持单独进程、只读材料与固定快照，不因同语言合并到执行上下文。
- 保留现行产品义务；不按 Ruby 文件逐行翻译，也不复制 DSH 已有的执行设施。无实际调用方的旧实现不带入新核心。
- 新核心不能靠调用旧 Ruby Core 完成主要功能。正式切换后移除被替代的 Ruby 执行、OMP 接线及安装依赖，不维护两个可写核心或永久运行时回退层。
- 旧任务、导出、证据与公开消费者是实际兼容对象，不因代码退场删除。历史只读支持与保留旧执行核心是两回事。

## 理由

Orbit 将通过 DSH 应用直接供用户使用，而不只是被 Loom 调用。将 Core、宿主插件和应用扩展统一到 TypeScript，可减少跨语言数据转换与重复类型维护，更直接地使用 DSH 的 TypeScript API，并有机会简化运行环境和调试工具链。

这些是工程收益的预期，不是已测得的性能提升，也不保证模型更聪明、费用更低或数据飞轮自动形成。用户在了解同时更换语言和宿主的回归风险后，选择本次迁移统一技术栈。

## 实际考虑过的备选

| 方案 | 取舍 |
| --- | --- |
| 长期保留 Ruby Core，仅用 TypeScript 接入 DSH | 原 R1 推荐，迁移变量较少；用户本次选择统一技术栈，不再作为目标结构 |
| 先完成 DSH 宿主替换，再另行决定是否重写 Core | 便于区分两类回归；用户选择把重写纳入本次迁移，而非推迟成另一项产品交付 |
| 本次重写 TypeScript Core 并接入 DSH | 采用；按完整用户行为分段验证，承担两类变更的兼容和运行验证成本 |

## 后果与不变边界

1. **保持职责隔离与权威写入口。** 同语言不等于同进程。任务监督记录（含 `state.json`、`members.json`、`events.jsonl` 和检查记录）的状态转移与耐久提交由 Core 统一负责；宿主插件上报事实并执行调用前控制，不直接修改任务记录或另建监督状态源。登记必须经 Core 写入口取得耐久确认后才能放行首调用。DSH 仍维护自己的原生会话日志，不把它与 Orbit 任务记录混为一谈。此约束不预选 IPC，也不强制单一常驻 daemon；不能因 DSH 有 RPC 删除监督边界，或凭静态类型替代运行时校验。
2. **保留行为而非代码形状。** 要求来源、版本失效、成员登记/结算、检查/裁定、完成资格、停止/续接、模型授权、JEV 和账本仍须按合同实现。既有 Ruby 程序与测试是行为参照，不是新运行时已正确的证明。
3. **保留数据与协议语义。** 当前记录结构、标识、版本、游标和摘要规则优先保持；不得因两种语言的 JSON、缺失值或数值处理不同而重算历史、伪造来源或改变公开结果。实施设计须明确格式/能力版本的识别与兼容规则，包括已有记录的识别办法，不为新增版本标识改写历史。新增字段不能仅凭旧解析器会忽略就判定兼容读写；确需变更时先明确兼容与转换办法，不顺带改存储架构。
4. **干净切换。** 切换前确认旧任务执行及资源实际停止；新任务由新核心拥有。新旧核心不得同时写同一任务目录，不能在未知停止时启动替代写者。旧任务不跨宿主伪续接，旧检查不自动取得新任务资格。
5. **失败恢复有边界。** 新版本未通过切换验收前保留现行可用版本；正式切换必须验证安装/升级失败不会破坏已有记录。保留可回退的发行物不等于保留双核心运行。回退入口须按目标版本的实际格式兼容能力核对读写，不能按记录创建于切换前后判断；不支持的操作在交给旧版本前明确阻止，保留原字节，不假定历史发行物自己会安全拒绝。
6. **兼容问题不由换语言解决。** 集成合同同主版本只加不改不删。DSH 中性消息读取、能力协商及 Loom 迁移仍按专题的逐项兼容路线处理；无法合法表达时先取得合同版本决定，不静默更改旧字段、状态或游标。
7. **证据闭环不升级权限。** 保留本地证据、用户主动分享与校准来源；不自动上传 `.orbit`、训练模型或修改策略，不用 DSH 遥测替代 Orbit 的任务事实。
8. **失联不放行。** Core 不可达、超时或绑定身份不明时，不得新增受控执行或放行登记；在途受控执行的下一次授权/登记门同样拒绝放行，不能借“已经启动”绕过检查。既有资源仍须按任务收束，停止证据未知仍为 `stop_unconfirmed`，不以 UI 退出或 IPC 断开代替确认。重连不授权盲目重发。普通非受控 DSH 会话不因此改变。实施相关行为前须确定 Core、宿主、检查者的启动/停止/回收责任及应用退出路径；Loom 场景保留调用方的进程所有权，公开 `launch` 不替调用方启动进程。
9. **应用不是第二监督源。** 应用入口通过 Core 的授权、状态变更和真实事实投影处理任务，不直接修改任务文件。选用公开集成接口还是内部宿主适配，须在应用接线设计时明确；不能绕过中性消息的来源/游标语义，也不能以 UI 需求破坏现行集成合同。独立交付以 DSH 应用受控路径验收，不另造 TUI；现有公开 CLI/自动化义务保留，宿主专用 `orbit omp` 可按退场条件替换，新宿主启动命令与装配在实施设计时确定。

## 与已有决定的关系

- 部分替代[联合方案 R1](../plan/dsh-capability-consolidation.md#联合方案-r1)中“保留 Ruby 监督核”的语言选择，以及后续产品定位中相同的 Ruby 假设；其余监督义务、独立检查、权限、停止、兼容和证据边界继续保留。原 R1 的双方确认记录是历史事实，不能充当本次新文档的复核证据；后续复核状态见[交接](../plan/handoff.md#本轮验证边界)。
- [ADR-014](014-host-port-interface.md)仍是未采纳的宿主接口提议；其 Ruby 文件布局是当时方案，不能直接作为新核心目录设计。本决定不顺带采纳其全部方法名、能力分级或测试协议。
- [ADR-008](008-omp-native-collaboration-base.md)的 OMP 单宿主仍描述当前可运行实现；本决定指定未来切换目标，不证明 DSH 已满足接缝或取代当前运行合同。
- [任务运行合同](../../contracts/task-runtime.md)、[集成合同](../../contracts/integration.md)、ADR-009/011/012/013 中的产品语义不因语言选择自动改变。实施时若确需改变语义，按对应事实源和用户授权单独处理。

## 当前授权与下一步

当前只完善文档。Node 支持版本、模块/包布局、构建与测试入口、DSH 插件装配和安装方式须在实施设计时依据实际宿主与仓库确定；本 ADR 不凭统一语言预选新框架、数据库或 IPC 协议。应用接口接线、记录格式兼容判定、跨进程启动/停止/回收归属须在对应行为实施前明确，不把这些未决设计当作已通过的能力。

后续工作集中在唯一总待办：先闭合必要宿主接缝及兼容设计，再完成 TypeScript 的真实行为路径，最后核对历史读取、独立应用入口、Loom 集成与干净切换。这里是依赖顺序，不是开工指令，也不把原 P3 适配试验的时限当成全量重写估计。

本次不安装依赖、不创建代码骨架、不启动应用或模型、不删除 Ruby/OMP 代码，不升级版本、提交、推送或发布。未来重写范围扩大不等于这些动作已获当前执行授权。

## 2026-10-20 修订

用户在审计与方案讨论后确认以下七项，作为本决定的修订；与上文冲突处以本节为准。实施依据见[实施计划](../plan/dsh-implementation-plan.md)，接缝验证见[探针记录](../plan/dsh-host-probes.md)。

1. **Core 与 DSH 宿主插件同进程。** 替代上文第 1 条"进程隔离"与第 8 条"失联不放行"：Core 作为 Cordis service 挂载，耐久写失败即失败关闭；进程隔离只留给检查者与 JEV 压缩 runner。理由：进程内同时适配应用入口与 Loom 拉起的进程，去掉 IPC、daemon 生命周期与失联状态；DSH 的插件哲学与此一致。接受的代价：同进程崩溃可能在写入中途带走 Orbit，重启后宿主死亡期间的任务一律 `stop_unconfirmed`。
2. **受控 profile 排除动态 Cordis 与 Creator 预设**，作为一致性测试硬项。这是同进程的前提：web-app bundle 默认挂载的 `cordis-host-runner` 让模型可在宿主进程内运行自定义代码。
3. **不钉 DSH 版本，跟最新。** 删除钉版与升级门禁；保留 `--dump-config` 组合断言、编译在 DSH 导出类型上的类型检查、`session-format-catalog` 历史恢复，用于快速发现而非阻止变化。
4. **发布为单一 npm 包，经 DSH 插件机制安装更新。** 任务记录仍是项目内 `.orbit` 文件；`orbit` 命令保留为薄客户端；Orbit 不向 DSH 会话日志追加自己的事件类型。
5. **凭据走 DSH credentials 引用**，JEV 与模型相关 key 不再经 shell 启动文件；模型参数进插件 Config。
6. **采纳 ADR-014 的义务清单（H1–H7、O1–O4）与一致性测试部分**，废弃其 Ruby 目录布局与"只换适配层"的理由。
7. **工具链**：Node 22 以上、pnpm、vitest、tsdown，与 DSH 对齐；包命名与仓库布局在切片一开工时定。

同日用户补充确认三项：

8. **不兼容旧记录。** 产品未发布，没有历史包袱。替代上文第 3 条"保留数据与协议语义"与第 5 条按格式核对回退：任务记录按 TypeScript 的需要重新设计，不读旧 OMP 任务，不提供旧字节偏移读取，不跨宿主续接。
9. **集成合同出 2.0，字段按 DSH 重新设计。** 不再按 1.x"只加不改不删"追加能力；Loom 节点在 C 阶段一次改到 2.0。破坏性变更升主版本的规则（ADR-010）不变。
10. **应用界面由 AI 先做出第一版**，用户之后再改；不先写界面设计。受控会话排除 Creator 预设与动态 Cordis 的取舍已确认；本修订不做第二方复核，用户决定。

本修订仍不构成实现、安装、发布或删除 Ruby/OMP 代码的授权。
