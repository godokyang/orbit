# ADR-012：按判断用途组织 JEV 输入，必要时压缩选型材料

- 状态：2026-10-16 用户已确认并授权实施；实现与验证进度见[总待办](../plan/agent-autonomy-implementation.md)。
- 规则归属：[任务运行合同](../../contracts/task-runtime.md)。本决定部分替代 ADR-008 的观察去重安排，以及 ADR-009 中检查模型随普通输入变化重选的安排。成员及检查者的质量判断仍不以速度排名；速度仅用于本决定新增的压缩模型选择。

实际委派和检查模型选择请求携带了约 154 KB 的项目依据全文，并返回输入超限。观察请求虽成功，仍有依据截断、操作头部丢失和成员关联缺失。减少请求长度不能证明判断正确，因此按四类问题分别收集已有事实，避免把整个任务或会话作为通用输入。

入口只读取当前用户原文，过长或指代不清仍交 Root。观察读取原要求、修订、新消息、执行状态、近期完整操作及带范围和版本的成果证据；首次约 5 秒，后续每 5 分钟一次，相同情况也能再次判断。检查在途时跳过，不补发。近期操作从上次检查节点之后取，最多最近 20 条，不裁剪单条文字。程序不推断语义进展，疑难情况交独立检查读取原件。

用户随后明确将成果提交判断交还 Root：JEV 缺少完整成果与执行上下文，删除 `artifact_ready` 问题及其自动产物检查分支，观察版本改为 `jev-observation-4`，仅保留卡住和偏题两题。Root 决定何时提交终检，独立检查者判断是否满足要求，程序核对版本、完成与停止事实。既有交付事件调度及手动终检门保持；不通过调低分数或扩大 JEV 上下文让它承担成果验收职责。

成员选择围绕已声明工作的目标、要求、背景、验收、依赖与候选能力组织，按实际选型依据复用结果。检查模型以真实任务要求、首次统计的项目规模、Root 可选补充和候选能力选择，并在同一任务内复用。文件数不代表复杂度；模型不可用、用户更换或 Root 判断能力需求发生实质变化时才重选。每次检查继续读取当前要求和成果。

只对成员及检查模型选择中的必要长材料按需压缩。先纠正输入组织；可靠容量检查或明确超限才能触发。JEV 依据用途、材料元数据和可用候选选择能保真且容纳原文的压缩模型，满足要求后优先快者。速度来自可靠资料或实际记录，未知不编排名。选型请求不发送待压缩全文。压缩不改写结构化身份、限制、状态和版本；原件保留。相同原文版本、用途、保留要求、规则和预算复用结果及在途请求，一次压缩后仅重试一次原判断。

没有选择独立记录 Agent、周期摘要或全会话压缩：它们增加常驻调用，不能修复材料选错。没有选择机械截断、固定小字数目标或强迫 Root 反复改写：它们可能丢失必要限制。没有采用分块递归压缩或每次再用模型审摘要：第一版明确失败并回到既有不可用路径，实际验证核对语义保真。程序格式与大小校验不证明无损，模型请求成功也不证明判断正确。
