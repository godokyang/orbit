# ADR-008：以原版 OMP 的原生协作为 Orbit 基座

- 状态：现行 OMP 单宿主决定；源码实现与当前验证边界见[交接](../plan/handoff.md)。已结束的 M4 九项历史判定与未测分支沿 Git 历史查阅（`git show 3865b76:docs/reference/omp-native-m4-acceptance-20260924.md`），不据此推断当前安装版或新选型方向已经验收。
- 范围：当前 `orbit omp` 入口、原生成员、独立检查及上游策略。具体行为以[任务运行合同](../../contracts/task-runtime.md)和[ADR-009](009-user-selected-model-pool.md)为准。
- 依据：OpenCode v2 与 OMP 调研、ADR-007 多宿主时代理由均沿 Git 历史查阅。后续架构选项见认可的[主方案](../plan/mixed-model-delivery-proposal.md)。

## 背景与理由

Orbit 自建的执行成员没有直接使用 OMP 的 `task/hub` 协作，成员通信与唤醒仍由 Orbit 接线承担。调研显示，OMP 已提供同一进程内的原生派发、成员消息、等待和唤醒；OpenCode v2 的已发布子 Agent 能力没有同等的成员互发消息路径。继续维护多个宿主及各自成员控制路径会增加实现和升级成本。当前只有一位使用者，没有需要迁移的外部调用方。

## 已确认的决定

1. **单一宿主。** 只支持 OMP。采用原版 OMP 加 Orbit 扩展；不复制 OMP 的 `task/hub` 模块，不预先维护 Fork。移除 Codex、OpenCode 等旧宿主路径时不建设兼容层或历史任务迁移；旧路径代码已移除（M3.1），历史验收证据保留在 `docs/reference/` 备查。
2. **显式会话入口与按请求建任务。** `orbit omp [OMP 原生参数]` 启动原版 OMP 并为本次 Root 会话加载 Orbit 扩展；模型、工具、权限、profile 和恢复参数仍由 OMP 处理。普通 `omp` 不接入 Orbit。会话入口只使 Root 具备接入资格，不因打开会话就创建任务；未绑定任务的新用户请求按下文 2026-09-26 的入口门自动判定或交 Root 显式决定。受控会话的恢复仍走该入口，不识别 Zeen 等具体项目。
3. **原生执行团队。** 当前面向用户的 OMP 会话担任 Root，不另建 Root。Root 显式调用 OMP 原生 `task` 派发成员，成员通过原生 `hub` 通信、回报和唤醒；Orbit 不再以自己的 SDK 成员替代原生团队。团队保持一层：只有 Root 能派发，成员不能再调用 `task` 派发或自行启动 Orbit。Root 负责核验和集成成员结果。
4. **Orbit 的职责。** Orbit 保留用户原文与有效修改、固定工作区快照、Jev 过程判断、独立检查、纠偏、状态记录和停止确认。委派建议在任务内按有界观察与事件变化给出，最终是否派发由 Root 决定；不使用 OMP advisor 代替 Orbit 的版本化检查，也不自动派发。用户修改要送到 Root 和相关活动成员。
5. **独立检查与模型。** 检查者使用另一 OMP 会话，读取固定快照，保持只读并独立于执行团队；裁定者同样不得参与执行团队。执行成员和检查者的模型由 OMP 配置与可用模型决定，Orbit 记录实际使用的 provider/model，不硬编码 GPT、DeepSeek、GLM、Kimi 等型号，也不把目录可见当作账号可用。
6. **登记、停止与故障。** Orbit 必须识别本任务派出的所有成员，确认其执行及原生后台工作实际结束后才报告完成或停止成功；证据不足时保留 `stop_unconfirmed`。现行“成员实际身份先持久登记、再开始模型工作”的要求不因本 ADR 放宽。OMP 或 Orbit 异常退出后不自动恢复模型执行，仍需能如实报告停止状态并按明确操作重试收尾。
7. **跟进上游。** 2026-09-26 用户将 OMP 入口版本门改为最低版本 18.2.8：等于或高于该版本允许启动，低于或无法解析的版本拒绝。更高版本通过版本门只表示可启动，不等于扩展钩子、`task/hub`、模型解析和停止路径已经逐项验收；发现实际接口变化或运行故障时，按这些接缝在隔离项目复核并修复。当前源码的独立检查 SDK 默认版本为 18.3.4；安装器按实际 OMP 版本对齐 SDK，具体安装以版本与 digest 核对，不用旧 18.2.8 验收记录推断新接缝全已通过。变更 SDK 仍需验证。若原版扩展接口经验证无法满足成员登记与控制，先确定所缺的最小上游接口；是否采用短期最小 Fork 留待有实证的阻断出现时再决定，不以复制模块绕过。

### 2026-10-09 补充决定：Esc 后任务相关追问续接（已确认，实施中）

用户在长任务优化准备讨论中回复“同意你的建议”，确认 D1 采用任务相关追问／纠正后续接。Esc 当下停止受控执行；之后用户追问同一任务进度或纠正做法时，Root 先回答，再沿原要求和有效修订建立新任务／接管边界并推进，不再要求用户额外说一次“继续”。明确暂停／先讨论／取消优先，独立问题只回答；没有后续用户输入时不自动重启，真正无法确认目标时才问归属。

理由：Zeen 现场出现暂停后普通执行继续而监督断档、等待已停止成员，以及最新状态提问成为新任务主体导致原目标丢失。需要保留中断当下的停止效力，同时让任务相关追问能接回原交付，减少用户反复催促。这不将普通独立状态问答一律视为新执行授权，也不改变异常退出后不自动恢复的边界。

旧任务终态及真实停止记录保留，不在终态重检或申请完成，不追认监督空档或迁入旧成员／用量／检查。有效原要求、修改与最新原生消息来源必须可追溯；新边界建立后才可声明受控。采用当前 OMP Root 与 native task/hub，不另建 Root、不换宿主、不扩大权限，完成与实际停止门保持。

目标语义见[合同](../../contracts/task-runtime.md#esc-后的任务续接)，实施与验收条件见[优化实施](../plan/orbit-long-task-optimization.md)。2026-10-09 后续正式授权启动实施；源码以 start.resume_from 接回原要求和有效修订并建立新边界，D1 已实施并通过隔离新安装的有界真实验收，首轮失败与后续修正保留在[长任务验收](../reference/long-task-optimization-acceptance-20261009.md)；本节标题保留确认阶段的链接锚点，不代表当前仍待实现。不宣称用户全局安装已更新。

### 2026-09-29 替换决定：入口价值与版本化放行（已交付，有限验收）

未绑定任务的新原生用户消息仍在 `before_provider_request` 以原生消息 ID 一次判定，明确受控请求走既有前置校验，拒绝与概念讨论不建任务。直接规则先排除成对引文及代码块中的命令；实际审计交付不能因为只读被排除。新 `orbit-entry-3` 分别判断执行授权、实质交接价值和独立监督价值，按授权且两类价值任一过门组合，允许串行交接和只由 Root 执行的监督任务。不使用速度、耗时或必须并行作为入口价值。

自动门只接受同规则、问题内容／版本、输入投影、决策版本和实际模型的放行证据；需有事先标注的真实正负、失败与缺证样本、实际回执、范围及复核理由。旧六条样本、旧 0.80 双门和只填样本数的配置不可迁用。当前源码内置有限 Git 入口放行，固定实际 `jev-1.13.0`，门值执行授权 0.85、交接／监督各 0.65。八个干净生产输入样本包含正负、缺证、真实 HTTP401 及两个阈值冻结后的 holdout，已独立复核。决策版本 `orbit-entry-decision-2` 按可观察 `git_untruncated_request_v1` 收窄：非 Git／截断 uncertain 请求保持 Root 自主决定且不付费，明确受控请求不被价值门否决。有限样本不证明领域泛化；新安装完整闭环已有有限真实验收（单文件负例等，见[完成记录](../reference/mixed-model-delivery-completion-20261001.md)）。裸“继续”没有可靠原要求时交 Root 查归属，已有活动绑定仍直接继续。阈值与别名不静默漂移，实际响应型号不匹配时保留消耗并拒绝自动启动。结构校验不能证明日志真实或普遍可靠，真实来源与效果已有有限验收（见[完成记录](../reference/mixed-model-delivery-completion-20261001.md)），全域仍不作宣称。

同一 `start` 入口亦支持对已执行要求的中途接管（语义见[合同](../../contracts/task-runtime.md)）：接管只记录 Root 的声明与程序真实采集的边界（原生消息来源、接管时存入任务私有目录的工作区快照与摘要、监督开始时刻），不追认旧执行为受控、不迁入其用量／成员／检查，失败即不建任务。

自动启动前置失败与 Root 自主恢复不互相阻断：明确受控请求仍失败关闭；非显式自动候选按下方恢复规则提示未受监督。原生消息去重、任务绑定、独立终检和停止门保持。`before_agent_start` 没有当前原生消息 ID，不作此门；`devin-agent` 类不触发 provider 钩子，其覆盖缺口不由新问题弥补。

统一 `JudgmentRequest`／`JudgmentResult` 继续提供带 ID 的真假标准及经校验的概率、实际 provider／模型和可得用量。部分答案不触发自动动作；本次失败回执保留真实返回的身份与用量，缺失保持未知。TypeSafe 适配只负责协议、鉴权与运行超时，不自己决定启动、派发或停止。其他尚未替换问题集仍按各自版本记录，不将入口放行移作成员适配依据。具体语义见[合同](../../contracts/task-runtime.md)，基线入口样本沿 Git 历史查阅，完整目标见 [ADR-009 §6](009-user-selected-model-pool.md#6-已采纳的替换决定与实现接缝已交付)。

### 2026-09-27 补充决定：低收益入口与未受控原生成员

用户确认后，自动候选选模失败不再默认阻断普通任务：已验证可恢复的宿主请求明确展示「未受 Orbit 监督」并继续，显式要求受控执行的请求仍失败关闭；无法保证恢复提示已送达的宿主请求保守中止。短任务通常直接执行，自动入口价值按当前已校准的交接或监督判断；用户明确指定受控则不因任务短跳过终检。未建 Orbit 任务时允许主代理显式使用 OMP 原生一层 `task`，明确说明不由 Orbit 登记、检查、停止；受控成员登记硬门不变。Root 仍是当前 OMP 会话，采用低成本模型须用户通过 OMP 原生模型选择主动指定，Orbit 不秘密改模型或跨供应商迁移。原因：自动资格不应把原本可直接完成的小任务变成选模死锁，同时不能把非受控原生执行伪称受控交付。

### 2026-09-28 补充决定：显式意图与普通命令的入口区分

「记得用 Orbit」仅在同一原生用户消息明确命令执行具体工作时构成显式受控请求；句中「用已更新的 Orbit 启动」亦不因修饰语漏识别。讨论 Orbit、同名文件、只问状态及孤立产品名不能当授权；明确「别用／不用 Orbit」不走显式或概率自动启动。理由：Zeen 两条已记录执行指令因窄正则走到双 0.80 门，被当成普通任务，显式授权不应取决于独立检查收益；同时必须保留负例边界。

旧 `orbit-entry-2` 的执行授权修订与有限真实样本按历史版本解释，已经被上方新题义替换，不能放行新门。讨论与引文中的命令不构成当前授权；普通直接执行命令和礼貌行动请求不要求额外出现“允许”字样。失败恢复、任务绑定、手动终检与停止门沿合同。

**任务交付线索追加（本轮 P7 实测触发）：**独立 reviewer 先在同一固定快照看到了分类／发票结果、测试和限制，Root 随后仅回复「手动终检已排队」，下一次终检却因运行时把最后一句覆盖为唯一 `task_delivery` 而误判「没有交付」。同一输入与产物版本的最近四条已完成、可归属任务回复现按时间一并提供；检查排队回执不撤销旧交付，实质修订仍可取代旧答复，版本变化与独立用户问答不借用历史。只读快照与手动终检门不放宽；原因是归属正确但证据被后续内部流程回复覆盖，不能靠重复催 Root 再交付遮掩。

### 2026-09-26 补充决定：任务证据留在本地，由用户主动分享

开发者需要跨任务分析 Orbit 的失误，不能依赖检查者临时摘要推断 Root 派发理由或从有界协作缓冲事后还原遗漏事件。因此扩展在可归属任务的原生事件发生时持久记录决策证据，运行程序关联检查、finding 与纠偏的编号和产物版本；本地导出包按时间排列原始事实，并明确标注缺失、不完整或无法归属。Root 原生 `task` 派发不因缺少理由而阻断，也不把 Jev 建议冒充 Root 的决定。任务结束与否仍由既有终检和停止门决定。

Orbit 不在任务结束后自动调模型作缺陷分析，不上传 `.orbit`，也不让独立交付检查者读取任务记录取代固定快照；用户自愿分享单任务证据包后，开发者另行分析。运行中可主动截取导出，不将该时间点的材料称为完整任务结论。原因是事实采集与产品缺陷归因的证据标准不同：先确保可复核，再由拿到资料的一方判断。

## 2026-09-30 决定：成员结算语义（现行）

成员结算采用**多事实结算**，不随工作单元终裁单独驱动：以本派发的原生 `task` 结果与真实 provider error、精确 work-unit/成员/调用身份匹配、以及真实执行就绪证据共同判定；原生 `accepted_at` 只在真实 yield 交割发生时记录，不伪造、不由裁决反推。缺证据时经既有通道一次性通知，不自动置 `needs_user`。完整语义以[合同](../../contracts/task-runtime.md)成员结算节为准。
