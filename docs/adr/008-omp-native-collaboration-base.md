## 背景与理由

Orbit 自建的执行成员没有直接使用 OMP 的 `task/hub` 协作，成员通信与唤醒仍由 Orbit 接线承担。调研显示，OMP 已提供同一进程内的原生派发、成员消息、等待和唤醒；OpenCode v2 的已发布子 Agent 能力没有同等的成员互发消息路径。继续维护多个宿主及各自成员控制路径会增加实现和升级成本。当前只有一位使用者，没有需要迁移的外部调用方。

## 已确认的决定

1. **单一宿主。** 下一版只支持 OMP。采用原版 OMP 加 Orbit 扩展；不复制 OMP 的 `task/hub` 模块，不预先维护 Fork。移除 Codex、OpenCode 等旧宿主路径时不建设兼容层或历史任务迁移；旧路径代码已移除（M3.1），历史验收证据保留在 `docs/reference/` 备查。
2. **显式会话入口与按请求建任务。** `orbit omp [OMP 原生参数]` 启动原版 OMP 并为本次 Root 会话加载 Orbit 扩展；模型、工具、权限、profile 和恢复参数仍由 OMP 处理。普通 `omp` 不接入 Orbit。会话入口只使 Root 具备接入资格，不因打开会话就创建任务；未绑定任务的新用户请求按下文 2026-09-26 的入口门自动判定或交 Root 显式决定。受控会话的恢复仍走该入口，不识别 Zeen 等具体项目。
3. **原生执行团队。** 当前面向用户的 OMP 会话担任 Root，不另建 Root。Root 显式调用 OMP 原生 `task` 派发成员，成员通过原生 `hub` 通信、回报和唤醒；Orbit 不再以自己的 SDK 成员替代原生团队。团队保持一层：只有 Root 能派发，成员不能再调用 `task` 派发或自行启动 Orbit。Root 负责核验和集成成员结果。
4. **Orbit 的职责。** Orbit 保留用户原文与有效修改、固定工作区快照、Jev 过程判断、独立检查、纠偏、状态记录和停止确认。委派建议在任务开始时有界给出，最终是否派发由 Root 决定；不使用 OMP advisor 代替 Orbit 的版本化检查，也不自动派发。用户修改要送到 Root 和相关活动成员。
5. **独立检查与模型。** 检查者使用另一 OMP 会话，读取固定快照，保持只读并独立于执行团队；裁定者同样不得参与执行团队。执行成员和检查者的模型由 OMP 配置与可用模型决定，Orbit 记录实际使用的 provider/model，不硬编码 GPT、DeepSeek、GLM、Kimi 等型号，也不把目录可见当作账号可用。
6. **登记、停止与故障。** Orbit 必须识别本任务派出的所有成员，确认其执行及原生后台工作实际结束后才报告完成或停止成功；证据不足时保留 `stop_unconfirmed`。现行“成员实际身份先持久登记、再开始模型工作”的要求不因本 ADR 放宽。OMP 或 Orbit 异常退出后不自动恢复模型执行，仍需能如实报告停止状态并按明确操作重试收尾。
7. **跟进上游。** 2026-09-26 用户将 OMP 入口版本门改为最低版本 18.2.8：等于或高于该版本允许启动，低于或无法解析的版本拒绝。更高版本通过版本门只表示可启动，不等于扩展钩子、`task/hub`、模型解析和停止路径已经逐项验收；发现实际接口变化或运行故障时，按这些接缝在隔离项目复核并修复。独立检查者的 SDK 仍精确固定 18.2.8，变更它需单独验证。若原版扩展接口经验证无法满足成员登记与控制，先确定所缺的最小上游接口；是否采用短期最小 Fork 留待有实证的阻断出现时再决定，不以复制模块绕过。

### 2026-09-26 补充决定：启动前 JEV 判定与统一判断数据模型（源码已实现；组合真实验收另记）

未绑定任务的新原生用户消息在 OMP `before_provider_request` 内已经持久化，扩展以原生消息 ID 执行有界入口判定，并在首个模型请求前通过既有 `start` 前置校验建任务：明确要求 Orbit 受控执行的请求直接走受控路径；明确讨论或只读问答不启动；其余请求由 JEV 判断执行授权与独立检查收益，只有双分数过线才自动启动。不确定、服务不可用、凭据缺失或项目禁用外发时交 Root 显式决定并给一次短提示。同一原生消息 ID 去重，用户后续改变要求按新消息重判。入口门不会自动派发 OMP 成员，也不改变独立检查、完成或停止确认。

入口门固定 TypeSafe `jev-1.13.0`，执行授权阈值 0.80、独立检查收益阈值 0.70；首轮仅以三条真实请求（明确执行 0.95/0.90、较软执行 0.55/0.75、讨论 0.07/0.67）校准，故仅高把握请求自动进入，其余保留 Root 判断。规则版本、问题集版本、消息 ID、实际模型、分数、可得用量或失败原因写入入口记录，已建任务内再保存同一判定。OMP `before_agent_start` 没有当前原生消息 ID，不作此门；`devin-agent` 类模型不触发 provider 钩子，不能声称该路径已受控。

外部判断业务依赖 Orbit 自有 `JudgmentRequest`／`JudgmentResult`：有界状态与带 ID 的二元真假标准输入，结果按 ID 返回经校验的 `[0,1]` `probability_true`、实际 provider／模型、可得用量或结构化不可用原因；部分回答不触发自动动作。TypeSafe 首个适配器负责原生协议、鉴权与超时；任务内既有问题和阈值保持原行为。新增 provider／模型须显式选择、按会触发自动动作的问题分别校准，不静默换服务或挪用分数。该 provider 选择独立于 OMP 执行／检查候选池。源码实现与真实验收边界见[任务合同](../../contracts/task-runtime.md)及[方案](../plan/orbit-omp-flow-and-model-picker-proposal-20260926.md)。

## 实现前事实缺口的关闭情况

- 成员实际身份在模型工作前持久登记：已闭合（M0）。扩展在原生 `task` 的 `tool_call` 门赋予请求名，在 AgentRegistry `registered` 窗口内经 TaskRecord 原子+目录 fsync 写入任务 `members.json`；写失败或 ID 漂移以注册表终态翻转阻断，成员不发生模型工作；真实正负样本见 [OMP 原生路径验证记录](../reference/omp-native-path-probe-20260924.md)。
- 阻止成员再次派发、观察成员/消息/实际模型/结果/后台工作：已闭合（M1.1；冻结 #3 PASS，成员→成员 idle-wake 样本 `ec90a0a9`）。一层派发由扩展在 `tool_call` 门的调用者身份校验保证（成员会话的 `task` 调用被阻断，成员也不能以 Root 身份绑定 Orbit）；`hub` 消息与 task 结果经按任务隔离的有界缓冲观察（含内容，进程内、非持久），成员源 hub 调用自 0.6.17 起记录；实际模型经注册表记录。**准确边界**：成员发起的 `hub send` 对"唤醒已停止成员"只能观察、不能在上游工具门前预阻断（OMP 18.2.8 不转发子会话 `tool_call` 门）；`hub cancel` 回执仍不作为退出证据；成员停止的准确边界：默认路径（`task.agentIdleTtlMs=0` 保持 attached）已完成成员可经桥核实并 `confirmed=true`（实测 `0bc4ec93`/B3）；仅用户显式 `--config` 覆盖或异常 park 后 session 不在时，park/dispose 无公开完成信号，桥返回结构化证据且保持 `stop_unconfirmed`。
- `orbit omp` 显式入口与普通 `omp` 零接入：已闭合（M2；冻结 #1、#8 本机 PASS）。入口透传原生参数与退出码，安装器只装受控入口、不再写全局扩展，本机旧全局扩展已清理；验收安装 0.6.18（digest `06dba0f1…`，installed_at `2026-09-24T21:55:54Z`；历史验收安装，本机当前无该安装）经 `orbit update` 与仓库外 `/` 的 `doctor`／`version` 复核，隔离前缀的"更新失败保留旧版、活租约拒绝卸载"负样本保留；普通 `omp` 的 `/tools` 无 Orbit 已在 E/H 被动实测；权限审批 parity 本机证据见验收记录。未来新 OMP 版本参数复核按决定 7 流程，非当前缺口。
- 独立 OMP 检查会话：已闭合（冻结 #6 PASS）。reviewer 以独立只读进程读取固定快照；固定快照与来源边界、confinement 专项 17/17、活 TaskRuntime adjudicator 的机械/只读/路由回路均有真实样本。**准确边界**：该活样本夹具存在 W38/W39 规格矛盾，adjudicator 裁定内容正确性不据此夹具判定，另行验证。

若任一关键接缝在 M4 验收中无法满足既定产品要求，停止该接线路径并依据证据重新裁决；不把能力缺口写成已支持。
