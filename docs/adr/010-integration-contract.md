# ADR-010：面向集成方的合同、能力协商与通用引用

- 状态：已采纳（2026-10-11，用户经协作会话转交并授权）。1.5 兼容追加公开会话绑定投影与可选续接唤醒；2026-10-16 已从隔离 Loom 实际入口完成普通路径及同 Root 续接验证。安装、历史失败与证明边界统一见[当前交接](../plan/handoff.md)，不把局部验收当作全部版本或供应商保证。
- 范围：Orbit 与外部调用方（首个是官方推荐搭配的 Loom）之间的接口承诺。具体命令、字段与取值以[集成合同](../../contracts/integration.md)和 `contracts/integration.json` 为准；任务运行语义仍以[任务运行合同](../../contracts/task-runtime.md)与 ADR-008/009 为准。

## 决定

1. **合同归 Orbit 仓库维护，版本独立。** `contracts/integration.md/.json` 带 `主版本.次版本` 的合同版本，与软件版本分开。同一主版本内只加不改不删，破坏性改动升主版本并写入发布说明。`status` 的取值集合同样冻结，新增取值按破坏性处理。
2. **只冻结一小组字段。** `status --json` 直接输出整份任务记录；整体冻结会使内部结构永远不能改。合同只列调用方实际依赖的字段，其余明确不属于合同。
3. **按能力而不是版本号判断可用。** `orbit capabilities --json` 读取 `integration.json`，只列已实际接线的能力及其限制（例如 `resume_from.from_status`）。能力来自同一份文件，契约测试读取它，不在测试里再写一份。
4. **引用是不透明的通用功能。** 检查结果每个覆盖项可带可选 `ref`，任务启动可带 `--external-ref`；Orbit 只存储、原样返回、限定长度与字符（`ref` 的空串按未提供），不解析前缀、不要求唯一或匹配，不引入交付项、权重等调用方概念，也不依赖调用方。
5. **契约测试由 Orbit 维护并随 `npm test` 运行。** 假调用方只用公开命令和声明字段，对真实 CLI、任务记录、运行时、覆盖存储、停止与导出路径运行。

## 理由

Loom 只想依赖声明过的接口，不读 `.orbit`，不 fork Orbit，也不比较软件版本。若不把合同、能力与版本规则落在 Orbit 仓库，发布会在无人知晓时破坏调用方。把引用做成通用不透明字符串，是为了让两边能像 issue/PR 那样互相查找，同时保持 Orbit 不理解调用方的业务概念。

## 有意取舍

- **`ref` 不合规视为结果契约违规**（与其他字段一致，走既有检查失败路径），不静默丢弃或截断；因此提示要求只逐字抄录、不确定就省略。
- **例外（合同 1.1，2026-10-11 用户决定）：空串或纯空白的 `ref` 按未提供处理并不保存。** 真实检查者试验（7 次调用中 1 次对 4 个项写了 `"ref": ""`）表明严格拒绝会让一次整体检查白费；空串没有携带任何可能被误读的信息，与省略等价。超长、含控制字符、非字符串仍拒绝。
- **`--resume-from` 的新任务不继承旧任务的外部引用**，调用方需重新传入；旧任务经 `continuation.previous_task` 反查。
- **2026-10-16：已确认停止的旧 `needs_user` 任务可作为 `resume_from` 来源。** 这是对接续来源的新增声明，不重解释其 status、attention 或终态含义；旧记录仍保持原状态，接续要求同一 Root、同一项目、真实原生用户消息和停止确认，并建立新任务边界。合同 `resume_from.from_status` 与能力清单共同声明支持；此前“当前不可接续”的取舍由本条部分替代。
- 自动入口（非显式 `start`）建立的任务没有外部引用；调用方若需要，另行决定是增加入队式追加命令还是让节点适配显式调用 `start`。

## 合同 1.2：外部会话与控制通道

2026-10-11 用户确认：选择进程环境变量关闭自动入口，并由调用方指定控制 socket；不建立会话登记、不提供 status --session、不隐藏 Root start。引用查询精确返回全部任务，无匹配成功返回空数组，start 不按引用去重。默认交互模式保持不变。

控制路径与 start --socket 逐字一致，不 realpath；父目录同 uid 且私有，拒绝活/未知通道，仅回收可证实的同 uid 死 socket。Node 关闭直接监听的 Unix 路径会删除调用方在该路径放置的替换文件，因此采用私有内部监听路径＋指定路径硬链接，关闭仅回收身份相符的公开 socket。代价是两目录必须同文件系统且支持 socket 硬链接；不兼容时明确拒绝。该方案已实测连通与替换文件保留。

OMP 18.9.0 实测首消息前 get_state 返回 sessionId 且控制通道已监听。该验证不认证所有 OMP 版本或其他平台。详细历史记录可从 Git 历史取回。

外部 CLI 冷启动通过现有私有通道登记精确任务，与原生工具使用同一宿主绑定；接纳前不投递指令或取得停止权。内部桥接不增加对外能力或合同版本，`start` 返回 `starting` 的异步含义不变。

## 合同 1.3：持久变更与只读摘要

用户确认 revision/updated_at、phase/needs_user，以及最近已完成检查（models 与 input_current 保留）。只冻结字段，不增加 reason_code/next_action_code、有序事件流或 needs_user 接续。

revision/updated_at 沿用唯一状态写者与既有原子 write，从已落盘语义投影比较，旧计数为权威；用量（包括检查/判断回执）、next_check_at 与读时覆盖 current/ready/gap 排除，其余持久状态计入。不另存 revision digest，避免调用方旧元数据与 JSON 键顺序影响计数；读/解析/权限/写入失败不能重置计数或覆盖坏状态。旧任务无字段读时未知，实际保存才初始化。排队、检查触发及检查完成登记属于语义变化；不能笼统排除时间戳/调度键漏掉它们。

attention 码表及优先级在集成合同冻结，以现有状态与检查/返工谓词映射；needs_user 只指已停止终态。latest_check 共享原检查身份回退，选择最后完成记录含失败/陈旧，白名单排除私有文本与路径，models 仅来自该检查回执，input_current 不代表产物有效。两个摘要只在 status 投影，不改变原始状态或 export 材料。

合同 1.3 的确定性测试和独立只读核查已完成；真实活动 tick、进程重启和模型回执仅有有界核验。合同不据此宣称所有模型检查通过。详细历史记录可从 Git 历史取回。

## 未覆盖

契约测试用 OMP Root 会话与检查模型两个替身，证明合同面与字段形状，不证明模型行为；1.2 的真实宿主会话另按上述有界验收记录。合同尚未经 Loom 自己的持续集成对 Orbit 最新版运行。

## 2026-10-12 合同 1.4：严格模型授权

新增 `model_authorization` 能力与任务字段，选择显式启动参数和可选会话启动环境上限，不建立外部供应商登记或第二授权服务。任务名单只可在新接续任务缩小，普通池保持偏好语义；Root/成员/检查者调用前守卫与可选 JEV 关闭是同一严格能力的必要组成。既有命令、字段意义和 status 码不改；软件版本与已发布身份另外报告。

## 2026-10-16 合同 1.5：会话绑定投影

阶段二 Loom 协同适配（用户授权）：首个外部消费者此前依赖未冻结内部字段 `root_session_file`、`sent_message_ids[0]` 与 `last_user_message_id`，三者都不能当稳定启动边界——原生消息启动的任务上 `sent_message_ids[0]` 是第一条纠正消息，`last_user_message_id` 随后续真实用户消息推进，`root_session_file` 只是内部观测缓存。新增只读 `session_binding` 投影（provider、session_id、session_file、launch_message_id、launch_message_source），同一主版本只加不改。

决定：缺失明确 null，不猜宿主路径；prompt-file 启动的投递边界由运行程序在 attach 投递成功时以 `state.initial_delivery` 记录一次（新任务），旧记录不借内部字段回填、launch 保持 null；原生/接续任务直接回读创建时已记录的 `instruction_source`/`continuation.source`。不建第二套存储：投影不持久化、export 不变，唯一新增持久字段是投递标记；身份、严格授权、停止门与旧字段含义全部不变。真实 Loom 消费与跨系统验证由 Root 负责；合同面与边界行为由契约测试和运行时回归覆盖。

## 2026-10-16 合同 1.5 追加：可选续接唤醒

真实 Loom 续接已恢复同一 Root 并建立新任务，但首条唤醒来自检查选型失败通知，而不是明确的续接信号。不能依赖这个副作用。新增默认关闭的 `resume_wake`：精确绑定后，经现有原生 custom message 通道发送程序通知；尝试先落盘，ACK 与未知分别记录，不自动重发，不改真实用户启动边界或停止、授权规则。具体字段见集成合同。

同次运行还暴露 CLI 未保存显式检查模型的缺陷：输入签名变化后重新选型可能掉回配置池。修复只持久保存实际显式选择，不固定自动选择，也不增加旧任务选型继承或跨池回退策略。
