# ADR-011：由 Agent 判断任务，Orbit 提供事实与执行支持

状态：2026-10-16 用户确认。Orbit 阶段一已实施；验证范围与未完成事项见[当前交接](../plan/handoff.md)。实施进度见[唯一总待办](../plan/agent-autonomy-implementation.md)，运行规则见[任务运行合同](../../contracts/task-runtime.md)。

本决定部分替代 [ADR-008](008-omp-native-collaboration-base.md) 的成员文件范围、检查取证和程序处置职责，以及 [ADR-009](009-user-selected-model-pool.md) 的交接范围约束。OMP 单宿主、原生协作、模型授权与真实停止要求保持。外部字段和状态遵守 [ADR-010](010-integration-contract.md)。

终检的默认验收范围、未检查项续查和结论沿用由 [ADR-013](013-final-review-scope-and-continuation.md) 进一步细化；本条其余职责与权限边界保持。

## 决定

- Root 决定实现、分工、纠偏、争议处理和是否需要用户介入。
- 成员自行调查，并选择完成任务所需的文件与方法。Orbit 不用预列文件名单代替成员判断。
- 检查者和裁定者独立、只读地调查相关证据。程序提供真实来源、版本和记录入口，不默认发送全部历史。
- Orbit 准确记录并传递要求、执行事实、结果和变化，再执行 Agent 的决定。程序不得把未知自动解释成失败、结果无用或必须由用户处理。
- Root 处理裁定不等于独立终检通过。授权、执行身份、独立检查和真实停止仍须分别核实。
- 明确的用户停止与授权要求继续有效。已确认的旧 `needs_user` 状态保持终态含义，通过现有续接能力处理后续任务。
- JEV 先记录完整请求、裁剪、返回和程序决定，再依据真实调用观察输入完整性与频率。不得从旧分数推断原因，或预先改阈值和严格模式。
- 检查者页面材料漏判仍未证明解决；开放读取入口不等于修复判断效果，收口条件见[缺口清单](../plan/debt-ledger.md)。

## 理由与后果

文件名单和场景专用验收规则会阻止 Agent 查找任务所需证据，也可能把可恢复的技术问题变成用户等待。由 Agent 判断能减少不必要限制，但仍可能误判，且读取更多材料可能增加单次调用成本。完整记录、Root 核对和独立检查用于发现与纠正问题；本决定不承诺取消限制即可消除漏判，也不引入自动重置系统。

本决定本身不发布新接口，也不改变机器合同。Loom 对阶段一行为的协同调整属于独立阶段，2026-10-16 已获用户实施授权；当前决定见[执行计划阶段二](../plan/agent-autonomy-implementation.md#阶段二loom-协同)，实现与验证边界见[交接](../plan/handoff.md)。兼容新增能力由集成合同与 ADR-010 裁定。
