# Orbit 用户结果补齐计划（收敛版）

状态：2026-09-18 方案稿。本文安排下一步验证与交付，不改变现行产品语义。涉及检查时机、旧结论投递、成员归属或停止范围的改变，先核对并按需更新[任务运行合同](../../contracts/task-runtime.md)与[ADR-007](../adr/007-task-runtime-refactor.md)。

## 用户结果

用户把任务交给自己惯用的 Coding Agent 后，应以合理的时间、资源和人工投入，得到符合原始意图、经过必要验证、可安全中断和接续的成果。Orbit 只有在相较 Agent 单独工作产生可观察收益时才值得增加运行机制。检查、Jev、成员和 Herdr 都是达成结果的候选手段，不以功能齐全本身作为完成条件。开发侧自行验证，不让用户承担测试。

## 当前事实与优先问题

- 源码已有 Jev 三项判断和 Codex MCP `orbit.task` 改名，已按 patch 升到 0.6.3 并本地安装；启动中的旧会话仍需重开才能加载新版。TypeSafe skill 是开发指导，不是运行时插件。
- 一次真实开发任务中，7 次已完成检查全部过期，Orbit 投递纠正为 0；记录的检查用量为 4,246,313 tokens，包含缓存口径。检查者曾提出有用问题，Root 是自行查询任务记录取得，不能把这次经历算作自动纠偏成功。详见[独立审查及复核](../reference/project-review-20260918.md)。
- 现有受控遗漏验收证明最小纠偏与停止路径可用，但还不能证明复杂日常任务普遍节省成本或减少人工介入。真实任务没有执行成员，不能由此推断跨 Agent 协作没有需求；用户明确提出 Herdr 协作缺口。
- `delegate` 已验证同宿主成员及 OpenCode Root → Codex 成员的跨宿主创建、结果回收和停止链；其他跨宿主 kind 尚未验证。Herdr 能显示 Agent，不等于 Orbit 能原生控制它；可用 kind 和授权范围必须分别核实。

切片 A 至 C 已分别验证。下一步评估切片 D 的 Jev 委派提示是否有实际收益，不把它扩成平台工程。

## 防止扩张的规则

1. 一次交付一个用户可见结果；前一段不因后续构想而保持未完成。
2. 先用已有 Root、检查者、任务记录及宿主原生接口。若一段需要多个新适配器、界面解析、双套兼容路径，或新增代码明显超过直接用户行为所需，先复审方向。
3. 记录检查是否过期、问题是否被 Root 接受、实际用量及未知部分；不设凭一次样本得出的固定节省率、纠正条数或接受率门槛。没有问题的任务不应为了达标制造纠正。
4. 旧版本检查只作为历史记录；当前合同要求重新核对变化，不能把旧 finding 直接当作当前问题投递。若要改变这一点，先明确允许的语义和风险，再修改合同与实现。
5. 少量测试覆盖关键行为，真实 Agent 和真实 Jev 验证分别说明证明范围；不得以夹具通过代替日常效果。发布、安装、推送分别记录实际结果。

## 切片 A：让检查结果有效到达 Root，并减少无效检查

- [x] 用已有任务记录复盘检查启动原因、检查者返回的 `next_check_seconds`、执行与文件变化时间、过期原因和用量。30–60 秒重启间隔是已观察到的重复触发因素；具体调度改动以此为依据。
- [x] 在保持约定时间、Root 交付检查及版本核对语义的前提下，收敛持续编辑时的重复完整检查。过期结论不直接纠正当前版本；让需要纠正的问题在新版本核对后自动送达 Root，不依赖 Root 轮询状态。
- [x] 在现有 `orbit status` 清楚显示最近检查是否过期、有无待处理问题及下次检查依据。不建新的事件总线或费用平台。

完成条件：开发侧用一条有实际问题的受控路径核对自动投递，再用代表性的持续编辑任务观察检查次数、过期原因、用量和用户可见结果。若真实任务没有问题，不要求出现纠正消息。修正仍导致大量重复过期或明显推迟重要纠偏时，停止增加调度层，重新检查检查范围和耗时。**本段独立交付，不等待 Jev 或 Herdr。**

## 切片 B：验证已写 Jev 接入的实际增益

- [x] 核对 Jev 输入保留当前有效要求。当前只取最近 20 条修改，不能仅凭这个上限宣称所有有效要求已覆盖；超出预算时明确标出省略范围，不把缺失依据的判断当问题证据。
- [x] 在最终源码上验证现有回归与普通宿主的真实 Jev 判断；观察它触发的过程检查是否给出有用发现，以及是否减少无效完整检查。服务失败应沿用既有检查路径。
- [x] 根据结果收束实现和发布准备。用户已决定以环境中的 `TYPESAFE_API_KEY` 全局启用、项目可关闭；若证据显示默认启用会明显损害效果或成本，报告事实并先修正或重新讨论该决定，不把审查建议自行改成新产品规则。（已按 patch 升到 0.6.2 并本地安装；未推送、未发布）

完成条件：新启动的日常任务能使用已配置的 key、留下可核对的 Jev 判断，且能说明新增判断的实际收益与额外消耗；`orbit.task` 可调用，安装版本可由 `orbit version --json` 核对。旧会话不冒充已更新。

## 切片 C：一条跨宿主原生成员路径

用户要的是 Root 能让已授权、实际可用的不同 Coding Agent 分工，并可靠回收与停止。首条已验收路径是 **OpenCode Root → Codex 成员**：跨宿主创建和控制由 Orbit 持有的 Codex 原生 app-server 完成，Herdr／tmux 只可用于展示，不承担成员消息、结果或停止控制。后续 kind 逐种验证，不以数量充当控制能力证据。

- [x] 首次 Herdr OpenCode 实验已记录为接口缺口：真实工作与文件结果可读，`esc` 未停止成员，`ctrl+c` 结束成员及前台进程，脱管后台服务在 pane 关闭后仍存活；该实验不证明 Orbit 已控制跨宿主成员。见[验证记录](../reference/check-loop-acceptance-20260918.md)。
- [x] 接线前明确合同与 ADR 中的跨宿主成员归属、原生停止和会话保留语义。保留现有同宿主 `delegate`；不因成员由不同宿主执行而放宽沙箱、权限或停止证据。
- [x] 接入一条最小路径：Root 在用户已允许的范围内显式指定 `kind: codex`；Orbit 为该任务启动并持有成员 app-server，记录可重连的短 socket 路径与宿主 PID／进程组，显式以项目目录创建 Codex 成员。成员记录包含 kind、连接位置、thread ID、模型和状态，并在 `turn/start` 前持久化；结果从原生会话读取，经现有 Root 通道回传。目标 Codex 模型按其自身配置或显式授权选择，不沿用 OpenCode 的 provider/model 字符串。
- [x] 分别验证成员交付与执行中中断：Root 收到并集成真实子任务结果；另一次中断后 Codex turn 与登记后台终端均确认退出，随后关闭成员 app-server 并核对其进程退出。历史与上下文保留按原生记录核实；不要求终态后成员仍在线，也不把“消息已发送”或“进程收到信号”当成停止完成。
- [x] 验证运行进程异常退出后的收尾：若成员宿主仍在，显式 `retry_stop` 能从任务记录重连、停止和核对；证据不足时保持 `stop_unconfirmed`，不能因 socket 消失就推断成员已停止。记录从成员登记、启动到停止的实际顺序；现有 `member_delegated` 事件发生在 `turn/start` 后，不拿它证明先登记。

有限停止边界沿用现行合同：只承诺本任务登记成员的原生执行及宿主能跟踪的后台工作。未经登记、脱离宿主管理的进程不自动终止；若已知有任务相关残留，报告具体事实，不能宣称整项任务已安全停止。完成条件是一条真实跨宿主派发、Root 集成和原生停止均得到确认的路径。按 kind 分别声明创建、结果回收、中断、后台跟踪和会话保留的实际能力；未验证的 kind 不列为受控。若独立成员宿主在既有 `approvalPolicy: never`、`workspace-write` 边界内无法运行或可靠停止，记录缺口，不转向 Herdr 按键、屏幕解析或更宽权限补齐。

授权来源与可用性分开：首条路径要求用户在当前任务或项目规则中允许目标 kind，Root 再显式选择；安装、登录或 Herdr 列表只说明候选可用性。用户此前提出的持久可用成员清单仍未实现，后续按实际使用需求以最小配置落实，不建设通用注册中心，也不把 Root 任意选择视为用户授权。

## 切片 D：协作路径成立后评估 Jev 委派提示

只有切片 C 证明可用成员、结果回收和原生停止后，才评估增加“当前是否可能有适合独立交付的子任务”这一窄判断。Jev 只提醒，Root 决定是否派发和选用哪个已验证、获授权的 kind。比较有、无提示时的实际分工收益与调用成本；没有可观察收益就停在 Root 手动分工，不堆阈值或路由规则。

后续接入其他 Agent kind、通用注册中心、完整跨供应商费用统计和自动 Root 替换都需要对应真实需求及原生能力证据，不属于上述切片的默认完成条件。

## 给接手实现的 Agent

- 接手时先读根 `AGENTS.md`、[开发流程](../agents/development-workflow.md)、[交接](handoff.md)、本计划及相关合同，再看 `git status` 与实际 diff；保留已有工作，不重置或覆盖。本机已安装 0.6.2，但启动中的旧宿主会话不会自动加载新版；以 `orbit version --json` 和新会话实际行为核对。
- 按 A → B → C → D 顺序交付，每段独立核对完成条件和真实证据。某段遇到明确停止条件时记录已完成、未完成及原因，不靠增加框架绕过，也不把依赖它的后续切片标成完成。实现期间只维护一份必要的总进度，不再复制计划文档。
- 在同一 pane 中使用 OpenCode 开发 Orbit，只说明实现 Agent 换成了 OpenCode；这不证明 Orbit 已能启动、回收或停止其他宿主的成员。切片 C 必须用 Orbit 登记的新 Codex 成员核对结果与原生停止，不能用当前开发 pane 充当成员；Herdr pane 只提供可选展示。
- 若实现选择会改变旧结论处理、定时检查、成员归属或停止语义，先改对应合同和 ADR，再改代码；不能为通过测试而降低原有保证。若只有少量明确用户行为需要验证，复用已有测试，不建新的测试体系。
- 每段回报源码改动、实际运行路径、检查用量和未知部分；分别说明测试、真实 Agent 验证、本机安装、提交与推送的状态。安装或切换前核对正在运行的任务与宿主会话；实现本文不自动授权推送或对外发布。
