# Orbit 日常使用交付计划

2026-09-14 用户授权列计划并跑通全流程。目标是高质量完成要求、自我纠偏、减少人工介入并按实际成本优化；Orbit 独立用于任何项目。Root 指当前执行用户任务的 Coding Agent，程序不自动更换它。

## 固定计划与验收

| 顺序 | 工作与完成条件 | 当前状态 |
| --- | --- | --- |
| 1 | 确定真实会话接入：识别原会话、读取原文、投递反馈、停止原生后台命令 | 已验证；采用用户启动入口 orbit codex，已有嵌入式会话不热迁移 |
| 2 | 安装后 skill 主动接入：自然语言执行要求，不点名 Orbit、不手填内部 ID；独立发现遗漏并由同一 Root 修正 | 真实路径通过；受控注入缺失文档，纠正后 complete |
| 3 | 必要分工：创建一个登记成员，回传并集成；用户补充要求同步；Root 中断后停止整项任务 | 真实路径通过；两个后台心跳进程均退出，会话与产物保留 |
| 4 | 普通终端、tmux、Herdr 使用同一入口；更新角色、模型、项目规则说明 | 三种入口均核对；tmux／Herdr 显式恢复同一夹具会话成功，没有重复付费任务 |
| 5 | 相关回归、安装更新、本机入口、独立核查、资源清理与记录 | 已完成；相关回归、隔离安装更新、独立核查及本机 CLI／skill 切换通过 |

验收范围固定为完整交付、协作停止和终端入口三条，不扩成全供应商矩阵。程序测试不能替代真实模型和进程验证。事实与可得用量保存在 [本轮验收数据](../reference/user-flow-acceptance-20260914.json)。

## 用户操作

安装一次后，在目标项目运行 `orbit codex`，正常给出执行要求。Agent 判断何时使用 Orbit；讨论或小修通常直接处理。模型沿用已有 Codex 配置，可单独设置 ORBIT_REVIEW_MODEL；必要成员可另选已有授权模型，单 Agent 足够时不创建成员。

原始要求、明确指定文档与后续修改原样留存；检查者看实际产物和项目规则，Root 修正并集成结果。程序按约定时间和结果节点检查，等待不调用模型；真实争议才独立裁定。用户原生中断 Root 时程序停止登记成员，不依赖 Root 再发命令。

## 已确认的技术边界

- `orbit codex` 由用户选择，用 Codex 原生 app-server 与 TUI 打开日常会话；MCP 连接避免模型 shell 沙箱的 socket 限制。只预先批准 Orbit 自己的工具，不写全局配置或扩大 shell 权限。
- `orbit start` 仍只绑定已经存在的 Root，不创建／恢复 Root。已有普通嵌入式会话不能假装热接入；用户停止当前工作后可显式 `orbit codex resume SESSION_ID`。已用夹具原会话验证恢复和原文保留，未迁移当前开发 Root。
- `delegate` 直接使用 Codex 原生后台成员；登记归属先于模型执行，结果回到 Root。外部未登记 Agent、其他供应商及脱管进程不在统一停止范围。
- Herdr、tmux 只影响终端组织，不成为运行依赖。没有 Git 和项目规范文件也能运行；无 Git 快照排除 node_modules、.venv、__pycache__。
- 停止优先于后续排队动作；Root、成员或检查者停止失败都不能冒充整项停止成功。

选择原生控制层的依据包括 [线上方案及 hcom 实测](../reference/existing-orchestrators-20260914.md)：通信成功不能证明派生进程停止。未继续叠加 acpx 或另建多供应商编排平台。

## 本轮执行约束与成本

Root 直接实现普通技术选择，仅复用本项目已有空闲 OpenCode Agent 做有界独立核查及发现项复核。真实实验使用已有 Codex／gpt-6-astra；未启动新 Goal、未提交推送、未启用新供应商。旧未提交修改和被忽略的本地资料保留。

首次估计 3–6 小时，仅作参考；完整任务供应商账单未知。交付实验用 4 次独立检查，2 次因检查期间执行变化而作废；协作实验的用量另计。缓存 tokens 包含在输入计数中，不能重复相加或当作套餐扣费。实验已证明纠偏与停止，不证明复杂项目普遍节省额度。复盘优先关注过早检查及过期检查成本，不为一次实验加统计平台。
