# Orbit 长任务优化实施

更新：2026-10-09。依据：[Beacon／Zeen 现场观察](../reference/beacon-orbit-observation-20261008.md)，问题编号沿用该文。**2026-10-09 用户正式授权 T01—T13 实施、必要验证与收尾，替代此前仅补文档阶段。** 实际 Goal 已启动且无 token 预算；完成门是全部授权修复、约定验证和自有资源收尾，不能以计划或一批测试代替。保留启动时已有四份修改与两份未跟踪文档；不更新全局安装、不推送发布。

## 目标与证据边界

让长任务在既有授权内持续推进：能执行就执行，缺必要输入就提出具体问题，收到纠正就落实到下一次动作。检查不能改变权限与要求事实；通知要简短、易懂、有一点自然的幽默；完成只覆盖实际验收过的交付，停止必须有实际确认。

观察记录已区分完整原件、程序事件、Root 自述、用户偏好和待核实推断。本方案不把三次 Zeen 任务合并成一次成功：UI 原任务暂停且总体交付未证实，发布任务暂停后存在无监督续接，最后接管任务的完成只证明其实际检查范围。Beacon 完成门的有效拦截也不证明独立审美核验充分。

实施启动源码 `0.8.2`，本次核对 HEAD 为 `dbd93aa8a8a35e0d6e8a16f5fb7259ab75ae7455`。Zeen 被观察安装为 `0.8.2`、源码同一提交、`dirty=false`、发布摘要 `bf05…`，独立检查 SDK `18.4.9`；具体原件见观察记录。旧现场不能当作未来修复版验收；实施及真实验证时重新冻结源码、安装摘要、宿主与检查 SDK。

本轮不引入新宿主、全局派发器、自动换 Root、评测平台或新权限框架，不接管 Beacon／Zeen，不重新执行其部署或使用生产凭据。既有[欠账](debt-ledger.md)的未测路径不自动全部进入本轮优化；当前现场问题及其直接影响才进入下面的工作项。

## 已有要求与已确认的续接决定

以下已有方向直接沿用，不重新征求同意：同型号跨渠道合理复用能力评测，优先具体型号再匹配基础型号，实际价格／额度／上下文限制仍取调用渠道；选型落实用户对 GPT-6.1 的偏好，但不自动禁用 GPT-6；用户明确纠正高于项目技能中的默认流程；通知简短、易懂、适度有趣；任务没有完成时应继续执行或明确问缺什么。落实模型匹配方向时需同步 [ADR-009](../adr/009-user-selected-model-pool.md) 和合同，不能把本方案当作已生效规则。

**D1：已确认采用“任务相关追问／纠正后续接”（2026-10-09）。** 用户在本次对话回复“同意你的建议”，选择原建议方案 A。决定与理由已写入 [ADR-008](../adr/008-omp-native-collaboration-base.md#2026-10-09-补充决定esc-后任务相关追问续接实施中)，目标语义见[任务运行合同](../../contracts/task-runtime.md#esc-后的任务续接)。原生中断仍当下停止受控任务；D1 新边界接线已实施，以下行为按隔离真实验收记录核对：

| 用户行为 | 后续行为 | 用户可见结果 |
| --- | --- | --- |
| Esc 后尚未再次发言 | 当下停止受控执行，不自行重启。 | 原任务暂停，成员停止状态如实显示。 |
| 追问同一任务进度／纠正做法 | 先回答，再沿可追溯原要求及最新纠正建立新的受控任务／接管边界并继续。 | 不需要再补一句“继续”；不会把旧暂停任务改写为持续受控，也不把已停成员说成仍在工作。 |

用户明确“停／先讨论／取消”必须落实；裸“继续”要找回真实原要求，不能以最近一句状态提问替换原交付。原要求加修订作为新任务输入时，需保存可追溯来源，而不是伪造一条用户消息。此次确认关闭 D1 的产品选择；2026-10-09 后续正式授权现已启动实施与隔离真实验收。

优先级：P0 为权限事实、执行闭环或交付范围错误；P1 为明确阻碍使用与协作的行为；P2 为可靠性和投入改进。编号是实施定位，不是要求同时开十三项，也不以表格完整代替逐项验证。

| 工作项／优先级／观察问题 | 责任与当前定位 | 用户可观察的完成标准 |
| --- | --- | --- |
| T01／P0／#9 权限证据失真 | Orbit 检查输入与独立裁定；`check_runner.rb` 通用数组截尾已定位，裁定还需核实快照原件投影。 | 允许路径／工具、有效要求等裁决事实保持完整或明确标为不完整；不能根据省略的权限项认定越权。反证能在对应固定快照中核实原声明，保留更正与理由，不能只靠 Root 接管绕过误报。 |

| T05／P1／#7、#10 通知与状态残留 | Orbit 用户展示、Root 协议投影和收尾同步。程序终态与 UI/TODO 是不同证据来源。 | 默认一至两句说明当前结果和下一步；用户能知道谁继续做、是否需要自己操作。技术字段／内部命令留给 Root 或按需详情；停止确认前不能说已停止。完成后 queued／blocked 等旧状态不继续冒充当前状态；用轻松措辞，不拿未知失败开玩笑。 |

| T11／P2／#5 已知检查不可用与格式失败 | Orbit 失败分类／记忆、检查模型与外部服务分别归因。重复余额不足 402 被分为 unavailable 已定位。 | 已观测的明确账户余额／额度失败不会仅因产物更新又被盲试；存在实际恢复依据后才重新考虑。短暂网络失败不永久禁用。格式失败如实记录并按现有有界恢复处理，不为了拿 pass 无限重试或改写失败标签。 |

## 用户通知示例与边界

以下是表达方向，不是无条件模板。每句话必须对应真实状态；用户纠正已确认，不再反复问“要不要继续”。

| 实际状态 | 用户可见示例 | Root 仍需拿到的信息 |
| --- | --- | --- |
| 活动任务未完，确实开始补证 | “还差真机截图，我继续补。” | 当前缺哪项、可执行动作与证据位置。 |
| 代码已交付，独立检查确实在途 | “代码已交付，正在独立检查。” | 在途检查身份、快照与当前版本；不反复发起检查。 |
| 缺不可替代的用户输入 | “缺测试账号，登录验收暂时卡住。请提供账号或指定替代验收方式。” | 具体缺口、已尝试的恢复与实际停止状态；不能无声闲置。 |
| 范围已验收且执行已确认停止 | “这单验收通过，进程也下班了。” | 实际验收范围、确认停止结果；若只完成子范围，同时说明总任务剩余。 |
| 原任务已暂停，成员已停止 | “原任务已暂停，成员也已停止。” | 原要求、最新纠正、接管资格；任务相关追问先答后续接，明确暂停与独立问题按 D1 保持边界。 |

减少重复通知按事实变化处理，不能靠隐藏真实错误改善观感。用户通常不需要任务 UUID、`task_delivery=null`、action/intent 差别或 CLI 命令；这些仍是 Root 必须处理的协议。幽默以清楚为先，不设机械字数评分，不用一句玩笑掩盖暂停或未完成。

## 实施顺序与冻结验收

1. 第一批恢复信任与执行闭环：T01、T02、T03、T05。T13 的非敏感探查与工具纪律可同时落实到相关 Root 指引。首先证明“事实不失真、任务实际推进、纠正有落实、通知看得懂”。
2. 第二批补协作接缝：T04、T06、T07、T08、T09、T10。T04 依照已确认 D1 实现停止与续接，先保证原要求、修订来源和成员实际状态。涉及生命周期、输入来源或型号匹配语义时同步权威合同／ADR，再实现。
3. 第三批减少重复成本：T11、T12；不把优化检查频次放在权限事实保护之前。可先修已定位的失败分类问题，不建设统计平台。

每批开始实现时冻结所选工作项、上述用户行为、变更范围和真实验证场景。代码实现、确定性验证、真实路径验证、安装发布分别记录；不因测试通过就将现场问题全部标为已解决，也不在收尾时不断加入其他历史组合。

先运行改动相关的已有测试，再补少量历史回归行为。下面列的是应证明的风险，不要求一行一测试；默认遵守根 AGENTS.md 的新增测试数量／规模建议，超过需说明必要性。

| 风险 | 最小有价值验证 |
| --- | --- |
| 权限被截短后误报 | 用本次六路径／五工具形状和大输入复现，验证前部允许项仍能裁决；若无法完整提供必须显式缺证。对固定快照中的原声明提交反证，验证裁定更正而非靠成员改任务绕开。 |
| 活动任务 idle、有效 continue、没有 finding | 验证实际唤醒及后续动作，同时覆盖已经 working、检查在途、已暂停的“不重复／不越界”行为；不把通知发送成功作为执行成功。 |
| 修订、交付归属、暂停后续接 | 验证原要求加最新纠正影响执行与交付版本；独立问题不改原要求。明确继续与 Esc 后任务相关追问／纠正均建立新监督边界，先回答再执行，已停止成员状态正确；明确暂停保持停止。 |
| 完成与展示不一致 | 验证在途检查、缺覆盖、停止未确认、终态四种真实状态的用户文案与 Root 协议；完整覆盖与实际停止门保持有效。 |
| 工作单元和派发接缝 | Root 自执行能够合法收口；显式模型覆盖按实际请求校验；合理权限拒绝保留，能力不匹配及超时不会冒充成功登记。 |
| 动态来源与外部失败 | 匹配规则用受控样本验证，不固化实时榜分／价格；已知账户失败跨产物版本保留、有依据恢复与临时网络失败区分。 |

模型实际行为还需真实路径补证。实施后使用本仓 [orbit-real-acceptance](../../.agents/skills/orbit-real-acceptance/SKILL.md)：通过 Herdr 在隔离临时 Git 项目启动新安装的 `orbit omp`，控制者只发送真实需求与用户纠正，不替 Root 实现、注入假 Jev／finding／检查结果。执行成员必须走 native task/hub，独立检查必须是固定快照上的独立只读 OMP，最终验证实际停止及所属异步工作收尾。实际运行时加载完整 skill，按变更选择其适用场景，并提前冻结范围。

必要的真实场景按所实施内容选取，每条路径独立记录，不能一单成功替代所有分支：

- **推进与纠正**：有界真实交付中观察未完成状态、通知后实际执行及有效用户纠正。独立视觉验证只有在检查者真的看过图时才能计入；未自然触发 continue／finding 的路径标未验证，不事后伪造卡点。
- **停止与续接**：真实 native Esc 后确认成员停止，再按 D1／明确继续建立新任务，原交付和最新纠正不丢；另验明确暂停后不会重启。正常退出的停止证据按 skill 的适用场景保留，不能由 Esc 结果推断。
