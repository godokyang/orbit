- [x] 原生插件取得会话身份；普通 `opencode -s` 无端口恢复后可通过插件 SDK 读回同一会话和原文。
- [x] 原始执行要求未点名 Orbit，Agent 根据夹具规则及工具说明主动调用实验工具，绑定当前会话；这不等于现行产品 skill 已支持 OpenCode。
- [x] 一个成员验证正常／空白输入，结果回传原 Root 并被集成。受控删除 USAGE.md 后，既有 Orbit 独立检查发现遗漏，同一 Root 补回，最终固定副本复核 complete；前后检查均核对内容版本一致。
- [x] 原生 TUI 中断命令经官方接口触发，实验控制程序观察到 MessageAbortedError，自动取消登记成员；四个实际进程退出、心跳不再增长、两段会话及原文保留。

接入结论：优先复用 OpenCode 官方插件与原生客户端，沿用用户会话。Root 的 parentID 关系不等于团队停止，Orbit 仍需登记成员并负责收尾。成功实验使用显式端口完成外部控制；无端口只验证了原生插件 SDK 读取与恢复，其默认 URL 不能当作外部控制端点。生产接入仍需落实两者之间的通信，不能直接宣布所有日常入口已受控。

供应商辨识已纠正：先前测试的 `deepseek-v4-flash` 与本机实际成功使用的 `deepseek-v4.1-flash` 是不同 ID。Go 的 V4 返回地区 opt-in 错误，V4.1 实测成功；不应据前者要求用户修改当前可用配置。直连／Zen 的余额错误保留在验证记录，不再作为当前阻断。恢复时界面模型名称与实际请求供应商曾不一致，原生请求明确传入模型后按响应字段确认。

当时边界：这是受控遗漏和最小实验接线，不是生产 TaskRuntime 的 OpenCode 验收，也未证明自然遗漏率或普遍省额度。安装、现行 skill、无端口完整流程、定时／旧结果处理、用户修改、争议裁定及跨供应商成员尚未接入。下一阶段按本次真实差异提取必要接口，不扩成供应商组合测试矩阵。
