## 实现边界

- 第一实现仅接入已有的、仍加载在 Codex Unix app-server 中且具备历史读取能力的会话。普通 embedded TUI、ephemeral 或尚未物化的会话明确报错；不自动启动 daemon，不静默 resume 或退化为仅消息排队。
- 原生 Unix 端点使用 WebSocket；通过一个小型 Node 桥复用 `ws`，Ruby 管理任务逻辑。唯一新增 npm 运行依赖为 `ws`。
- 检查默认只读固定副本。首个代表性产物、实际交付与约定时间触发检查；旧版本结论不能控制新版本。同一问题先修正或补事实，真实争议才裁定，不投票。
- 停止确认覆盖绑定 Root 的当前执行与 Codex 登记的后台终端；脱离原生管理的 daemon/process group 不在已确认范围。Task 不控制无关会话。
- 原始执行文本和明确修改保存于任务记录，指定依据文件保留内容版本。没有额外需求表、receipt 链或测试数量／重试次数硬门。
- 时间和 token 预估不是上限。只有用户明确给出的 deadline 才产生时间停止。记录可得消耗；Root 会话累计量可能包含之前工作，不冒充本任务总量。
