# Orbit 当前计划

## 目标与依据

高质量完成用户需求，能发现并纠正偏差，减少人工介入，并根据实际结果优化供应商消耗。Orbit 独立用于任何项目，其他工具可通过同一入口调用。当前决定由 [ADR-007](../adr/007-task-runtime-refactor.md) 和 [任务运行合同](../../contracts/task-runtime.md) 维护。

## 已完成的范围

2026-09-14 已完成独立任务进程、原文和指定依据留存、实际内容快照、约定时间检查、向已有主执行 Agent（Root）投递纠正、按需独立裁定、原生停止确认，以及 CLI、skill、角色规则和模型配置说明。旧运行架构已直接删除，无兼容层。

冻结的两条真实验收均通过：遗漏被独立发现并由原 Root 修正；明确截止后实际停止相关执行且上下文保留。确定性测试另外验证版本失效、误报裁定、等待不唤醒模型和停止未确认。完整事实与时间／用量复盘见 [验收记录](../reference/orbit-runtime-acceptance-20260914.md)。

文档清理已完成：现行设计、使用入口、开发规范和验收事实保留；旧阶段和重复材料退出当前目录。后续不重新执行旧阶段，也不为证明这次文档清理重跑模型实验。

## 已完成：安装、更新与版本管理

用户同意先补齐这一范围，由 Root 实现、现有 OpenCode Agent 独立核查。未启动日常会话接入、未改本机全局安装、未发布 npm 包。初始预估 30–60 分钟，未取得整次供应商用量，不据此声称节约额度。用户要求的 upstream 子模块已移除。

- 统一版本来源，提供命令查询；安装记录版本、来源提交和本地修改状态。
- 远程源码固定到一次解析得到的提交；完整准备并验证新版后切换入口，失败保留旧版。
- CLI 与 skill 共用版本切换，清理淘汰的安装文件，卸载保留用户资料。
- 冻结四条验收：首次安装、成功更新、更新失败保留旧版、卸载保留用户资料。另运行已有相关测试和版本／包内容检查，不新增模型实验。

当前状态：四条安装路径、版本／包内容校验、原有相关测试与 skill 校验通过。事实见验收记录的“安装与版本管理补齐”；提交及远端同步状态以 Git 为准。
