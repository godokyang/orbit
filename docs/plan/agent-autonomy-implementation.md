# Orbit 当前需求与待办

产品行为以[任务运行合同](../../contracts/task-runtime.md)为准，公开接口以[集成合同](../../contracts/integration.md)为准。

## 已确认需求

- JEV 按入口、观察、成员选型和检查者选型分别组织输入；仅两类选型按需压缩，保留必要信息，复用缓存及在途请求。Root 决定提交终检，JEV 不判断成果就绪。理由见 [ADR-012](../adr/012-jev-purpose-specific-input-and-compaction.md)。
- 默认终检聚焦功能、关键安全边界和必要验证；明确要求的文档、权限、资源及报告仍须验收。未检查项由检查者续查，缺证和缺陷交 Root 处理。同版本有效结论可沿用，反证撤销旧结论，跨版本不得自动继承完成资格。理由见 [ADR-013](../adr/013-final-review-scope-and-continuation.md)。
- 执行者与检查者候选池分离；程序不自动更换 Root 型号，不越过用户模型授权。理由见 [ADR-009](../adr/009-user-selected-model-pool.md) 与 [ADR-011](../adr/011-agent-autonomy-and-runtime-responsibility.md)。

### Loom 协同边界

- 仅适配 Loom 的实证缺口；Orbit 只补兼容公开能力，不改 Zeen，不发布或部署。提交与推送按功能验收后的用户另行授权执行。
- 已确认停止的公开可续接任务在同一业务 run/attempt 内追加监督绑定历史，不增加或扣减尝试额度；保存答复与显式续接分开。
- 核对同 Root、项目、真实原生用户输入、停止与严格授权；未知停止或未知接收结果不得放行第二写者或盲目重发。
- 新监督边界重新取得自检、独立检查、候选及业务验收；旧终态、问答与证据保留，但不冒用其当前资格。
- 通过公开 `session_binding` 与宿主接口取得原生身份、记录路径和启动边界；外部接续协商可选 `resume_wake`，原生 ACK 不等于执行或采用。
- Loom 严格路径继续关闭 JEV，保留显式检查模型和当前 Root 型号，不强加角色池配置或界面。

### DSH 迁移准备（2026-10-20）

- 当前授权：迁移前期准备与文档完善。用户已选择本次迁移重写 TypeScript/Node.js Core，随后明确“先继续完善文档”；联合复核后另行授权将这批文档提交并推送到新分支。不开始重写实施或 P3，不安装或发布。
- 工作区、分支与基线只在[交接](handoff.md#dsh-迁移工作区)维护；协作流程在[多 Agent 专题](dsh-collaboration.md)，跨功能处置与遗漏在[能力整合与源码复核](dsh-capability-consolidation.md)，不另建迁移总待办。
- 当前准备项已落实：独立 worktree、版本化专题、流程与待验证接缝、导航及交接均已落盘。源码 CLI 冒烟通过；文档链接检查未新增断链，基线已有 3 处断链保持不动。上述准备不代表 P3 已实施或 DSH 能力已验证。

- R1 联合复核已落实：用户指定的隔壁 OMP 先独立审查，再与 Root 交换源码反例，并明确确认当时合并稿 R1；功能处置、双方差异与兼容路线见能力整合专题 C1–C15。R1 合并时核验了 9 个本地及 31 个固定上游引用；它们不覆盖后续文档变更，当前验证记录见交接。剩余运行实证条件随各项维护，不代表 P3 或 DSH 真实验收完成。

#### 已确认的迁移产品目标

2026-10-20 用户确认以下目标并授权落盘；实施与真实验收均未开始。它们是正式迁移需要保持的产品能力，不因 P3 探针采用较小支持集合而删减；本次不启动 P3，也不修改现行 OMP 合同。设计理由及 DSH 资料见[产品定位补充](dsh-capability-consolidation.md#用户确认补充独立使用应用入口与证据反馈)。

| 已确认目标 | 迁移后的通过信号 |
| --- | --- |
| 保留独立 Coding Agent 使用方式 | 不启动或依赖 Loom，用户能直接提出开发要求，由 Orbit 组织代码执行、必要的成员协作、独立检查和交付；状态与真实停止可核对。“独立”不要求自建模型/工具执行引擎，也不要求新增 TUI |
| 在 DSH 应用内提供 Orbit 受控入口 | 已加载 Orbit 宿主插件的应用可创建受控会话，处理输入/答复并展示任务、成员、检查发现、交付与停止状态；界面状态来自真实运行记录。仅命名 preset、提示词或 UI 开关不算接入；活动任务退出受控模式不能绕过停止确认。Web 原生扩展基础与桌面应用加载分别验证，普通 DSH 会话不自动受控 |
| 保留 Orbit 证据与反馈闭环 | 独立入口与 Loom 入口均按同一任务规则关联要求/修订、工作单元、真实调用与产物版本、检查/纠偏/结果及可得用量；缺失保持未知，证据可追溯、可导出供复盘。延续本地留存、用户主动分享，不自动上传 `.orbit`，不把 DSH 遥测当 Orbit 反馈；不宣称已实现自动训练或策略自动优化 |

待实施/验证：上述三条的真实用户路径、DSH 应用接入和证据连续性；仍由本总待办管理，当前只完成目标与验收条件落盘。

#### TypeScript 重写目标与边界

2026-10-20 用户选择本次迁移统一 TypeScript/Node.js，替代此前长期保留 Ruby Core 的路线；理由与替代关系见 [ADR-015](../adr/015-typescript-core-and-dsh-migration.md)。这不是对当前实现已完成的声明。

- 目标交付为 TypeScript Core、DSH 宿主插件及应用受控入口；Core、执行会话和独立检查者仍保留各自职责与必要进程隔离。
- 上述三项产品目标及现行监督、模型授权、JEV、证据和公开合同义务完整保留。新核心不能以调用旧 Ruby Core 作为功能实现，不因重写缩减受控交付能力。
- 保留历史任务和导出读取、来源/版本/摘要及错误语义；不强迁旧记录、不跨宿主伪续接。新旧核心不能同时写同一任务，切换先确认旧执行停止，验收后退场被替代的 Ruby/OMP 路径及运行依赖。
- 分段完成真实用户行为，不按 Ruby 文件逐行翻译；复用 DSH 已有执行原语。旧实现只作行为参照，不把旧测试通过当成 TypeScript/DSH 已通过。
- 范围映射与切换通过信号集中在[重写与切换条件](dsh-capability-consolidation.md#typescript-重写与切换条件)。原 R1 的联合确认只覆盖当时版本，不替代对新路线的后续验证。
