# 宿主一致性测试方案（草案）

状态：草案，2026-10-19，**未生效**。配套 [ADR-014](../adr/014-host-port-interface.md) 与[宿主接口合同](../../contracts/host-port.md)。本文件只定义测试范围与判定，不改变任何运行语义。

## 1. 目的

把“某个宿主能不能承载受控任务”从口头判断变成一组可重跑的探针：

- 新宿主接入前，用它决定哪些义务满足、哪些功能必须关闭；
- 宿主版本升级时，用它替代逐版本手工复核；
- 失败时给出具体义务编号，不笼统说“不兼容”。

## 2. 来源

现有探针不新造一套，按三个来源合并：

| 来源 | 覆盖 |
| --- | --- |
| 安装器的可信扩展能力探针 | 扩展是否加载、基本钩子是否存在 |
| `tests/omp_*_test.mjs` | 宿主内拦截、登记、回执、停止 |
| Loom 的 `rpc/probe.py`、`orbit/probe.py` | 会话读取、提问、状态 |

## 3. 目录与运行

以下目录与 Ruby 入口是原草案，保留供理解已有探针来源；不作为 [ADR-015](../adr/015-typescript-core-and-dsh-migration.md)的新核心目标。迁移后的主入口与报告实现采用 TypeScript/Node.js，具体文件和测试工具在实施设计时确定，不现在创建。新运行时必须通过自身的合同与行为检查，不能只跑旧 Ruby 测试；真实模型组的证据边界不变。

```text
tests/host_conformance/
├── zero_model/     # 不需要模型调用
├── real_model/     # 需要真实模型与可运行宿主
└── report.rb       # 汇总为 JSON 与人类可读摘要
```

- 原草案入口（历史）：`tests/host_conformance_test.rb`，曾计划与现有 Ruby 测试一起跑；不是新核心的执行指令。
- 迁移后入口：TypeScript/Node.js；具体目录、工具与报告接线待实施设计，不能以旧 Ruby 入口通过代替新运行时验证。
- 零模型组默认运行；真实模型组要求 `ORBIT_REAL_ACCEPTANCE=1`，否则记为 `skipped`，不记为通过。
- 每组探针独立，单项失败不阻断其余探针，但总体结论为失败。
- 不使用重试掩盖失败；瞬时错误如实记 `error`。

## 4. 零模型探针

| 编号 | 探针 | 通过条件 |
| --- | --- | --- |
| Z1 | `session_state` | 返回 `cwd` 且为绝对路径；同一会话重复读取身份一致 |
| Z2 | `model_catalog` | `current` 与 `available` 非空；id 符合 `provider/id`；不返回凭据 |
| Z3 | `bind_task` | 回显 `task_directory`；绑定后可读取该任务 |
| Z4 | `stop_root`（空闲） | 无在途工作时返回 `confirmed: true` |
| Z5 | `messages` | 两次读取的稳定 id 一致；`internal` 消息不被当成用户消息 |
| Z6 | 合同声明 | 适配层声明 `host-port` 版本；核心拒绝未声明版本 |
| Z7 | 失败语义 | 非法方法、非法参数、越界 id 返回 `error`，不崩溃、不合成结果 |

## 5. 真实模型探针

| 编号 | 义务 | 场景 | 通过条件 |
| --- | --- | --- | --- |
| R1 | H4 | 让成员登记失败 | 成员的第一步模型调用被拦住，任务不进入执行 |
| R2 | H5 | 带运行中成员和名下后台任务时停止 | 只有成员与后台任务都结束后才 `confirmed: true`；否则 `false` |
| R3 | H7 | 检查者在只读会话里尝试写 | 写入被拒绝；读取固定快照成功 |
| R4 | H6 | 一次真实模型调用 | 回执含实际型号、用量、时间；缺失字段如实为空 |
| R5 | H3 | 成员尝试再派成员 | 被拒绝并记录原因 |
| R6 | H2 | 一轮真实对话 | 有效要求被投影；状态摘要按轮注入 |

真实部分按 `.agents/skills/orbit-real-acceptance` 执行，保留实际回执。

## 6. 报告

```json
{
  "host": "omp",
  "host_version": "18.10.1",
  "contract": "1.0",
  "started_at": "…",
  "passed": ["Z1", "Z2"],
  "failed": [{ "id": "R2", "obligation": "H5", "reason": "…" }],
  "skipped": ["R1"],
  "conclusion": "pass | fail | incomplete"
}
```

- `incomplete` 表示真实模型组未运行，不能当作通过。
- 报告附在发布记录或升级说明里；不写入任务记录。

## 7. 失败处理

| 失败类型 | 处理 |
| --- | --- |
| 必需义务（H2–H7）失败 | 该宿主不能承载受控任务；接入中止 |
| 可选义务（H1、O1–O4）失败 | 关闭对应功能，在状态与记录中写明；不静默降级 |
| 探针自身错误 | 记为 `error`，不记为通过；区分宿主缺陷与测试缺陷 |

## 8. 升级流程

1. 宿主版本变化时先跑零模型组；失败即停止升级。
2. 零模型通过后跑真实模型组；失败按义务编号定位。
3. 报告与版本号一起保存；没有报告不声称兼容。
