# Orbit 当前限制

最后核对：2026-09-29。这里只保留当前使用或交付仍受影响的缺口；认可方案的逐项改造维护在[代码审计](mixed-model-delivery-code-audit.md)，不在这里另建队列。现行行为见[合同](../../contracts/task-runtime.md)及 ADR-008/009。已结束 M4 的冻结判定和例外见[历史验收](../reference/omp-native-m4-acceptance-20260924.md)。

| 限制 | 当前影响 | 解除条件 |
| --- | --- | --- |
| park/dispose 后退出不可证实 | 默认 `task.agentIdleTtlMs=0` 保持 session attached 的已完成成员可核对；用户覆盖或异常 park 后失去 session，不能把 idle、cancel 回执当退出，保留 `stop_unconfirmed` | 上游提供 dispose 完成信号并验证对应真实路径 |
| 异常退出时协作日志仍可能缺失 | 可归属事件已另写 `collaboration.jsonl`，但异步写入未完成、写入失败和旧任务仍可能不完整；导出必须显示缺口 | 可恢复事件流或同步确认边界，并完成真实异常退出验证 |
| 上游 provider 与控制钩子有缺口 | `devin-agent` 类不触发 `before_provider_request`；部分异常不能可靠 fail-close。单成员编程 kill、已 park 工作和保留名称碰撞也受上游接口限制 | 实证确认所缺的最小接口，按 ADR-008 跟进，不预维护 Fork |
| 自动入口失败时未知请求体 | 已核对的 OMP messages / Responses 可传恢复提示；不能安全识别的请求体仍中止，不能声称普通执行已可恢复 | 取得实际请求体与返回契约并完成隔离验证 |
| 历史读取有前置条件 | 需要已加载且具备历史读取能力的持久会话；ephemeral 或未物化会话不支持 | 原生接口具备能力且有明确需求后再适配 |
| 新入口与质量题义尚未校准 | 现入口仍只判独立检查收益；新方向改变题义后，旧分数与样本不能证明召回、准确度或自动正向推荐有效 | 按主方案预先标注真实任务及失败样本，升问题版本并形成放行依据 |
| 整次任务费用与用量归属可能未知 | session-summary 可汇总可得记录；失败检查 usage、Root/成员归属、实际路由价格和订阅消耗仍可能未知。交叉输入/输出单价不能直接判总成本 | 可核验本路由价格/额度规则及同任务归属；未知预算按主方案退化，不用 OpenRouter 报价代替 |
| 独立检查投入仍高且净收益有限 | 历史样本有数万至数十万 input token；少数完整闭环不证明复杂任务普遍省顶级额度或减少介入 | 同条件比较整体交付、返工、核验和人工投入；压缩同时核对缺陷发现率与 stale 行为 |
| 真实验证尚未覆盖所有分支 | 同版本 repeat/reopen 只有确定性回归；部分矛盾夹具只证明裁定机械/只读回路。旧授权例外已撤销，不再列为当前验收条件 | 保留各报告未测边界，有真实业务需求再验证相应现行路径，不重复已结束迁移 |
| 工作区冲突不自动暂停检查 | 程序不会检测 Root 声明产物位置与绑定是否冲突，也不据此暂停 | 单独明确检测与暂停语义并取得真实路径证据 |
| 语义同义 finding 不自动合并 | 依赖检查者复用已有 id，不靠程序猜测不同 id 语义相同 | 有实际重复误报证据后再决定显式对照方案 |
| OpenRouter 覆盖与路由核验不足 | 四条模型版本对应不证明完整 OMP 路由；K3 映射 `billing_route=unknown`，真实路由可能不同。当前 coding 非空门、缺失 intelligence 缓存及测量日期会限制任务相关先验 | 按主方案 §8/§10 逐候选核实身份、扩展任务指标与 schema、审计覆盖和冲突；不得伪改路由命中 |
| 有池成员默认门与检查者兜底缺少新方向实机验证 | 历史池外默认失败和 fallback 成功各有样本，但不能证明当前多型号优选、真实费用或成员 OpenRouter 选型已闭合 | 在真实可用配置中按新题义验证派发、实际身份、完整交付和成本；失败保留，不能由别的夹具倒推 |

Root 故障只记录，不自动替换或恢复模型执行。新供应商、全局调度和复杂统计平台没有因列入限制而获得实施授权。退役 Codex/OpenCode 路径的旧欠账仅供 Git 与历史证据查阅。
