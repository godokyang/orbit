# OMP 原生协作路径验证

状态：最小路径原型与实跑已完成（2026-09-24）；正式接线的登记异常保证仍待闭合。结果见[验证记录](../reference/omp-native-path-probe-20260924.md)。依据：[ADR-008](../adr/008-omp-native-collaboration-base.md)。本票只验证目标架构能否安全接线，不迁移正式运行合同或删除既有宿主。

## 目标与完成条件

在隔离项目和独立 OMP profile 中给出可运行的最小路径及证据：

1. `orbit omp` 透明启动原版 OMP 并接入 Orbit；普通 `omp` 保持不接入，原生参数和恢复可用。
2. Root 调用 OMP 原生 `task` 派一名成员，原生 `hub` 可通信／唤醒，结果回到 Root；成员不能继续派发。
3. Orbit 能在成员模型工作前持久登记其真实身份，并在停止时核对成员与原生后台工作实际结束；证据不足不得宣称停止成功。
4. 独立 OMP 检查会话能只读固定快照，不进入执行团队。

若任一必要条件在原版 OMP 的正式扩展接口下不可满足，记录具体接口缺口及最小备选，不把失败路径写成通过，也不放宽当前合同。

## 范围与顺序

- 先核对本机 OMP 18.2.8 的扩展与 `task/hub` 接缝，做最窄的可运行试验。
- 再实现必要的隔离验证代码，并跑一次有模型的原生协作、停止与检查链路。只使用已配置且用户已列出的模型；实际可用性按运行结果判断。
- 本轮不全量迁移 TaskRuntime、不卸载或修改本机全局 OMP、不发布／推送，也不为旧宿主增加新能力。

分工：当前 Root 负责接缝裁决、代码审查与组合验收；同一 Herdr tab 的 OMP 负责原生 `task/hub` 隔离实验，OpenCode 负责 `orbit omp` 入口原型，Cursor Agent 负责独立 OMP 检查会话实验。各自仅写分配的文件，避免并行修改同一接缝。可用模型候选为用户列出的 GPT、DeepSeek、GLM、Kimi；具体凭据／额度未知。现行程序及文档改动保留，不覆盖用户已有工作树。
