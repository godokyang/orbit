# Orbit 当前交接

最后核对：2026-10-16。源码版本以 `package.json` 为准，用户安装版以 `orbit version --json` 为准。真实模型隔离验收使用 Orbit 0.8.11 与 OMP 18.9.0。

## 当前状态

- Agent 自主调查的阶段一改动已实施。执行者与检查者候选池已拆分，CLI 和 `/orbit-models` 已接入角色编辑。当前规则见[运行合同](../../contracts/task-runtime.md)、[集成合同](../../contracts/integration.md)与 [ADR-009](../adr/009-user-selected-model-pool.md)。
- Root 阶段换模和程序自动换模入口已移除，用户仍可通过 OMP 原生 `/model` 主动切换；执行者配置空池或全部不可用时，原生派发门拒绝默认或池外回退。协作状态明确区分未配置、继承候选和已配置空池。
- 独立复核已按原 7 项验收核对实现与证据，本次范围内无未关闭阻断。
- 0.8.13 修复 CLI 启动依赖：原始响应使用 Ruby 内置 `pack("m0")` 编码，移除 `base64` gem 依赖，保留 `--disable-gems` 启动方式。
- 后续工作统一见[总待办](agent-autonomy-implementation.md)与[缺口清单](debt-ledger.md)。Loom 阶段二等待用户另行通知。

## 验证结论与边界

- 自动化：候选池迁移、角色隔离、空池回退、显式检查模型、CLI 与 UI 操作检查通过。Root 换模与派发门修复后全量 `npm test` 通过；后续状态显示、双池重叠断言和提示修正完成 CLI、原生宿主门、检查者选型、入口恢复与模型池 UI 的专项复验。该轮全量测试临时添加了本机 base64 gem 路径，并使用仓库声明的 Zod 4；测试后已恢复原依赖目录。该结果不能证明无环境覆盖的安装可用性。
- 启动修复验证：清除 `RUBYOPT`、`RUBYLIB` 后，JEV 响应编码、用量记录及安装生命周期回归通过，本机实际 `orbit update` 成功。安装测试固定清除这两个变量，防止开发环境掩盖缺失依赖；此项验证未调用真实模型。
- 真实运行：隔离安装下完成负例、原生成员交付正例、Root 集成、独立检查、成员在场中断和停止确认。结论限于该构建与 OMP 版本，不证明所有模型的质量。
- 真实界面：已操作角色选择、执行者列表、搜索、Space 勾选和 Esc 取消，并核对取消后两池未改变、Root 模型标题未变。检查者列表未做同等手动操作；自动选型已由自动化与真实任务覆盖。
- 静态检查：语法、打包预检、文档本地链接与差异空白检查通过。最终 Root 模型边界与空池派发修复使用自动化验证，未重新运行真实模型；此前真实验收不作为这两个分支的证明。

项目开发规范见 [AGENTS.md](../../AGENTS.md)；产品语义以合同与 ADR 为准。
