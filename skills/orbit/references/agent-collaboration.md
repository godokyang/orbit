# 执行成员

Root 是当前负责整项用户任务的 Agent。用户授权、目标项目规则与宿主权限继续适用；角色名称不增加授权。

优先使用 Orbit 的 `delegate` 工具动作（CLI 等价为 `orbit delegate TASK --file FILE`）。这条路径直接使用 Root 所在宿主的原生后台会话（Codex、OpenCode 或 OMP），不需要 Herdr 或 tmux，不复制 Root 的整段聊天。程序先登记成员归属再启动执行，附上原始要求和有效修改，回收结果到当前 Root，并核实成员后台命令已停止。

Root 决定必要分工，说明目标、文件边界、允许的资源和最小验收；避免成员同时修改同一文件。使用 `member` 参数复用本任务已有成员，不能拿其他项目的空闲会话充数。在用户已允许的范围内，`kind: codex` 由 Orbit 为本任务启动并持有独立 Codex 成员宿主（当前支持 OpenCode Root）：先持久登记短控制 socket、宿主 PID／进程组和 thread ID 再启动，模型取自 Codex 配置或显式 `model`，停止覆盖成员 turn、后台终端和宿主进程退出。Codex 成员默认使用检查模型，在工作区写入沙箱下执行，不申请权限升级；OpenCode 成员默认沿用 Root 的模型和 variant，沿用项目及 Root 权限，并禁用再次派发和启动 Orbit。OMP 成员沿用当前模型、thinking 和有效权限配置，只开放 Root 当前启用的基础编码工具，不复制扩展、MCP 或委派工具。OMP 的 `hub wait` 不等待 Orbit 回报；交给 Orbit 自动投递，准备好后结束当前轮次。Root 可以指定该宿主已有授权中的 `model`。Root 负责核验和集成，独立检查者负责整项要求核对，成员不再派发或启动 Orbit。

用户直接补充要求时，程序记录原文并转发给活动成员；Root 判断哪些产物需要返工。Root 被原生中断时，程序直接停止全部登记成员，不依赖被中断的 Root 再发收尾命令。

用户明确指定其他协作工具时，先加载对应工具说明，再发现和操作本任务已授权的成员；仅检测到 `HERDR_ENV` 或 `TMUX` 不等于授权控制其他会话。Herdr 用本机 herdr skill，tmux 用本机命令说明，不在 Orbit 中复制其操作手册。外部成员当前没有登记入口，Orbit 的停止确认不覆盖它们；用户要求统一停止的任务应使用上述受控成员通道，不能静默换成外部协作。
