# 停下与交接

**所有权边界**：本文拥有共用职责、何时必须停下、交给谁、交什么。各任务规则拥有本主题的独特判据。程序整理内部记录，模型不做字段劳动。

本文是判断依据，不是可以机械勾选的清单。

## 目标和现状

目标和授权看用户原始执行指令、其指定文档，以及用户明确修改。当前是否做到看实际代码、diff、测试和产物。模型计划或摘要不能替代上述依据。两者不一致时，先判断是未实现、旧资料过时，还是确有歧义。

不接管需求讨论，不收集整段聊天，不要求另填需求表。原始指令足够明确即可开工。

## 职责

主执行 Agent（Root）是当前接收用户要求并负责整项交付的 Agent，通常也是启动 Orbit 的会话。这个名称不要求项目预先配置角色；若没有必要分工，它也直接承担实现。Orbit 程序是观察和控制工具，不是另一位 Root。

- **Root**：对照原始指令维护整体交付；按完整用户行为分工，能直接完成时不机械拆开；普通工程选择自主处理；落实纠正并核查下一实际动作；收尾对照预估解释偏差。预估不是硬门。
- **执行者**：完成所分配行为；先查现有能力；控制改动范围；验证直接相关行为；报告实际产物、结果和具体阻断。
- **独立检查者**：只读。对照原始指令、指定资料、用户明确修改和实际产物；同时找漏做、做错和做多；判断当前投入是否仍推进需求。不改需求，不把工程偏好升级成阻断。
- **按需裁定者**：只处理真实争议。看双方依据和当前事实，在原目标与授权内给出可执行结论。不投票，不要求双方同意，不增加验收。同一问题须有新证据或相关变化才重开。

已确认的产品决定写入权威出处。普通工程选择由执行者或 Root 作出，不升格。

## 何时停下

必须处理：

- 真实影响执行的目标歧义或授权缺口 → 交用户。
- 真实争议 → 按需裁定；只阻止争议部分完成，不默认停掉无关执行。
- 根因需要本仓库给不了的信息 → 交用户。
- 已裁定的纠正多次未落实 → 停止受影响工作、保留上下文，向用户报告。不自动替换 Root。

不是边界：

- 多个可行实现；由执行者或 Root 选择。
- 缺少固定结果表或内部记录字段。
- 超出预估；用户另行指定的硬上限仍有效。
- 同类失败到固定次数。问题仍是当前交付所必须且有新事实时，在原授权内调整；否则先诊断。仅为更漂亮或无真实风险的覆盖 → 停止该支线。
- 测试数量或行数。
- 发布、删除用户数据或改生产状态，若已在当前授权内 → 不重复确认。尚未授权才交用户。

## 交接

| 类型 | 交什么 |
| --- | --- |
| 目标／授权缺口 | 缺什么、为何影响执行 |
| 真实争议 | 争议点、双方依据与当前事实、一个可执行结论候选 |
| 缺陷 | 位置 + 具体可核实证据 + 影响。静态缺陷不要求先跑复现。缺可核实证据则是意见 |
| 范围外 | 问题、影响、建议。本任务不改 |

## 清理

删测试、删代码或精简说明时核：把义务改成许可、把设想说成已落地、删掉真事实、丢出处、删掉修复承诺却不修缺口。既有有效验证和仍有效的人工前置直接复用。区分模拟结果与真实路径。只清理本任务归属明确且不再需要的资源。
