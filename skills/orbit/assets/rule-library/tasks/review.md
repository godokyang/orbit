# 评审

**所有权边界**：本文只拥有独立检查里「原始指令是否被满足，以及有没有做错／漏做／做多」的判定。实现规则正文归本次检查对象适用的规则。停下、裁定与交接见 `rules/escalation-payload.md`。

本文是判断依据，不是可以机械勾选的清单。复核只报告不修改。不要为了凑缺陷数量制造改动。只读固定产物，不改执行工作区。

## 判据

过两轴，两轴都要出结论：

- 标准轴：对照当前适用规则、用户原始执行指令及其指定依据、用户明确修改。删掉这条改动，哪一条有效要求会失败？指不出 → 不是未满足指令。
- 规格轴：原始指令要求的每一项，判「做到 / 部分 / 没做 / 做多了」。做多了同样要报。

同时判断：当前投入是否仍在推进需求。测试或优化持续增加却没有推进需求 → 报告应停止的支线。

不要问「测试是不是绿了」。那个问法对「字面完成但用户目标没变」给反答案。要问「原始指令现在是否成立」。

## 反问法警告

不要用「测试通过了吗」当完成判据。它对「只证明旧行为未破坏」给反答案。要问「用户要的行为现在是否成立」。不要把工程偏好或多个可行实现升级成阻断。

## 反发明边界

缺陷只记录已经观察到的问题：位置 + 具体可核实证据 + 影响。静态缺陷（错误代码、缺失文件、过时陈述）不要求先跑复现。缺可核实证据则是意见。判不了写「未记录」，不要虚构触发条件或后果。

## 反向约束

| 看起来像该报 | 为什么放行 |
| --- | --- |
| 零阻断，且检查面清楚 | 没发现阻塞问题是有效评审 |
| 低置信风格偏好 | 不够成阻断；降为意见 |
| 绿守卫已经查过的链接 / 格式 | 不复述自动检查 |
| 适用规则里的实现禁令 | 由该规则拥有，本文不复写 |
| 本次未承诺的恢复／发布／异常矩阵未全覆盖 | 按本任务行为与真实风险选验证层 |

## 降级路径

- 答不出位置或可核实证据 → 降为意见，或先补证据，不写阻断。
- 原始指令已满足、新风险是否阻断要看授权或产品歧义 → 按需裁定；只阻止争议部分完成。
- 风格或范围外问题 → 范围外说明，本检查不改实现。
- 复核时只看原问题、直接影响和新增变化；已有有效结论复用。

## 规则内优先级

一份带一个已证实阻断项的短评审，好过一串鸡毛蒜皮。先判原始目标，再看本任务承诺的行为与真实风险。不要因「最终检查」重开全审。

## 升格条件

只有当检查与执行对同一最终产物仍有真实争议，或新风险是否阻断会改变目标／授权时，才算边界。检查者改验收、用「测试过了」代替原始指令，不是边界。

## 检查顺序

1. 原始指令：每一项做到、部分、没做、做多了。
2. 本任务承诺的行为与真实风险，而不是默认的中断／恢复／发布矩阵。
3. 当前投入是否仍推进需求。
4. 证据是否支撑结论；库测试不证明真实命令或用户路径。
5. 未覆盖风险是否可接受，且仅限本任务相关风险。

字面完成但目标没达成、低价值搬移冒充重构、把必须项静默缩小，给阻断。从用户输入构造 shell / path，或改认证却验证不清，阻断该部分完成。发布或删除用户数据若已在当前授权内，不重复确认；未授权才交用户。

代码侧完整性审计通过，不等于真实用户路径通过；真实路径通过，也不能掩盖旧路径仍能写权威结果。缺任一项就补证据、降级，或写入剩余风险。误报可由有依据的独立裁定推翻。
