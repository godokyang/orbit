# 测试取舍

**所有权边界**：本文只拥有「这条验证该不该写成永久测试」。根因与回归守卫的作者义务归 `targeted-fix`。停下、清理与交接见 [共用职责](../shared/escalation-payload.md)。

本文是判断依据，不是可以机械勾选的清单。复核只报告不修改。不要为了凑覆盖率制造测试。

## 判据

先把被测事实分成稳定程序规则 / 动态或时效数据 / 本任务一次性复现，再问：

- 换一轮数据，这条断言还成立吗？不成立 → 不要写成永久测试。
- 删掉这条测试，发现真实问题的能力会下降吗？不会 → 不写。
- 它测的是可观察行为，还是构造函数赋值、mock wiring、实现细节？后者 → 不写。
- 污染过生产代码、改过输入、覆盖过失败 run 的结果，还能不能当作通过依据？不能。
- 新加测试失败本身不证明它是交付阻断。先核查这条测试是否必要；既有必过检查不能随意绕过。

测试数量和行数是工程建议，不是硬门。独立检查结合需求和真实影响判断是否过度测试；用户明确设定的资源上限仍须遵守，不把测试规模冒充供应商用量。

## 反问法警告

不要问「覆盖率够高吗 / 再加几条是不是更安全」。它对「一次性验收扩成永久测试」给反答案。要问「删掉它谁会坏，换一轮数据还成立吗」。

## 反向约束

| 看起来像该加测试 | 为什么放行 |
| --- | --- |
| 发布审计或本轮截图 / URL 复验 | 那是一次性验收证据，不是永久测试 |
| 框架、标准库、SDK 已保证的行为 | 无业务价值 |
| 只服务测试的代码结构 | 测试不能驱动业务偏离 |

## 降级路径

- 只能验证当前具体词 / 具体样例 → 标明缺口，写明缺同形态输入，不升格。
- 缺真实用户路径 → 记剩余风险，不宣称路径通过。
- 同一证据又像稳定规则又像数据快照 → 按稳定行为写永久测试，按当前数据留一次性证据。

## 规则内优先级

先覆盖本轮改动路径、失败模式和用户路径。需求与测试冲突时，完成需求主线；测试不能阻塞核心功能。发现测试或优化持续增加却没有推进需求时，停止该支线。

## 升格条件

只有当测试取舍会改变目标、验收或权限，或绕过既有必过检查需要授权时，才算边界。把一次性 URL 写成永久测试、为凑数量加低价值用例，不是边界。

## 污染与真实路径

禁止为制造测试通过而改变业务规则、覆盖失败记录、手工补系统应生成的产物，或改输入后仍声称原测试通过。按原始要求修复生产代码并重新验证属于正常修复。用户可见完成状态与产物／状态文件矛盾时不能过。只跑编译或 mock happy path，不能证明真实路径。

测 parser / resolver / 状态机 / artifact writer 时，要证明同形态输入也不会进入正式事实源；只过当前报错样例不够。
